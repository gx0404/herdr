Herdr 是鼠标原生的。你可以点击窗格、标签页、工作区和智能体,拖动分割边框,使用右键菜单,一个按键绑定都不用学。键盘操作是可选的一层,不是必需项。 浮层里的滚轮只滚动视口，不改动键盘选中；窗格、侧栏与浮层的滚轮步进统一取 `ui.mouse_scroll_lines`（默认 3 行）。

分块到达时，bracketed 文本粘贴仍会作为一次粘贴处理，因此 Unicode 文本和结束粘贴标记不会被当作普通按键。完整 bracketed 粘贴超过 1 MiB 时会显示通知并拒绝，但连接仍可继续使用；其它超限输入会被视为协议错误，并可能关闭客户端。

在已识别的 Codex 窗格中，无修饰键的左键拖动使用 Herdr 冻结文本选区；启用 `ui.copy_on_select` 时松开即复制。单击仍交给 Codex；全程按住 Alt 可把完整鼠标手势交给 Codex。这需要连接的服务端支持文本快照。在同一窗格右键选择 **复制** 即可复制已完成的选区，自动复制后也可再次使用。自动复制会恢复实时输出，只临时保留选中文本供菜单使用；新输入、新选择、滚动、切换窗格、调整大小或重连会清除这份文本。没有当前选区或临时保留文本时，菜单中的 **复制** 置灰，不会向应用发送中断按键。若该窗格启用了右键透传，请改用选区复制快捷键。

再次点击当前工作区会立即把键盘焦点交回其终端；布局调整模式仍保留面板焦点。

使用上一个、下一个或按编号聚焦智能体的快捷键时，统一会话树会展开折叠的祖先，只滚动到足以露出目标的位置。目标已可见时保持当前滚动位置，单机也一样；折叠图标栏揭示目标所属工作区，不使用独立智能体列表。

## 发送给窗格应用的按键

Herdr 使用 libghostty 按窗格应用当前的键盘模式编码按键，包括 Kitty 键盘协议和 `modifyOtherKeys` level 2。外层终端仍须报告可区分的按键；Herdr 无法恢复从未收到的修饰键信息。没有启用增强键盘协议时，原生 Windows 窗格仍保留 ConPTY 输入记录回退路径；参见 [Windows 支持](/zh-cn/docs/windows-beta/#键盘和鼠标)。

未启用这两种协议的普通 shell 中，`ctrl+shift` 加 ASCII 字母发送与 `ctrl` 加该字母相同的 C0 控制字符，而不是 CSI-u。带修饰键的 Enter 仍按 Enter 处理；传统的 `ctrl+i` / `ctrl+m` / `ctrl+[` 组合则分别保留 Tab、Enter 和 Escape 行为。未被 Herdr 快捷键处理的 Super/Command 组合不会作为裸字母转发，也不会强行转换成 CSI-u。窗格应用启用增强模式后，编码遵循它协商的模式；`modifyOtherKeys` level 1 按未协商处理。

## 前缀键是什么

终端复用器位于终端和其中运行的程序之间。这些程序已经占用了大多数按键组合: `ctrl+c` 中断,`ctrl+r` 搜索历史,编辑器几乎占用了剩下的一切。如果 Herdr 直接抢占常用按键,就会破坏其中运行的程序。

前缀键解决了这个问题。按下前缀键 (默认 `ctrl+b`),下一次按键会发给 Herdr 而不是终端。`prefix+c` 的意思是: 按下 `ctrl+b`,松开,再按 `c`。只保留一个键,而不是几十个。

随时按 `prefix+?` 可以查看所有生效的绑定。在快捷键帮助中按 `/` 即可筛选操作和快捷键；使用 Backspace 编辑筛选内容，或按 `ctrl+u` 清除。前缀模式等待下一个按键期间，会弹出 which-key 面板列出可用的后续绑定（可用 `ui.which_key = false` 关闭）。按 `prefix+Space`、点侧边栏底部的「菜单」，或在停靠布局启用时点标题栏的「≡ herdr」，都会打开主菜单（停靠布局的侧边栏不再有第二个入口）；标题栏的 `⋯` 打开一个更小的布局菜单，只有「监控」「调整布局」「锁定布局」「复位布局」。主菜单在所点的入口下方展开，下方放不下且上方空间更大时改为向上展开；点击打开时不预选任何条目，按方向键后才出现选中行（按 `prefix+Space` 打开时从第一项开始）：每个分类是一个子菜单，条目右侧显示当前生效的快捷键，「锁定布局」、机器的启用项这类开关用勾选标记表示状态，暂时不可用的条目照常列出但置灰，当前布局里根本不存在的动作（例如经典布局下的「锁定布局」）则不列出。方向键会跳过置灰条目与分隔线，`→` 进入分类、`←` 回到分类列表，`Home` / `End` 跳到首尾条目；分类条目较多时可以滚动，还有条目被隐藏时边框上显示 `▲` / `▼`。直接输入文字、按 `/` 或 `prefix+/` 会切换到覆盖所有动作的模糊命令搜索（包括机器连接、编辑与从 SSH 配置导入，命令片段的管理与运行，场景快照，以及输入广播管理）。搜索按词匹配，而不是零散的字母：查询的每一段都要落在词首，或紧接上一个命中，所以 `mon` 能找到「监控」（英文标题 Monitor），`mtl` 能找到「左移标签页」（move tab left），空格表示另起一词（`mon sys`）。中文标题逐字匹配；内置动作在任一界面语言下都能按英文或中文标题搜到，条目的快捷键与所属分类名也参与匹配。主菜单与空搜索框都会优先显示最近使用的命令。

各弹层页面有自己的局部按键，显示在页面底栏：机器页面（`prefix+m`）上按 `b` 打开广播目标集合；机器动作键 —— `e` 编辑、`R` 重命名、`r` 重连、`f` 端口转发、`o` 远程文件浏览器、`d` 启用/禁用、`x` 移除、`v` 处理失败、`c` 复制修复命令 —— 在列表和机器详情卡上行为一致。「已复制修复命令」这类一次性反馈会显示在机器列表与机器详情卡底部，几秒后自动消失。输入广播开启期间，状态栏（经典布局下是 mode bar）常驻 `⇄ 广播 ×N` 徽标，让你绝不会忽视输入正在扇出到其他机器。

## 先学这五个

| 动作 | 按键 |
| --- | --- |
| 新建标签页 | `prefix+c` |
| 向右 / 向下分割 | `prefix+v` / `prefix+minus` |
| 在窗格间移动 | `prefix+h/j/k/l` |
| 工作区导航 | `prefix+w` |
| 分离并让一切继续运行 | `prefix+q` |

这些覆盖了日常的大部分移动操作。其余的都可以继续用鼠标。

## 其余的,按任务分

窗格:

| 动作 | 按键 |
| --- | --- |
| 缩放聚焦的窗格 | `prefix+z` |
| 关闭窗格 | `prefix+x` |
| 交换窗格 | `prefix+shift+h/j/k/l` |
| 调整大小模式 | `prefix+r` |
| 复制模式 | `prefix+[` |
| 链接提示（可见 URL 上的两字母标记） | `prefix+u` |

标签页:

| 动作 | 按键 |
| --- | --- |
| 下一个 / 上一个标签页 | `prefix+n` / `prefix+p` |
| 跳转到标签页 1–9 | `prefix+1..9` |
| 重命名标签页 | `prefix+shift+t` |
| 关闭标签页 | `prefix+shift+x` |

工作区与会话:

| 动作 | 按键 |
| --- | --- |
| 新建工作区 | `prefix+shift+n` |
| 重命名工作区 | `prefix+shift+w` |
| 关闭工作区 | `prefix+shift+d` |
| 智能体总览 / 会话导航 | `prefix+g` |
| 下一个需要处理的会话 | `prefix+a` |
| 切换侧边栏 | `prefix+b` |
| 切换 Inspector | `prefix+i` |

智能体总览（`prefix+g`）：`g` 切换状态/位置分组，Space 预览，Enter 跳转（或展开状态组），`r/u/R` 在本地标为已读/未读/全部已读。`e` 仅为端点明确宣告 `agent.prompt` 的空闲/待查看会话打开回复。编辑器内 Enter 换行，Ctrl+Enter 或「发送」使用 `wait = None` 提交。PageUp/PageDown 滚动预览文本，上下键仍选择目标。工作中、失败及受阻会话只能跳转。提交超时时，重试前先检查终端：提示可能已被提交。

Inspector 仅在停靠布局中提供。点击正文即可交给它键盘焦点：上下方向键或 `j/k` 选择行，Enter 激活，PageUp/PageDown 与 Home/End 滚动，`d` 打开详细活动，`r` 刷新活动，Esc 返回终端。滚轮与滚动条轨道只滚动，不会回答问题。「跳转并回答」只聚焦真实智能体窗格；权限必须在那里回答。

位置模式（在总览中按 `g`）保留 Goto 选择器的机器、工作区和普通终端导航。每个智能体或终端各占一行，包括分割标签页中的每个窗格。搜索框按空白拆词，只保留每个词都出现在行内的结果，所以 `server web` 也能找到 `web server`，词序不影响命中。搜索或状态筛选从第一个自身命中的目标开始，而不是容纳它的工作区行。未编辑搜索框时，Home 回到首行，End 或 `Shift+G` 跳到末行。SSH 导入的发现和选择列表也支持 `Shift+G` 跳到末尾，包括使用 kitty 键盘协议的终端。（`prefix+w` 则进入侧栏工作区导航，没有搜索框。）

按 `/` 搜索名称、智能体类型、标签页、工作区、分支或路径；未输入搜索时，用上下方向键或 `j/k` 移动。位置模式未打开预览时，左右方向键跳到上一个或下一个工作区中的第一个智能体或终端，到两端后不会循环；打开预览时左右键滚动预览，编辑搜索时则移动文本光标。搜索外用 `b/w/i/d` 筛选 blocked、working、idle 或 done 智能体，`a` 清除筛选。目标的位置和路径显示在列表下方。滚轮、滚动条轨道和滑块只滚动，不打开目标。

完整键位和绑定语法见[按键绑定参考](/zh-cn/docs/configuration/#按键绑定)。

按 Esc 或 Ctrl+[ 退出工作区导航。在 Go To 中,即使布局需要 Shift 才能输入 `/`,也可以用它打开搜索。

窗格输入遵循应用请求的键盘模式。普通 shell 将 Ctrl+Shift+字母作为控制字节接收;窗格无法表示的 Super、Hyper 和 Meta 组合键会被丢弃。使用 Kitty 键盘输入的应用会收到其请求的修饰键和按键事件。非 report-all 模式下,带修饰键的 Enter、Tab 和 Backspace 不接收释放报告。数字小键盘键和单独的修饰键按下也不会转发。

非拉丁布局中,Ctrl+W 等仅带 Ctrl 的快捷键可以使用支持 Kitty 的主终端报告的物理基础键。拉丁布局字符、Ctrl+Shift 和 AltGr 保留布局含义。不报告物理键的终端无法提供相同的跨布局快捷键。

## 编辑文本输入框

Herdr 的命名对话框、worktree 分支名、筛选框和复制模式搜索框支持在光标处编辑。以下快捷键适用于 Herdr 自己的输入框，不改变窗格内 shell 或智能体的按键行为。

| 操作 | 按键 |
| --- | --- |
| 移动一个字符 | Left / Right、Ctrl+B / Ctrl+F |
| 移到开头 / 末尾 | Home / End、Ctrl+A / Ctrl+E |
| 移动一个词 | Alt+B / Alt+F |
| 删除前一个字符 | Backspace、Ctrl+H |
| 删除后一个字符 | Delete、Ctrl+D |
| 剪切到开头 / 末尾 | Ctrl+U / Ctrl+K |
| 剪切前一个词 | Ctrl+W、Alt+Backspace、Ctrl+Backspace |
| 剪切后一个词 | Alt+D |
| 插入上次剪切的文本 | Ctrl+Y |

输入和粘贴会插入光标所在位置。移动和删除遵循 Unicode 字素边界，长内容会水平滚动。剪切的文本只保留在当前输入框中，不使用系统剪贴板。Alt 快捷键需要终端报告 Alt/Meta。Enter 和 Esc 仍用于对话框的确认和取消。

## 复制模式

按 `prefix+[` 让聚焦的窗格进入复制模式。用 `h/j/k/l`、tmux 风格的 `w/b/e` 和 `{`/`}` 移动。按 `/` 或 `?` 向前或向后进行文本搜索,再用 `n` 或 `N` 按相同或相反方向重复搜索。查询包含大写字母时区分大小写,否则不区分。用 `v` 或空格开始选择,用 `y` 或回车复制,用 `q` 或 Esc 不复制直接退出。Esc 会先清除当前选择或搜索,然后才退出。复制模式不会暂停窗格进程:停留在底部时继续跟随输出,进入历史记录后保持当前位置。鼠标拖选可以直接复制,完全不用进入复制模式。

鼠标拖选以及通过 `v`、空格或 `V` 开始的选择会在输出和重绘期间保持有效，即使部分选中范围位于可视区域之外。复制读取的是该范围内当前的文本，而不是冻结的快照。调整窗格大小或在普通屏幕与备用屏幕之间切换仍会清除选择。搜索结果和双击单词选择仍保留内容变化检查。

## 一切都可以改

每个绑定都可以配置,包括前缀键本身:

```toml
[keys]
prefix = "ctrl+a"
```

## 不用前缀键

你可以把 Herdr 动作绑定到完全不需要前缀的直接组合键。难点在于知道哪些组合键是安全的,因为终端、shell 和桌面环境已经占用了键盘的大部分。

任何组合键都可以做绑定: `ctrl+j`、`alt+k`,顺手就行。但一个组合键要经过三层才能到达 Herdr: 操作系统、外层终端 (Ghostty、iTerm2 等都带有自己的默认键位),以及窗格内运行的程序。`ctrl+j` 能顺利到达 Herdr,但 shell 和编辑器把它当作回车。`alt+k` 在 Linux 上是空闲的,但在 macOS 的大多数终端里会被组合成特殊字符。如果你从这些键系里选组合键,请对照自己的终端和系统快捷键再确认一遍。

我们梳理了 Ghostty、iTerm2、Terminal.app、kitty、WezTerm、Alacritty、Warp、Windows Terminal、GNOME Terminal 和 Konsole 的默认按键绑定,以及 GNOME 和 KDE 的全局快捷键。有一个修饰键系几乎在所有地方都没被占用: `ctrl+alt`。终端把它留空,它不受 macOS option 键组合行为 (会挡掉纯 `alt` 组合键) 的影响,而且即使在没有现代键盘协议的终端里也能正常传输。它是安全的默认推荐;选择权在你。

下面的配置保留前缀绑定,并在其上叠加直接组合键:

```toml
[keys]
focus_pane_left = ["prefix+h", "ctrl+alt+h"]
focus_pane_down = ["prefix+j", "ctrl+alt+j"]
focus_pane_up = ["prefix+k", "ctrl+alt+k"]
focus_pane_right = ["prefix+l", "ctrl+alt+l"]
previous_tab = ["prefix+p", "ctrl+alt+["]
next_tab = ["prefix+n", "ctrl+alt+]"]
new_tab = ["prefix+c", "ctrl+alt+c"]
split_vertical = ["prefix+v", "ctrl+alt+d"]
split_horizontal = ["prefix+minus", "ctrl+alt+shift+d"]
zoom = ["prefix+z", "ctrl+alt+z"]
```

少数 `ctrl+alt` 组合键已被其他地方占用。请避开这些:

| 组合键 | 占用者 |
| --- | --- |
| `ctrl+alt+arrows` | GNOME 工作区切换,Ghostty 和 Konsole 默认键位 |
| `ctrl+alt+t` | Ubuntu 和 Fedora 的“启动终端” |
| `ctrl+alt+l` / `ctrl+alt+a` | KDE 锁屏 / 注意力窗口 |
| `ctrl+alt+s` / `ctrl+alt+u` | Konsole |
| `ctrl+alt+f1..f12` | Linux 虚拟控制台切换 |

如果某个直接组合键没有任何反应,说明终端或桌面环境在 Herdr 看到它之前就把它消费掉了。两边任选其一重新配置: 在终端设置里释放这个组合键,或者在 Herdr 里换一个。
