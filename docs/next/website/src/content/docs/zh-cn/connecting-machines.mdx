---
title: 连接机器
description: 在一个 Herdr 窗口中使用 Local 和已保存的 SSH 机器，集中查看智能体，各连接独立重连。
---

将本地工作和远程智能体放在同一个 Herdr 窗口中。SSH 机器只需保存一次，就能在它的工作区与 Local 之间切换，无需再开一个客户端。智能体列表汇总已连接的机器，让你看到工作在哪里运行，以及谁在等待回答。

每台机器保留自己的 Herdr 服务器、会话和进程。一台机器断线不会影响其他连接。

## 连接前的准备

你需要能够通过普通 SSH 访问远程机器。先验证：

```bash
ssh workbox
```

`workbox` 可以是 SSH 配置中的主机名，也可以使用 `ssh://you@server:2222` 这样的目标。

多机器连接支持 Linux 和 macOS 客户端，连接目标为 x86_64 或 aarch64 的 Linux 和 macOS 服务器。Windows 上的多机器连接尚未验证，也暂不受支持；独立连接命令 `herdr --remote` 仍支持 Windows。原生 Windows 服务器不能作为 SSH 目标。有关 SSH 配置、认证和自定义二进制文件，请参阅[通过 SSH 远程连接](/zh-cn/docs/persistence-remote/)。

## 添加机器

请在交互式终端中运行，以便 Herdr 在安装或替换内容之前询问：

```bash
herdr machine add workbox --label "Build machine"
```

这会使用远程默认会话。一个机器配置只对应一个远程会话，不会汇总该主机的所有会话。

如需命名会话，再添加可选的 `--remote-session`：

```bash
herdr machine add workbox --label "Build machine" --remote-session agents
```

Herdr 分别检查已安装的二进制文件和运行中的服务器，并在保存配置之前启动目标后台服务器。客户端和服务器版本只要兼容，就不必一致。未安装或不兼容时会进入需要批准的设置流程。如果必须替换运行中的服务器，会先询问是否停止它及其窗格进程，再启动兼容的服务器。默认回答为 No；同时需要安装和替换时，一次确认涵盖两项操作。`machine add` 不使用实验性的实时交接。取消或设置失败时，不会保存配置。

运行 `herdr` 打开 UI。如果本地客户端已经打开，新增或启用的机器通常会在一秒内出现并在后台连接，不改变当前选择。切换机器期间的配置变化会在切换完成后应用。设置结束后，远程服务器仍会运行。

也可以不离开界面添加机器：从主菜单或用 `prefix+m` 打开机器页面，按 `a`（或点页脚的**添加**；还没有保存任何机器时，空页面上也有**添加**按钮）。添加表单是单页的。顶部的**快速添加**框接受 `user@host:port`、`ssh://` 地址或整条 `ssh` 命令：粘贴后立即解析（续行符会被合并），手动输入则在按 Enter 或离开该框时解析。解析会一并填入目标、用户和端口，以及其中出现的身份文件、跳板机和受支持的 `-o` 选项；`user:password@host` 会被拒绝。

快速添加框下方的字段分为连接、认证、会话和高级（保活、控制连接保持、远程命令、会话日志）四组。Tab / Shift+Tab 或方向键在字段间移动，左右键或空格切换选项，鼠标点击字段即聚焦并把光标放到点击处。每个字段在你改动或离开后单独校验——目标必填且不能以 `-` 开头、端口须为 1–65535、名称不能与其他机器重复等；保存或测试时会显示所有剩余错误，并把焦点移到第一个错处。宽屏时字段旁的实时预览显示等价的 `ssh` 命令和将要保存的全部值；未通过校验的值在值清单里标红并注明「（无效）」，该值出现在命令里时命令中也同样标出。

Enter 保存机器，保存后它会像导入的机器一样在后台连接；仍需设置的机器会显示 Attention 并给出独立设置命令。**测试连接**（`Ctrl+T` 或页脚对应项）是单独的动作，不保存任何内容。它会预先授权 `machine add` 在终端里会询问的安装、更新或必要的服务器重启，所以第一次按下只在页脚上方显示确认说明（窄屏同样显示）：必要时会在远端安装或更新 herdr，更新需要时会停止远端正在运行的服务器及其全部窗格进程。再按一次 `Ctrl+T` 或 Enter（或点**开始测试**）才开始测试，`Esc` 收起确认。测试依次执行平台检测、安装或更新、启动服务器和验证端点，并逐步显示结果。`Esc` 取消正在运行的测试；测试结束后，第一次按 `Esc` 只清掉结果。表单有未保存的改动时，`Esc`（或页脚的返回）会先询问是否放弃：Enter 或**放弃更改**离开表单，`Esc` 继续编辑。改动连接相关字段会作废上一次的测试结果。界面内的 SSH 仍以非交互方式运行，因此测试因主机密钥或认证失败时，`Ctrl+R`（或页脚对应项）会打开对应的恢复对话框：主机密钥未知打开主机密钥核对，主机密钥已变更打开强阻断的移除对话框，认证失败打开交互认证引导。信任密钥后关闭对话框再测试一次；交互认证成功会保存该机器并接管连接。界面内无法恢复的失败（DNS、超时、远程安装、协议）会指出失败的步骤，并给出可在交互式终端完成设置的独立命令（例如 `herdr --remote workbox --session default`）。编辑机器（`e`）打开同一张表单，没有快速添加和测试连接，目标只读展示；Enter 保存后回到详情卡。

## 从 SSH 配置导入机器

如果 `~/.ssh/config` 已经描述了你的主机，可以直接导入，不必重新输入每项设置：

```bash
herdr machine import                     # 查看检测到的主机并勾选要导入的项
herdr machine import --yes               # 全部导入（stdin 不是终端时必需）
herdr machine import --host 'db-*' --group prod
herdr machine import --file ~/work/ssh_config
```

导入按 OpenSSH 语义读取你的 SSH 配置（包括 `Include` 引入的文件）：每个指令取第一个值生效，`Host *` 提供兜底，主机匹配不区分大小写，支持 `*`/`?` 通配与 `!` 取反。`Match` 块无法静态求值，会被跳过。SSH 配置只读，绝不修改。

每个 `Host` 成为一个机器配置：别名作为标签，解析出的 `HostName` 作为目标，`User`、`Port`、`IdentityFile`、`IdentitiesOnly`、`IdentityAgent`、`ProxyJump`、`ForwardAgent`、`ServerAliveInterval`、`ServerAliveCountMax`、`ControlPersist`、`RemoteCommand` 和 `StrictHostKeyChecking` 成为配置字段——与 `machine add` 接受的命令行标志一一对应。`ProxyJump` 中引用同批导入主机的跳点会成为指向它的 `profile:<id>` 引用，其余跳点保持字面值目标。`*.internal` 这类通配模式默认跳过，除非传 `--include-wildcards`；导入的通配配置是使用前需要编辑的模板。与已保存机器（或彼此）标签或目标重复的主机会被跳过并逐台报告，因此重复执行导入是安全的。

同样的导入也可以在界面中完成：在机器页面按 `i`（或点页脚的**导入**，或用命令面板的「从 SSH 配置导入机器」）打开三步导入。第一步列出检测到的主机以及将被跳过的主机与原因，一屏放不下时可以滚动（方向键、`PageUp`/`PageDown`、`Home`/`End` 或鼠标滚轮）；找不到主机时会说明这一点并显示配置路径。第二步是待导入主机的勾选清单（空格切换、`a` 全选/全不选、分组输入框为整批指定分组）；宽屏时旁边的预览显示当前聚焦主机将要保存的字段和会被丢弃的设置，有设置被丢弃的主机在行尾带 `!` 标记。最后一步逐台列出每台主机的结果：已导入、失败（附原因）或已跳过——取消勾选的主机注明「未勾选」，发现阶段就跳过的主机附上第一步显示的原因。导入的机器与 CLI 路径一样在后台连接；远程 server 的安装仍是单独的显式步骤。主机多于一屏时，选择步骤会滚动，通配符开关、分组输入框与计数行固定在底部；完成步骤也可以用方向键滚动，最后一台主机总能滚到。

导入只登记配置，绝不安装、更新或重启远程服务器。导入后机器在后台连接；需要设置的机器会显示 Attention 并给出独立设置命令。若要登记单台主机并执行与 `machine add` 相同的准备流程，请使用：

```bash
herdr machine add --from-config web
```

它在你的 SSH 配置中解析 `web`，按找到的完整指令登记，并在保存前执行常规的远程设置。连接选项标志不能与 `--from-config` 组合；`--label`、`--remote-session`、`--group`、`--tag` 和 `--color` 仍然可用。

## 切换机器

在侧边栏选择机器或其工作区。只有选中的机器接收窗格输入和终端尺寸，并提供可见的终端内容和图形。其他已连接机器仍会更新工作区信息、智能体状态和通知，但不传输窗格画面。

键盘导航：按 `prefix+w`，再用工作区导航键（默认上 / 下）按侧边栏顺序在各台已连接机器的工作区之间移动高亮。Enter 激活高亮的工作区；Esc 或前缀键取消且不切换。紧凑与展开的侧边栏都会让高亮行保持可见，折叠的机器下也一样。在侧边栏里导航到两端会回绕；移动端切换器（只存在于连接旧版服务器时的经典布局）则停在第一个或最后一个工作区。未连接的机器会被跳过。

启动时会立即打开 Local，不等待 SSH 连接。一台机器无响应不会阻塞其他机器的输入。多个 Herdr 客户端也可以独立查看同一服务器上的不同标签页；共享标签页的尺寸规则见[客户端与服务器](/zh-cn/docs/concepts/)。

断线后，最后的工作区和智能体状态仍然可见，但会变暗。这是缓存，不是实时状态。在新连接和对应画面到达前，不能输入或导航到这些缓存窗格。重连不会从正在使用的机器抢走选择。

输入禁用是刻意设计：断线期间客户端无法确认会话的真实状态，继续输入可能把按键送进错误的上下文——已经走远的 shell、另一个提示符、正在执行任务的智能体。禁用窗格输入并把缓存画面调暗，是在界面上明确这条边界，而不是让按键漂进状态不确定的会话。远端不会有任何损失：链路中断期间，远端 Herdr server 完好保留会话、智能体和窗格进程，新连接建立后工作区原样恢复。如果不想等自动退避，受影响机器上的重连横幅提供两个入口：**立即重连**马上发起一次尝试，**放弃**禁用该机器（可在 machines 页面重新启用）。

## 重命名、禁用或移除

从列表读取配置 ID，不要根据标签或主机名推测：

```bash
herdr machine list
herdr machine rename <profile-id> --label "New name"
herdr machine disable <profile-id>
herdr machine enable <profile-id>
herdr machine remove <profile-id>
```

用于脚本时，可给 `machine list` 添加 `--json`。

重命名只修改显示标签，不会重连。禁用会保留配置供以后使用，移除则会忘记该配置。两者都只从客户端断开该机器，即使主机无法访问也可以操作；远程会话和智能体仍会运行。

同样的操作也可以在界面里完成。从主菜单或用 `prefix+m` 打开机器页面，可以看到每台已保存机器的实时状态、目标、分组和服务器版本。按 Enter 打开详情卡：列出完整配置（含全部连接字段）和该机器的端口转发规则及其实时状态；连接失败后还会列出结构化的失败原因与建议的下一步，失败有界面内恢复路径时另有**处理失败**入口（见[连接问题](#连接问题)）。在列表或详情卡上都可以重命名（`R`）、编辑配置（`e`：分组、标签、颜色、会话及连接字段）、启用或禁用（`d`）、确认后移除（`x`）、立即重连（`r`）、打开端口转发规则（`f`）或远程文件浏览器（`o`）、处理失败（`v`）以及复制修复命令（`c`）——两处按键相同，始终作用于键盘选中的那台机器。页脚列出这些按键，同时就是按钮栏：点击动作项即可执行（导航键与 `R` 只作提示），当前不适用的项会置灰（例如已禁用机器的重连），`v` 只在失败有界面内恢复路径时出现。没有任何已保存机器时，列表改为显示**添加**按钮；过滤没有匹配时会照实说明。「已复制修复命令」这类一次性反馈显示在机器列表和详情卡底部，几秒后自动消失；显示期间被它盖住的页脚项不能点击。在侧边栏右键一台机器，可选 **管理机器...**、**立即重连**、**切换到此机器**、**重命名**、**编辑机器...**、**启用**（启用时带勾选）、**复制修复命令** 和 **移除机器...**；**复制修复命令** 把该机器的独立设置命令放进剪贴板，机器页面未打开、或没有显示列表或详情卡时用通知确认。编辑机器的会话或连接字段只会重连该机器。列表还提供**导入**（`i`、页脚对应项，或命令面板的「从 SSH 配置导入机器」），分三步打开与 `machine import` 相同的 SSH 配置导入；详情卡的**端口转发**项（`f`）管理端口转发规则并显示其实时状态。

移除或禁用正在查看的机器会返回 Local。如果 Local 不可用，Herdr 会显示该状态并重试连接，而不是选择其他远程机器。有已启用的保存机器时，即使 Local 失败或重启，客户端仍可继续使用。

## 场景快照

场景快照把当前工作现场保存下来，之后可以一键恢复：启用的机器集合、活动机器及其工作区与标签页（客户端有缓存视图的每台机器都会记录），以及侧栏状态（宽度、折叠、分组折叠）。从命令面板打开快照页（「保存现场…」/「恢复现场」），按 `s` 把当前现场保存为带名称与可选备注的快照。最多保留 32 个现场，存储在 endpoint catalog 旁的版本化 `scene-snapshots.json` 中。

恢复现场会启用快照记录的机器。「恢复时停用现场之外的机器」开关（`x`）**默认关闭**：普通恢复不会停用快照之外的任何机器。打开它后，恢复会先弹出确认页，列出将被停用并断开的每一台机器——确认键是 `y`（或 `ctrl+↵`）而不是 `↵`，长按或连点回车都走不完这一步，并且只有确认页列出过的机器会被停用。确认之前不会写入端点目录；如果现场已经覆盖全部已启用的机器，没有任何机器需要停用，恢复会直接执行。记录的活动机器及其工作区在线时会成为当前选择，在线的后台机器也会恢复其记录的工作区焦点。快照中已不存在的机器不会导致恢复失败，而是被跳过并在结果提示中列出。

在现场列表里单击只选中一行——恢复要走「恢复」按钮、`Enter`，或对同一行的二次点击。现场可以在同一页面重命名与删除。现场名唯一：保存和改名撞到已存在的名字都会就地报错，而不会删掉或覆盖其中任何一条快照。

## 端口转发

保存的机器可以携带 SSH 端口转发规则：随连接建立启动，重连后自动重建。通过 CLI 管理规则，或在界面中从机器列表或详情卡进入（`f`，或点页脚对应项）：详情卡列出规则及其实时状态，规则页面可增删规则；还没有规则时页面提供**添加**按钮。规则页面会滚动以保持选中规则可见；`x` 先点名待删规则并等待 `enter` 确认（`esc` 取消）。确认期间该位置上的规则发生变化时会取消本次移除，而不是删掉挪到该位置上的另一条。已打开的客户端约 1 秒内感知规则变化，无需重连：

```bash
herdr machine forward list <profile-id>
herdr machine forward add <profile-id> --kind local --listen-port 8080 --target-host 127.0.0.1 --target-port 80
herdr machine forward add <profile-id> --kind remote --listen-port 9000 --target-host 127.0.0.1 --target-port 3000
herdr machine forward add <profile-id> --kind dynamic --listen-port 1080
herdr machine forward remove <profile-id> <rule-number>
```

三种类型分别对应 `ssh -L`、`-R`、`-D`：

- `local` 在本机监听（默认绑定 `localhost`，可用 `--bind-address` 覆盖），经 SSH 机器转发到 `--target-host:--target-port`。
- `remote` 在 SSH 机器上监听，回连转发到目标，目标从本机一侧访问。
- `dynamic` 经 SSH 机器打开本地 SOCKS 代理，没有固定目标。

每条规则以独立的非交互 `ssh -N` 子进程运行，使用与连接本身相同的受管 SSH 配置，因此逐项设置仍以你的 `~/.ssh/config` 为准，且转发永远不会弹出提示。无法启动的规则（例如本地监听端口已被占用）只影响该规则本身；失败原因随规则记录，并显示在机器详情卡与规则页面的对应规则旁；连接与其他规则不受影响。每台机器最多 16 条规则。

## 远程文件

每台保存的机器还通过同一受管 SSH 通道暴露文件系统，底层是批处理模式的 OpenSSH `sftp` 客户端。它面向小文件——配置、脚本、笔记——不是批量传输：

这些一次性通道按档案共用一条 ssh 控制连接（master），连续的文件操作因此省掉 TCP 与 SSH 握手；空闲超过 `ControlPersist`（默认 120 秒，可按档案覆盖）后 master 自行退出。可复用的配置目录位于 `/tmp/herdr-ssh-<uid>-*`，复用时校验属主与权限；改动档案的连接字段后立刻换用新的 master。

```bash
herdr machine fs build ls /srv/app
herdr machine fs build stat /srv/app/config.toml
herdr machine fs build cat /srv/app/config.toml
herdr machine fs build get /srv/app/config.toml ./config.toml
herdr machine fs build put ./notes.txt /srv/app/notes.txt
herdr machine fs build mkdir /srv/app/logs --parents
herdr machine fs build mv /srv/app/notes.txt /srv/app/notes-old.txt
herdr machine fs build rm /srv/app/notes-old.txt
herdr machine fs build rm /srv/app/old-logs --recursive
```

profile 选择器接受标签或 profile id，与全局 `--machine` 前缀规则一致。操作复用 profile 的受管 SSH 配置、连接复用与非交互选项族，因此逐项设置仍以你的 `~/.ssh/config` 为准，且永远不会弹出提示。远程路径由 sftp 服务器相对登录目录解析（不展开 `~`）；以 `-` 开头的路径会被拒绝以免被当成选项，含 `\` 或 `"` 的路径也会被拒绝，因为批处理引用对这两类字符在不同 OpenSSH 版本间行为不一致。`ls` 与 `stat` 支持 `--json`。

单文件传输上限 1 MiB。`get` 以 `0600` 权限原子写入本地文件，绝不通过符号链接替换；`put` 先上传到同目录临时名再原子 rename 覆盖目标，目标已存在时恢复其原有权限位。`mkdir --parents` 创建中间目录；`rm` 删除目录需要 `--recursive`，不跟随符号链接，并拒绝远程根目录。SSH 传输层故障（认证、主机密钥、DNS、超时）以与连接本身相同的结构化失败类型呈现，因此机器故障在界面中显示为 Attention，而不是让命令挂起。

同一通道也驱动界面内的文件浏览器：在机器列表或详情卡按 `o`（或点页脚对应项）打开。浏览器列出远程目录的名称、类型、大小与修改时间；Enter 进入目录或在只读查看器中打开文件（≤1 MiB 的小文件），Backspace 返回上级，`r` 刷新，`/` 过滤列表。`d` 把选中文件下载到你确认的本地路径，`u` 把本地文件上传到当前目录，`m` 新建目录，`R` 重命名，`x` 经确认后删除（目录递归删除）。所有操作在后台 worker 线程执行并内联展示错误，界面不会被 SSH 阻塞。

## 会话日志

机器 profile 可以把它的窗格镜像到本地日志文件——适合审计，或事后回顾 agent 在你离开时做了什么：

```bash
herdr machine log <profile-id> on
herdr machine log <profile-id> on --path "{machine}/{date}-{pane}.log" --max-bytes 16777216 --interval 30
herdr machine log <profile-id> show
herdr machine log <profile-id> dump
herdr machine log <profile-id> off
```

该机制刻意采用快照式：客户端 worker 按配置的间隔（默认 30 秒）通过机器的 JSON API 桥轮询其窗格，窗格 revision 变化时追加一段快照——一行含 UTC 时间戳、机器、窗格与 revision 的分隔行，加上最多 200 行窗格最近文本。它不是连续字节流：两次轮询之间的快速输出以其最新状态呈现，等同于周期性的 `pane read`。worker 使用自己的桥，因此日志不依赖你正在查看哪台机器，并随机器连接生命周期重启。

路径来自模板，支持 `{date}`（UTC 日期）、`{machine}`（标签 slug）、`{machine-id}`、`{pane}`、`{session}` 变量；相对模板解析到 `<state dir>/session-logs/` 下，默认为 `{machine}/{date}-{pane}.log`。文件以私有权限创建，在大小上限（默认 16 MiB）处轮转为 `<file>.1`。所有写入经过单个后台队列——磁盘慢或窗格输出洪峰都不会阻塞客户端；队列满时快照被丢弃并计数，而不是反压界面。开关日志只编辑 profile 的 `session_log` 字段，绝不重连机器。`dump` 立即执行一次快照循环并报告追加了几个快照，是验证模板最快的方式。

同样的偏好在界面中也可编辑：machines 页面的编辑表单末尾就是会话日志字段——开/关/默认三态选择，外加路径模板、大小上限与间隔（留空即默认值）。选择保持**默认**时原值原样保留，编辑其他字段绝不会丢掉既有配置。机器详情卡展示生效中的模板、上限与间隔；日志开启且写入队列有丢弃时，还会显示丢弃计数。

## 输入广播

广播把你在一个窗格中输入的内容同步发送到一组已注册窗格——每个端点（Local 或某台保存的机器）各一个——让同一条命令同时到达多处。因为误输入同样会被扇出，该机制有两道安全闸：集合默认空且禁用，集合非空并显式开启之前不会发送任何内容。

在界面中从 machines 页面管理集合（列表或详情卡按 `b`，或命令面板的「广播输入…」）：`g` 开关广播，`a` 依次选择机器与其在线窗格完成注册，`x` 移除选中目标，`c` 清空集合。集合持久化在 endpoint catalog 旁的 `broadcast.json`，与 CLI 共享（`herdr broadcast status/enable/disable/add/remove/clear/send`，见 [CLI 参考](/zh-cn/docs/cli-reference/#输入广播)）。

广播生效期间，mode bar 常驻 `⇄ 广播 ×N` 徽标——即使在普通终端模式下——让你不会在不知情时把输入扇出到其他机器。输入的文本与按键经各端点的 API 通道送达每个已注册窗格；你正在输入的窗格本身除外（它已收到输入），粘贴保留目标窗格各自的 bracketed-paste 处理，鼠标输入绝不广播。拒绝输入的目标会以 toast 报告一次，下一次成功后重新武装；离线目标直接跳过。在同一弹层再按 `g` 或用 `herdr broadcast disable` 即可关闭。

## 状态查看与一次性命令

两条 CLI 命令覆盖不打开界面的快速检查：

```bash
herdr machine status "构建机" [--json]
herdr machine exec "构建机" -- systemctl --user status herdr
```

`machine status` 接受标签或 profile id（含已禁用机器），报告 profile 字段、实时连接探测（不可达时附结构化失败类型与信息）、在线时的远程 server 版本与协议兼容性、已保存的端口转发规则，以及会话日志偏好。`machine exec` 通过与文件操作相同的受管 SSH 通道执行单个远程命令：stdio 直通你的终端，远程退出码即命令退出码，不弹出提示，也没有超时。`--` 之后的所有内容原样作为远程命令。

## 为什么不用 mosh

mosh 面向交互式终端会话：它通过 UDP 用自有协议同步屏幕状态与击键，服务端内嵌终端模拟器。Herdr 的远程传输是完全不同的东西——一条 SSH stdio 管道，在客户端与常驻的远程 Herdr server 之间承载 Herdr 二进制 wire 协议（带长度前缀的结构化消息：请求、响应、事件与帧）。mosh 无法承载它：mosh 只提供屏幕同步，没有通用字节流通道，其服务端也只会启动终端会话。

更重要的是，mosh 提供的韧性 Herdr 已经在另一层内建。远程 Herdr server 持有会话状态——窗格、agent、工作区——网络断开时继续运行。客户端 supervisor 检测传输断裂（应用层健康检查，而非只看 TCP），带退避自动重连，并复用 SSH 连接复用让重连足够便宜；睡眠唤醒与网络切换不过是一次普通重连。会话的存续不依赖传输不间断——这正是 mosh 为普通 shell 补上的性质。在其下再加一层基于 UDP 的 mosh 反而会削弱模型：它要求主机上有 `mosh-server` 二进制且放行 UDP，而只允许 SSH 的环境两者都不提供。因此传输在任何场景都保持纯 SSH，包括远程自动化使用的 JSON API 通道。

## 连接问题

- **Reconnecting：** 网络中断、睡眠或 SSH 故障后，Herdr 会以有上限的退避间隔重试。受影响机器上的横幅会显示第几次重连与预计下次尝试时间，并提供可点击操作：**立即重连**马上发起一次尝试，**放弃**会禁用该机器（可在 machines 页面重新启用）。SSH 连接会监测应用层活动并在空闲时探测，避免已断开的连接一直显示 Online。Local 使用本地连接关闭或失败来判断断线，而不是远程健康探测。
- **Attention：** 目标需要无法在后台完成的操作，例如批准主机密钥、认证或准备兼容服务器。其他机器仍可使用。侧边栏机器行会保留 Attention 标记；点击打开该机器的详情卡，其中显示结构化的失败原因（DNS、超时、主机密钥未知或已变更、认证、远程安装、协议）、建议的下一步、独立修复命令和重连操作。对有界面内恢复路径的失败，还会显示**处理失败**入口（`v`，也可在页脚点击）：
  - *主机密钥未知* 打开首次信任（TOFU）确认框，显示主机、密钥类型和 SHA256 指纹（失败时未捕获到指纹会先扫描）。带外比对指纹后，选择**信任并记住**（把密钥写入 `known_hosts` 并重连）、**仅本次连接**（用进程级 `accept-new` 覆盖重连一次，不写入目录文件），或**中止**。
  - *主机密钥已变更* 打开强阻断对话框，区分「机器重装」与可能的中间人攻击。带外核实之后，**移除旧记录并重试**用 `ssh-keygen -R` 删除记录并重连，随后经未知密钥对话框确认新密钥。
  - *需要认证* 打开引导对话框，列出服务器提供的认证方式与已配置的密钥文件。批准**交互认证**后，会通过 Herdr 的内存 askpass 通道进行一次交互尝试：SSH 密码与口令提示以掩码输入框弹出，回答只发送给提示应答方，绝不记录、落盘或持久化。口令提示还会提醒你可以用 `ssh-add` 把密钥加载进 agent，以便后续非交互连接。同一对话框还提供预采集主机密钥和复制修复命令两条替代路径。添加表单里失败的**测试连接**同样提供交互认证与**核对主机密钥**入口（`Ctrl+R`）。
- **保存机器文件错误：** 目录文件无法读取或内容无效时，当前连接保持不变。Herdr 会显示通知并自动重试读取。

后台连接不会回答提示，也不会安装、更新、重启或交接服务器。交互式 SSH 认证只有在界面内显式批准后才会启用；默认路径保持完全非交互并快速失败，绝不弹出提示。对于界面内恢复覆盖不到的情况，请在交互式终端运行 Herdr 显示的独立设置命令，例如：

```bash
herdr --remote workbox
```

使用配置中的目标。如果添加时选择了命名会话，再加上可选的 `--session <name>`。完成批准提示后，重启客户端以重试 Attention 连接。不要仅因为版本与客户端不同就停止运行中的服务器。

认证失败时，先检查普通 SSH。对于有口令的私钥，请在启动 Herdr 的非交互式后台连接前用 `ssh-add` 加载。

## 设置与自动化

UI 默认使用客户端本地的主题、侧边栏设置和按键绑定。选中服务器公布的自定义命令和插件仍在那里运行。Herdr 不会将本地插件、配置、可执行文件或机密复制到 SSH 主机。远程缺少命令时会明确报错。编辑客户端设置后，使用 UI 中的 `reload config`；参见[配置](/zh-cn/docs/configuration/)。

有多台机器时，默认智能体行会显示 `machine` token。已有的自定义行保持不变；需要机器标签时请显式加入 `machine`。[侧边栏行布局](/zh-cn/docs/configuration/)还支持按机器标签设置条件颜色。

工作区、标签页、窗格 ID 和智能体名称仅在所属服务器内有效。两台机器可能都有 `w1:p1` 或名为 `reviewer` 的智能体。在 UI 中选择机器不会改变已有窗格中 CLI 命令的目标，它们仍使用继承的会话和 socket。远程自动化可使用 `herdr --machine <label-or-id> agent list` 获取 ID，并在后续操作中使用同一前缀。CLI 直接使用保存的 SSH 目标和会话，不需要打开 TUI。省略 `--machine` 时现有行为不变。支持的命令、更新要求和远程路径规则见 [CLI 参考](/zh-cn/docs/cli-reference/)。

## 更新与保存的数据

配置只保存不透明 ID、标签、SSH 目标、明确的远程会话名和启用状态，以及可选的组织元数据（组、标签、颜色）、SSH 连接选项（端口、用户、密钥文件、跳板机等）、端口转发规则和会话日志偏好。Herdr 不会将密码、私钥、智能体票据或 SSH 控制套接字存入机器目录。认证仍由 OpenSSH 处理。

客户端与服务器协商兼容性，不要求版本完全相同。保存机器的连接还需要服务器支持 `surface_interest` 和 `health_check` 能力。缺少这些能力的旧服务器，即使能独立连接，也会显示 Attention，直到明确更新。其他缺失的方法只禁用对应操作。

更新兼容客户端不会替换远程服务器或停止其智能体。需要新的服务器行为时，请明确更新该服务器。正常替换会在停止服务器及其窗格进程之前询问。

实时交接是实验性的，需要明确选择。独立设置过程中需要替换受支持的服务器时，可为 `herdr --remote` 显式添加 `--handoff`；正常连接或认证修复不需要它。有关重启和交接的选择，请参阅[更新](/zh-cn/docs/install/)及[会话状态与恢复](/zh-cn/docs/session-state/)。

## 页面与认证恢复

宽屏机器页提供列表和详情分栏；窄屏使用列表进入详情。从主机密钥或认证对话框返回后，添加表单的全部字段与上一次测试结果都还在。字段栏可用鼠标滚轮滚动，并跟随键盘焦点；窄屏时省去预览，测试步骤显示在字段下方。

交互认证得到明确许可后，通过内存 askpass 通道完成探测、安装、验证和连接交接；密码不会写入配置。`仅本次信任` 固定界面展示的公钥到连接拥有的临时 known_hosts 文件，连接结束后回收。永久信任只保存已展示的公钥，操作目标通过 `ssh -G` 解析，包括端口、别名和 known_hosts 路径。代理连接无法直接扫描时走同一路线的 OpenSSH 交互确认，不绕过跳板机。

取消测试连接、认证或文件页会结束该任务的本地 SSH/SCP/SFTP 进程；已经完成的远端写入不会回滚。文件列表忽略过期读取，但会结算每个请求，重复响应不会让加载状态卡住。

Windows 原生回放：`powershell -File scripts/windows_tui_compat.ps1 -ExePath target/debug/herdr.exe -Shell powershell`；PowerShell 7 使用 `-Shell pwsh`。加 `-Interactive` 在 WezTerm 内检查拖选、中文输入和 60×16、80×24、120×40、160×50 布局。WSL 在发行版内部构建并运行 Linux Herdr，使用发行版默认用户和登录 shell。CI 的 PowerShell 回放验证 ConPTY，不替代桌面输入法和鼠标验收。
