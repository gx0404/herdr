Herdr 自动检测受支持的智能体。官方集成可以额外提供用于恢复的原生会话身份、生命周期状态上报,或两者兼有。

当你想要智能体原生会话恢复、直接生命周期上报,或两者都要时,使用集成。完整的状态权威模型见[智能体](/zh-cn/docs/agents/)。

## 安装集成

在 Herdr 中打开设置,用集成标签页为 `PATH` 上发现的智能体安装集成,或手动运行命令。在该标签页里，`Enter`（以及主按钮）**只安装当前选中的那一行**——主按钮只在选中行确实需要安装时才出现，页脚列出的 `a` 才一次性安装全部待装项:

```bash
herdr integration install pi
herdr integration install claude
herdr integration install codex
herdr integration install kimi
herdr integration install opencode
```

安装完成后，标签页会在各行下方列出每个集成写入的位置以及告警。较长的消息按面板宽度折行显示，不会被截断；列表可以用鼠标滚轮或 `↑`/`↓` 滚动。点击某一行即选中该行。

## 窗格上报来源

Herdr 会校验内置集成上报（`source` 以 `herdr:` 开头）以及所有带 `pane_id` 的 `account.usage.report` 请求的进程来源。来自窗格进程树的上报正常生效。后台会话或守护进程如果只继承了 `HERDR_PANE_ID`、已经脱离窗格进程树，上报会收到成功应答，但不会改变窗格状态、会话身份、活动、元数据或用量。不带窗格的账号级用量上报，以及第三方来源的窗格上报，保持原有行为。

使用 tmux 或 screen 时，如果上报进程的祖先包含其服务端，且目标窗格进程树内有同类复用器的客户端，也接受上报。这是基于进程名的启发式判断，不能证明客户端和服务端属于同一复用器会话。如果无法读取对端 PID 或进程父链，则放行；Windows 的部分孤儿进程会保留已退出父进程的 PID，也属于无法确定的情况。

来源校验默认开启。可用以下配置关闭，然后重新加载配置：

```toml
[server]
verify_report_process = false
```

`HERDR_REPORT_BG_SESSIONS=1` 只绕过 Claude 钩子侧的后台会话过滤，仍受服务端来源校验约束；要允许脱离窗格的上报，还需要设置 `server.verify_report_process = false`。

此功能防止继承窗格环境导致的意外上报，不作为身份认证边界。自定义集成应使用自己稳定的来源名称。

## 卸载集成

```bash
herdr integration uninstall pi
herdr integration uninstall claude
herdr integration uninstall codex
herdr integration uninstall kimi
herdr integration uninstall opencode
```

Herdr 对 Linux/macOS 上的集成配置和所有平台的新文件使用原子保存；Windows 上的现有文件先备份再原地更新，以保留权限。如果 Windows 提示存在备份，请在重试前关闭智能体并检查配置：未完成的 `.herdr-backup.pending` 只能在确认配置正确后删除，不能用于恢复；完整 `.herdr-backup` 的内容可在需要时写回现有文件（若文件已丢失，先设置其预期权限），确认配置正确后再删除备份。

## Herdr 如何使用集成

Herdr 以两种不同方式使用集成:

| 集成类型 | 智能体 | 效果 |
| --- | --- | --- |
| 生命周期权威 | Pi、Kimi Code CLI、OpenCode | 已安装且在为该窗格主动上报时,由钩子或插件事件决定 `idle`、`working` 和 `blocked`。对同一个生命周期权威,Herdr 不再使用屏幕清单兜底。 |
| 会话身份 | Claude Code、Codex | 集成上报用于恢复的原生会话引用。状态仍来自 Herdr 的屏幕清单检测。 |

自定义集成在定义了原生终端 UI 中不可见的状态时,也可以上报状态。它们不需要内置到 Herdr 中,也不要求 Herdr 识别智能体的可执行文件。

## 集成你自己的智能体

在 Herdr 窗格中运行的智能体会继承 `HERDR_ENV`、`HERDR_PANE_ID`、`HERDR_BIN_PATH` 和 `HERDR_SOCKET_PATH`。如果智能体提供生命周期钩子,可从这些钩子通过 Herdr CLI 上报语义状态:

```bash
"$HERDR_BIN_PATH" pane report-agent "$HERDR_PANE_ID" \
  --source custom:my-agent \
  --agent my-agent \
  --state working
```

当智能体等待输入时上报 `idle`,需要用户决策时上报 `blocked`。用 `--message` 描述阻塞原因。智能体退出时,释放同一来源的生命周期权威:

```bash
"$HERDR_BIN_PATH" pane release-agent "$HERDR_PANE_ID" \
  --source custom:my-agent \
  --agent my-agent
```

仅在 `HERDR_ENV=1` 且必要变量存在时上报,这样集成在 Herdr 外不会执行任何操作。保持 `--source` 稳定且对该集成唯一。如果上报可能乱序到达,请加入严格递增的 `--seq`;Herdr 会忽略同一来源的旧序列号。

你可以在 `report-agent` 中加入 `--agent-session-id` 或 `--agent-session-path`,也可以在会话身份独立于状态变化时使用 `pane report-agent-session`。Herdr 会通过窗格和智能体 API 暴露该引用。自动恢复会话还要求 Herdr 知道如何启动该智能体并恢复所引用的会话。

要实现可移植的集成,请使用 `HERDR_BIN_PATH` 和 CLI 包装命令。需要直接 IPC 的代码可以发送 [Socket API](/zh-cn/docs/socket-api/) 中说明的等效 `pane.report_agent`、`pane.report_agent_session` 和 `pane.release_agent` 请求。

[Prime Agent 内置的 Herdr 上报器](https://github.com/PrimeIntellect-ai/prime-agent/blob/main/packages/coding-agent/src/core/extensions/builtin/herdr-agent-state.ts)是一个真实实现示例。它只在 Herdr 中启用,将智能体事件映射为 `working`、`idle` 和 `blocked`,跨会话保持上报顺序,并在退出时释放权威。

一些集成会上报智能体的原生会话引用。除非被 `[session] resume_agents_on_restore = false` 禁用,Herdr 会在服务器重启后使用官方会话引用恢复 Claude Code、Codex、Kimi Code CLI、Pi 和 OpenCode 的窗格。

原生会话恢复需要最新的 Herdr 集成: Pi 集成版本 `2`、Claude Code 版本 `6`、Codex 版本 `5`、Kimi Code CLI 版本 `3`、OpenCode 版本 `5`。用 `herdr integration status` 查看已安装版本。

## Pi

安装 Pi 集成:

```bash
herdr integration install pi
```

Herdr 把内置扩展写入:

```text
~/.pi/agent/extensions/herdr-agent-state.ts
```

如果设置了 `PI_CODING_AGENT_DIR`,Herdr 会改为写入 `$PI_CODING_AGENT_DIR/extensions/herdr-agent-state.ts`。如果 Pi agent 目录已经存在,Herdr 会创建 extensions 目录。卸载只删除那个扩展文件。

从集成版本 `10` 起,扩展还会在交互式(TUI)会话里上报两样东西:会话用量,显示在账号页(见[监控](/zh-cn/docs/monitoring/));以及供 Agent 活动窗口使用的活动树。Pi 本身没有内置的子 agent、待办或后台任务,这些都由扩展提供。每次调用不属于 Pi 内置工具的工具都会成为一个活动项,内容是该工具的流式输出;官方 `subagent` 扩展还会为每个被委派的 agent 加一个子项。这棵树最多保留八个工具调用项(有新项时先丢已结束的)、每项之下最多八个子项,每项的输出只保留最后 2,000 个字符。Pi 不在磁盘上保留这些记录,所以扩展把整棵树发给 Herdr。升级后请重新安装 Pi 集成以启用它们。

## Claude Code

安装 Claude Code 钩子:

```bash
herdr integration install claude
```

该钩子在会话启动时把 Claude Code 的会话身份上报给本地 Herdr socket。Claude Code 的状态来自 Herdr 的屏幕清单检测。

Claude 集成 v10 仅匹配文档列出的 `SessionStart` 来源: `startup`、`resume`、`clear`、`compact` 和 `fork`。这会阻止导入 Claude 钩子的第三方工具用其他来源值触发导入的 Herdr Claude 钩子,而不会禁用其他 Claude 兼容钩子。升级后请重新安装 Claude 集成,以迁移原有的通配匹配规则。Claude 新增来源值时需要更新集成。

Claude 集成 v11 在 macOS 和 Linux 上还会订阅 `SubagentStart`、`SubagentStop`(matcher 为 `*`)以及 `TaskCreated`、`TaskCompleted`。这些钩子只向本地 Herdr socket 通知 Claude Code 的子 agent 或任务发生了变化,不上报 agent 状态。Windows 上不安装这些钩子。升级后请重新安装 Claude 集成以添加它们。

Claude Code 后台会话(用 `claude --bg` 启动或由 Claude Code daemon 托管的会话)不向 Herdr 上报。它们继承了启动 daemon 的那个窗格的变量,上报会被显示成那个窗格的 agent。钩子根据 daemon 设置的 `CLAUDE_JOB_DIR` 或 `CLAUDE_CODE_SESSION_KIND=bg` 变量识别后台会话。如仍要上报,在它们的环境中设置 `HERDR_REPORT_BG_SESSIONS=1`。Herdr 会从新窗格的环境中去掉这两个变量,因此即使 Herdr server 是从后台会话中启动的,窗格里的 Claude Code 仍会上报。

Herdr 从 Claude Code 自己的会话文件构建它的活动树。Claude Code 在后台运行的子 agent,在 Claude Code 为派生它的 agent 记下结束通知后显示为完成或失败;被停掉的子 agent 显示为失败,摘要开头注明 `stopped`;已结束的子 agent 被重新唤起后重新算作运行中。Claude Code 的 workflow 运行的子 agent 归在该 workflow 及其阶段之下,状态改看 workflow 的 journal:记有结果的显示为完成,记有失败的显示为失败;只记了开始的算运行中,直到其转录 30 分钟没有变化才显示为未知。workflow 本身结束后,其下仍在运行或未知的子 agent 随 workflow 的终态落定。其余没有这类记录的子 agent,转录在最近两分钟内有变化时算运行中,之后显示为未知。会话很长时 Herdr 只在主转录较新的部分里查找结束通知,更早的后台子 agent 可能显示为未知。

在 Agent 活动窗口里,Claude Code 子 agent 的输出为每个工具调用附上主要参数,例如 Bash 命令、文件路径或搜索词;每个工具结果显示输出的前五行,其余只标出剩余行数。失败的工具结果标为 `[tool error]`。

Herdr 默认使用 `~/.claude`,设置了 `CLAUDE_CONFIG_DIR` 时使用后者。Claude 配置目录必须已经存在。安装会写入 `hooks/herdr-agent-state.sh`,并向 `settings.json` 添加 Herdr 钩子条目。卸载会移除匹配的钩子条目并删除钩子脚本。

## Codex

安装 Codex 钩子:

```bash
herdr integration install codex
```

Codex 钩子通过与其他集成相同的本地 socket API 上报会话身份。Codex 的状态来自 Herdr 的屏幕清单检测。

Codex 集成 v9 在 macOS 和 Linux 上还会订阅 `SubagentStart` 和 `SubagentStop`。这些钩子只向本地 Herdr socket 通知 Codex 的子 agent 线程启动或结束,不上报 agent 状态;Herdr 会从 Codex 自己的会话文件重建活动树。Codex 0.157 默认启用钩子。Herdr 仍会显式写入 `[features] hooks = true` 以兼容旧版本；显式设为 false 会禁用钩子。Windows 上不安装这些活动钩子。升级后请重新安装 Codex 集成以添加它们。

Codex 子 agent 以「昵称 · 任务名」标注,任务名取 agent 路径的最后一段,例如 `Boyle · herdr_probe`;摘要显示完整的 agent 路径,子 agent 失败或被中断时改为显示原因。没有昵称的子 agent 只显示任务名。

在 Agent 活动窗口里,Codex 子 agent 的输出是它自己线程的可读转写:来自父 agent 的消息、`user:` 与助手消息、`(thinking)` 标记、带主要参数的工具调用及其输出的前五行、计划,以及带该回合最后一条消息的 `[task complete]`。开发者指令、子 agent 从父 agent 继承的历史、token 计数、额度限制等簿记记录不显示;Herdr 认不出的记录只在方括号里显示其类型。给其它 agent 发消息或管理 agent 的工具调用(`send_message`、`followup_task`、`send_input`、`interrupt_agent`、`close_agent`、`resume_agent`、`wait_agent`)在 `→` 后显示目标 agent,再接消息正文;Codex 加密保存的消息显示为 `(encrypted)`。

Codex 只运行你信任过的钩子。安装集成后,或更新改动了钩子后,Codex 下次启动会显示「Hooks need review」。请选「Trust all and continue」,或进入「Review hooks」信任 Herdr 的钩子。如果选「Continue without trusting」,Herdr 的钩子不会运行,Herdr 也拿不到 Codex 的会话身份和活动信号。Codex 还没信任当前的 Herdr 钩子时,`herdr integration install codex` 会输出这条提醒,`herdr integration status` 也会在 Codex 那一行下面附一条提示;你在 Codex 里用 `/hooks` 停用了 Herdr 的钩子时,这两条命令同样会提示。

Herdr 默认使用 `~/.codex`,设置了 `CODEX_HOME` 时使用后者。Codex 配置目录必须已经存在。安装会写入 `herdr-agent-state.sh`、更新 `hooks.json`,并确保 `config.toml` 中有 `[features] hooks = true`。如果存在已弃用的顶层 `codex_hooks` 标志,它也会一并移除。卸载会从 `hooks.json` 中移除 Herdr 条目并删除钩子脚本,但不改动 `config.toml`。

会话钩子会随会话 ID 转发 Codex 的转录路径,上报后活动发现即可跟随仅在该窗格设置的 `CODEX_HOME`。请在同一配置目录安装集成,并重启 Codex 加载更新后的钩子。恢复仍使用会话 ID。归档布局与有界压缩转录支持见[智能体活动](/zh-cn/socket-api/#智能体活动)。

Herdr 通过窗格内的启动器执行受管 Codex 启动和会话恢复。对交互启动、`resume` 和 `fork`，启动器根据窗格当前 `PATH` 选择可执行文件，通过 `--help` 确认完整的 `--no-daemon` 参数后才添加它。Codex 0.157 默认共享 daemon；前台模式让钩子保持在当前窗格的进程树中，避免复用另一窗格的环境。保存的恢复命令仍是原始 `codex resume <id>`。Herdr 不修改 Codex 配置，也不停止已有 daemon。

新窗格还会在 `PATH` 最前面加入私有的原生 `codex` shim；通过该路径找到的普通 `codex` 命令使用同一启动器。登录脚本、nvm/mise 初始化、alias、shell 函数、绝对可执行路径以及外部包装器可能绕过它；这些场景请对支持该参数的 Codex 显式使用 `--no-daemon`。Herdr 不编辑 shell 启动文件。为避免包装器递归，启动器会从实际启动进程的 `PATH` 中移除自己的 shim 目录；Codex 内的子命令使用剩余的原始路径。

非交互子命令（包括 `exec`、`review`、`app-server`、`mcp-server`、`login`、`agents`、`queue`）、显式 `--remote` 和已有的 `--no-daemon` 都原样传递。未知选项也保守地原样传递。子命令清单以 Codex 0.157 为准，包含隐藏命令和别名。未来新增的裸命令名可能无法与单词提示词区分；Herdr 尚未适配该命令时，请通过真实 Codex 可执行文件路径调用。不支持该参数的旧版程序保持原样。能力探测最多两秒，标准输出与错误输出合计上限 64 KiB；探测失败时，Herdr 提示前台隔离能力未知，并且只启动一次原始命令。Codex 启动失败后不会自动重试。在 Herdr 窗格外不会添加参数。此启动器不会为脱离窗格或远端 Codex 的钩子赋予可信的窗格归属。

## Kimi Code CLI

安装 Kimi Code CLI 钩子:

```bash
herdr integration install kimi
```

该钩子向 Herdr 上报 Kimi 的会话身份和生命周期状态,用于原生恢复和权威的 `idle`、`working`、`blocked` 状态。需要 Kimi Code CLI `0.14.0` 或更新版本。

从集成版本 `8` 起,该钩子还订阅 `SubagentStart`、`SubagentStop`、`Notification`(`task.*`)和 `PostToolUse`(`TodoList`)。这些条目只告诉 Herdr 活动树可能变了,不携带会话内容;活动树由 Herdr 自己读 Kimi 的会话文件得到。

集成版本 `8` 还把 Kimi 回合的每种结束方式都映射为 `idle`:回合完成时的 `Stop`、被打断时的 `Interrupt`,以及回合出错(例如 provider 报错或鉴权失败)时的 `StopFailure`。因此出错的回合不会再让窗格一直停在 `working`,直到 Kimi 退出。Herdr 支持的所有 Kimi Code CLI 版本都有 `StopFailure`;升级后请重新安装 Kimi 集成以添加它。

集成版本 `8` 还会从钩子自身的绝对 `KIMI_CODE_HOME`（未设置时用钩子的用户目录）补报会话目录,因此每个窗格的活动树都能跟随自己的配置目录,即使它与服务器不同。若 `SessionStart` 早于会话落盘,后续生命周期和活动事件会重新查找。只有唯一且与会话 ID 匹配的目录才会被接受;恢复仍使用 ID。空值、相对路径、字面量 `~`、重复目录,或超过 256 个工作目录条目的查找会省略路径,保留正常状态上报。Windows 同样补报目录,活动更新仍依靠轮询。请重新安装 Kimi 集成以更新脚本。

Herdr 默认使用 `~/.kimi-code`,设置了 `KIMI_CODE_HOME` 时使用后者。Kimi Code 配置目录必须已经存在。安装会写入 `hooks/herdr-agent-state.sh`,并在 `config.toml` 中追加 Herdr 管理的 `[[hooks]]` 条目。卸载会移除 Herdr 管理的配置块并删除钩子脚本。

Herdr 用 `kimi --session <id>` 恢复保存的 Kimi 会话。

## OpenCode

安装 OpenCode 插件:

```bash
herdr integration install opencode
```

该集成支持 OpenCode V1 `1.18.29` 及更高版本，以及 OpenCode V2（已验证 beta `19242`）。OpenCode 配置目录必须已经存在。Herdr 将服务端入口安装到 `~/.config/opencode/plugins/herdr-agent-state.js`，并在该配置目录安装共享 TUI 插件 `herdr-tui-session.js` 和 V2 TUI 入口 `herdr-opencode/tui.js`。

安装会在 `tui.jsonc` 中注册 V1 TUI 插件，并在 `cli.json` 中注册 V2 TUI 插件，同时保留其他设置和插件。如果 OpenCode 仍有 V1 TUI 偏好需要迁移(`tui.json` 或 `kv.json`),Herdr 会推迟注册，以便首次启动时执行迁移；此时请先启动一次 `opencode2`，然后重新安装集成。否则 Herdr 会创建 `cli.json` 并注册插件。安装后请重启 OpenCode TUI。卸载会删除受管理的插件文件及其配置条目。

V2 生命周期上报在窗格本地的 TUI 中运行。即使多个窗格共享同一个 OpenCode 服务端，事件也只归属于该 TUI 选中的根会话。完成和中断会清除工作状态；待处理的权限请求、表单以及执行失败会使窗格保持阻塞。V2 Mini 和无界面客户端不运行 TUI 插件，因此不提供此生命周期上报。

V1 TUI 跟踪窗格选中的会话及其后代。只要其中任何会话仍在忙碌或重试，就保持 working；存在待处理的权限请求或问题时保持 blocked。连接时会读取已有活动，已取消工具的请求不会在重新连接后再次变成阻塞项。查看子代理时保留原来的会话范围；直接连接子会话时只跟踪它及其后代，不包括兄弟会话。

本地 V1 的 `opencode run` 和 `opencode --mini` 保留原有服务端钩子；此变更不会为 Mini 或无界面客户端添加窗格本地的生命周期上报。更新集成后，请同时重启共享 OpenCode 服务器及其 TUI，避免旧服务端上报覆盖窗格本地状态。

在 OpenCode V1 下，服务端插件只在 OpenCode 自己报告会话忙碌（`session.status`）时上报 `working`，并按 OpenCode 发出事件的顺序发送上报，因此回合结束后窗格总会回到 `idle`。其他插件只添加消息、不启动回合时（`noReply` 提示，例如后台任务的通知），窗格状态不会改变。

该插件在 OpenCode 运行于 Herdr 窗格内时上报生命周期状态和会话身份。在 OpenCode 发出携带会话信息的事件后,Herdr 可以用上报的会话 id 通过 `opencode --session <id>` 恢复该窗格。插件未安装时,屏幕清单检测仍然可用。

从集成版本 `13` 起,V1 的服务端插件还会在会话或其待办变化时通知 Herdr,子 agent 会话也一样;V2 的 TUI 插件不发这类通知。这些通知不携带会话内容:活动树由 Herdr 自己经 `opencode db` 只读查得,来自该会话派生的子 agent 会话(各自的消息与工具调用作为内容)以及该会话的待办。最后一条回复以错误告终的子 agent 会话显示为失败,摘要以错误名与说明开头,例如 `APIError: Rate limit exceeded`。OpenCode 并不保存所有错误:配置的模型已不存在时,它只在自己的界面里报错,会话里只留下提示词,所以 Herdr 把这个子 agent 显示为运行中,直到最后一次更新 30 分钟后改为未知。

## 已退役的集成

本 fork 只提供 Pi、Claude Code、Codex、Kimi Code CLI 和 OpenCode 五家官方集成。其余内置集成连同各自的捆绑检测清单都已退役:

- CLI 不再接受这些名字。对 `cursor`、`omp` 这类已退役的名字,`herdr integration install` 与 `herdr integration uninstall` 会给出退役提示和当前支持的目标列表,`herdr integration status` 也不再列出它们。原先实验性的 `letta` 目标从来没有 API 名称,所以得到的是「未知的集成目标」错误和同样的列表。
- 旧客户端仍可能向 `integration.install` 或 `integration.uninstall` API 方法传入已退役的目标。请求照常解析,并得到 `integration_retired` 错误;`integration.list` 不再返回已退役的目标。
- 早先版本写进已退役智能体配置目录的钩子或插件不会被改动。不再需要时请手动删除;它们上报的会话按非官方来源处理,不用于恢复。由于 `herdr integration uninstall` 同样拒绝已退役的名字,本 fork 无法替你清理:请自行打开该智能体自己的配置目录,查阅它自己的文档定位钩子或插件文件的确切位置并删除。
- 用量 statusline 回调是唯一的例外。早先版本可能为上报用量包装过 Antigravity CLI 的 `~/.gemini/antigravity-cli/settings.json`(或该账号 `profile_dir` 下的同名文件)里的状态栏命令。Herdr 仍能识别这层包装,但只删不装:对配置了 `agent = "antigravity"` 的账号以 `enabled: false` 调用 `account.usage.integration` 会还原原来的状态栏命令,`enabled: true` 则被拒绝。
- 在窗格里运行的已退役智能体只是普通程序:不会被自动检测,指向它的配置键(例如 `[ui.sound.agents]` 覆盖项)会被忽略。

无论是否退役,任何智能体仍可通过[集成你自己的智能体](#集成你自己的智能体)中的通用接口上报状态。ZCode 以外部智能体来源的形式支持,而不是内置集成:它是从不在窗格里运行的桌面应用,Herdr 把它最近仍在运行的根会话列在 Agents 面板的「外部」分组下(见[智能体](/zh-cn/docs/concepts/#智能体)),并读取它的本地 token 用量(见[监控](/zh-cn/docs/monitoring/)),不会往 ZCode 里安装任何东西。

## 自定义状态标签

集成只把生命周期状态作为语义状态上报。例如,上报智能体为 `working` 时,不在生命周期报告中添加展示字段。

```bash
herdr pane report-agent w1:p1 \
  --source custom:docs \
  --agent docs-bot \
  --state working
```

与 Herdr 管理的集成并行运行的用户钩子,应该使用元数据而不是 `report-agent`。元数据只改变展示,不会夺走集成对 `idle`、`working`、`blocked` 或会话恢复的权威。`--agent` 和 `--applies-to-source` 只守卫展示字段 (`--title`、`--display-agent` 和 `--state-label`)。令牌补丁始终生效;上报方负责清除或刷新 TTL。`--display-agent` 修改显示名称。

```bash
herdr pane report-metadata "$HERDR_PANE_ID" \
  --source user:claude-title \
  --agent claude \
  --title "Refactor auth middleware" \
  --display-agent "Claude: auth" \
  --token summary="refactor auth" \
  --state-label working="refactoring auth" \
  --ttl-ms 3600000
```

令牌和状态标签只影响视觉。等待、通知和工作区汇总仍使用语义状态。

## 调试集成状态

列出已知的智能体:

```bash
herdr agent list
```

需要验证 Herdr 能看到什么时,读取窗格:

```bash
herdr pane read w1:p1 --source recent --lines 50
```

如果集成状态看起来不对,先确认智能体运行在 Herdr 内部,并且相关的钩子或插件是为同一个用户账号安装的。
