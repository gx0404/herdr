---
title: 安装 Herdr
description: 在 Linux、macOS 和 Windows 上安装、更新和验证 Herdr。
---

Herdr 为 Linux、macOS 和 Windows 提供稳定通道二进制文件。Windows 支持已正式发布,并记录了平台专用的已知限制和持续修复。

## GX fork 安装包

`gx0404/herdr` fork 有独立的安装包链路，目标平台是 Windows x64 与 Ubuntu 22.04 / 24.04 amd64。发布后可从 [fork 的 GitHub Releases](https://github.com/gx0404/herdr/releases) 下载 `gx-v<version>` 标签下的产物；它们与下文的上游安装方式相互独立。

| 系统 | 安装包 |
| --- | --- |
| Windows x64 | `herdr-gx-<version>-windows-x86_64-setup.exe` |
| Ubuntu amd64 | `herdr-gx_<version>_amd64.deb` |

Windows 双击运行 Setup EXE，按当前用户安装到 `%LOCALAPPDATA%\Programs\Herdr GX`，包含应用本地 ConPTY 运行时，并将安装目录加入用户 PATH。重新打开终端后检查：

```powershell
where.exe herdr
Get-Command herdr
herdr --version
herdr
```

如果命中了其他安装或 shell 别名，先检查显示的路径，不要盲目删除其他安装。已经打开的终端可能仍保留旧环境。未签名安装器可能触发 SmartScreen 提示，请核对发布来源和校验值，不要关闭安全防护。

Ubuntu 将 `<version>` 替换为下载的包版本后运行：

```bash
sudo apt install ./herdr-gx_<version>_amd64.deb
command -v herdr
herdr --version
herdr
```

程序安装到 `/usr/bin/herdr`，无需修改 shell 配置或 PATH。APT 会报告包名冲突，并可能建议移除上游 `herdr` 包，请在确认前检查事务内容；不强制覆盖其他包拥有的文件。原有 `~/.local/bin` 或 `/usr/local/bin` 中的命令仍可能优先，请检查 `command -v herdr`。

GX 安装包的版本输出包含 `-gx.windows-installer.` 或 `-gx.deb.` 及源码提交号。升级时下载并运行新版安装器，或安装新版 deb。升级前先完成工作并自行停止旧的本地 Herdr 会话；Windows 安装器遇到文件占用会拒绝操作，不会杀掉 pane 进程。替换磁盘文件不代表运行中的服务器已经升级，安装后请重新打开终端并启动新版本。

这些安装包会在修改配置或安装上游程序前，拒绝 `herdr update`、`herdr update --handoff` 以及 `herdr channel set stable` / `herdr channel set preview`。`channel show` 只读，并说明渠道不管理此安装包。新启动的包 runtime 不检查上游二进制更新，也不恢复旧自更新通知；agent 检测清单更新仍独立运行。这项本地保护不屏蔽仍在运行的旧服务器或远程服务器发来的通知。当前没有 GX APT 软件源，因此普通 `apt upgrade` 不会发现 GitHub 上的新版本。

Windows 从“已安装的应用”卸载 **Herdr GX**；Ubuntu 运行：

```bash
sudo apt remove herdr-gx
```

卸载保留用户配置和会话数据；Windows 只移除本安装器添加的 PATH 条目。Release 同时提供 `manifest.json` 和 `SHA256SUMS`，用于核对产物来源与摘要。

## 安装

以下方式安装的是上游 Herdr，不是 GX fork。在 Linux 或 macOS 上运行:

```bash
curl -fsSL https://herdr.dev/install.sh | sh
```

在 Windows 上运行:

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"
```

如果端点安全软件阻止该无文件 PowerShell 命令，请打开命令提示符并运行：

```cmd
curl.exe -fsSLo install.cmd https://herdr.dev/install.cmd && install.cmd && del install.cmd
```

安装器会下载适合你平台的发布二进制文件并放到 PATH 上。新的直接安装默认使用稳定更新通道。现有的 Windows 预览安装会继续留在预览通道,直到你运行 `herdr channel set stable`。在 Windows 上,PATH 指向当前带版本号的发布目录;安装器还会更新 `current` 和稳定的 `bin` 兼容别名,因此更新时不需要覆盖正在运行的 `herdr.exe`。

## 用 Homebrew 安装

如果你已经在用 Homebrew:

```bash
brew install herdr
```

## 用 mise 安装

如果你已经在用 mise:

```bash
mise use -g herdr
```

如果 mise 报 `herdr not found in mise tool registry`,请更新 mise 后重试。旧版 mise 早于 Herdr 的注册表条目;`mise use -g github:herdrdev/herdr` 可以作为临时兜底。

## 用 Nix 安装

如果你已经在用 Nix,Herdr 提供了一个从源码构建的 flake:

```bash
nix run github:herdrdev/herdr/v0.x.y
nix build github:herdrdev/herdr/v0.x.y
nix profile install github:herdrdev/herdr/v0.x.y
```

把 `v0.x.y` 替换为最新的发布标签。省略标签可以跟踪 `master`,但常规安装建议使用发布标签。

flake 还提供一个开发 shell:

```bash
nix develop github:herdrdev/herdr
```

更新时使用你安装 Herdr 的同一套 Nix 工作流。对于 profile 安装,列出 profile 条目并升级 Herdr 条目:

```bash
nix profile list
nix profile upgrade <index-or-name>
```

如果 Herdr 是你自己 flake 的一个 input,更新该 input 并重建你的系统、Home Manager 或开发环境:

```bash
nix flake update herdr
```

## 手动下载

也可以从 [GitHub releases](https://github.com/herdrdev/herdr/releases) 下载二进制文件。

选择匹配你系统的产物:

| 系统 | 产物 |
| --- | --- |
| Linux x86_64 | `herdr-linux-x86_64` |
| Linux aarch64 | `herdr-linux-aarch64` |
| macOS Intel | `herdr-macos-x86_64` |
| macOS Apple silicon | `herdr-macos-aarch64` |
| Windows x86_64 | `herdr-windows-x86_64.zip` |

在 Linux 或 macOS 上,赋予可执行权限并移动到 PATH 上的某个位置。

```bash
chmod +x herdr-linux-x86_64
mv herdr-linux-x86_64 ~/.local/bin/herdr
```

### Windows 压缩包

稳定版发布和预览版预发布都会包含 `herdr-windows-x86_64.zip`。压缩包包含 `herdr.exe` 及其应用本地 ConPTY 运行时。请保留完整的解压目录,不要只复制 `herdr.exe`。

## 验证

启动 Herdr:

```bash
herdr
```

如果 shell 找不到 `herdr`,重启终端,或检查安装目录是否在 PATH 上。

## 更新

Herdr 会检查新版本并在应用内通知你。也可以手动更新:

```bash
herdr update
```

`herdr update` 适用于由 Herdr 自带安装器管理的安装。Homebrew、mise 和 Nix 安装请改用那些包管理器更新。

Linux、macOS 和 Windows 的直接安装默认使用稳定更新通道。要启用来自 `master` 的预览构建,设置通道:

```bash
herdr channel set preview
```

用同样的方式把直接安装切回稳定版:

```bash
herdr channel set stable
```

对于直接安装,切换通道时也会检查该通道并安装其最新二进制文件。如果该更新失败,运行 `herdr update` 从配置的通道重试。

预览构建是从当前开发分支定期发布的 GitHub 预发布。当你想在下一个稳定版之前拿到修复时很有用,但它们可能出现回归。Homebrew、mise 和 Nix 安装不使用预览通道。

Windows 的常规使用建议选择稳定版。预览版能更早获得修复,但可能出现回归,因此只有在接受这一取舍时才应主动启用。现有的 Windows 预览安装会继续留在预览通道,直到你明确切换。如果旧预览构建拒绝 `herdr channel set stable`,请先在预览通道运行一次 `herdr update`,再重试切换通道。

默认情况下,`herdr update` 会安装新二进制文件,并让端点第 1 代服务器及其窗格进程继续运行。再次启动 Herdr 即可用更新后的客户端重新连接。纯客户端改动会立即生效。新的服务器端操作会保持不可用,直到对应服务器更新并重启;客户端会显示通知,而不会断开连接。只有早于端点第 1 代的服务器需要在更新时再停止最后一次。

完成后,`herdr update` 会列出仍在运行旧版本的服务器及重启它们的命令,以及运行各自 Herdr 的已保存 SSH 机器。请在每台机器上也运行 `herdr update` 来更新。

要对受支持的运行中会话启用实验性的实时服务器交接,运行:

```bash
herdr update --handoff
```

当两个服务器都支持智能体状态传输时,实时交接会保留钩子上报的智能体状态,直到下一次上报到达。从较旧服务器交接时,运行中的智能体可能暂时显示为 idle。

实时交接不适用于 Homebrew、mise 或 Nix 的包管理器更新。这些安装先用包管理器更新,再重新运行 Herdr,用更新后的客户端连接。兼容的旧服务器会继续运行。只有需要新版本的服务器端改动时,才稍后用 `herdr server stop` 或 `herdr session stop <name>` 重启它。

## 系统要求

Linux、macOS 和 Windows x86_64 都提供稳定通道二进制文件。受支持的工作流和已知限制见 [Windows 支持](/zh-cn/docs/windows-beta/)。Windows ARM64 通过 Windows 模拟运行 x86_64 构建。
