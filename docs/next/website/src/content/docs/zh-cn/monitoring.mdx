---
title: 监控与停靠布局
description: 在终端工作台查看主机资源，拖动面板与标签安排工作空间。
---

从顶栏、主菜单或命令搜索打开「监控」。单一面板承载 系统 / 监控偏好 两个页面，用面板内标签或 `1`/`2` 切换；`r` 刷新、`Space` 暂停历史、`Esc` 关闭，页脚把它们列成可点的提示——刷新与暂停在系统页，关闭各页都有；监控偏好页只有本机偏好，页脚不提示刷新。硬件数据属于当前连接的主机。

## 菜单、页面与稳定选字

`prefix+Space` 打开分类主菜单，`prefix+/` 打开命令搜索（默认 prefix 是 `Ctrl+B`）。分类为「工作区与 Agent」「标签与窗格」「机器与 SSH」「监控」「工具与自动化」「外观与设置」「帮助与通知」；最近使用最多显示五项。搜索可匹配任一界面语言的动作标题、快捷键、分类名和机器地址。鼠标滚轮只滚动列表，方向键把选中项带回可视区域。

全局页面的上边框可以拖动，左右和下边框可以缩放；位置与尺寸保存在客户端偏好中，窗口变小时自动限制在屏幕内。停靠布局锁定时也禁止拖动页面。菜单关闭后恢复原页面的输入和选择；设置页选择后按 Enter 或「应用」按钮生效，主题可预览，Esc 取消预览。

拖选终端文字时，Herdr 固定目标窗格的文字快照，后台进程和其他窗格继续运行。松开后自动复制并恢复实时显示；关闭 `copy_on_select` 时，选区保留到 Ctrl+C 复制或取消。冻结期间的滚动浏览固定历史，不移动实时终端。捕获前画面已经更新且鼠标已松开时，会提示确认固定选区后再按 Ctrl+C，避免复制未看到的新内容。

快照最多保留 65,536 格、2048 行和 8 MiB；历史超出边界时停止滚动。服务端总预算为 64 MiB、32 份，每个客户端同时一份。尺寸变化、切换目标、取消或断线会回收快照；未确认的捕获有 60 秒租约。旧 server 不支持快照 API 时沿用原复制行为。

在 Ghostty GX 中，把 `Ctrl+B` 留给 Herdr，宿主快捷键改用 Herdr 不占用的组合键，例如以 `Ctrl+Shift+Space` 开头的按键序列。普通拖选交给 Herdr，Shift+拖选使用 Ghostty GX 自己的选区。

## 安排工作台

拖动面板标题的 `⠿` 到其他面板的左、右、上、下边缘可以停靠，落点会显示边框。拖动分隔线调整大小。拖动标签可以重排，或拖到内容边缘另建一个终端组；拖动窗格把手可以交换窗格或把窗格移到其他标签页，终端进程不会重启。无边框窗格的把手仅在「调整布局」模式显示，平时不会遮住终端正文。

主终端页跟随聚焦的工作区：在侧栏点击工作区，标签条与终端内容会整体切换到该工作区的标签页（编号每个工作区独立从 1 开始）。拖出为独立面板的标签不受工作区切换影响。

`□` 最大化当前面板；有面板处于最大化时按钮显示为 `◫`，点击即恢复原布局。点顶栏的「调整布局」进入调整布局模式，开启期间按钮反色，页脚显示模式名与键位提示：`Tab` 切换面板（`Shift+Tab` 反向），方向键调整分隔线，`Shift+方向键` 移动面板，`Enter` 最大化，`Esc` 完成（页脚的「Esc 完成」也可以直接点）。面板处于最大化时整套布局键仍然有效：`Tab` 让最大化目标跟随焦点轮转，方向键与 `Shift+方向键` 会先退出最大化，让调整或移动看得见。「锁定布局」是开关，锁定期间带勾选标记，可以防止误拖；「复位」只在调整布局模式显示，恢复默认分栏；布局锁定期间它置灰，点击无效。右键标签仍可使用原有菜单。

布局按客户端和主机保存。终端变小时，只投影当前面板；放大后恢复布局树。旧 server 未声明多视图能力时继续使用原来的单视图界面。

「监控」面板的标题栏在 `□` 旁带 ` × ` 关闭按钮。停靠面板里的页面不再自带外框——面板标题栏与分隔线已经框住它——页签就在面板标题栏下方的第一行，卡片与面板边缘隔一列。面板聚焦时 `Esc` 关闭承载该页面的面板；终端聚焦时 `Esc` 进入终端，请用标题栏按钮或命令搜索中的「关闭监控面板」（仅当监控面板已停靠时出现）。布局锁定时拒绝关闭，并在监控页脚提示「布局已锁定，解锁后才能关闭面板」。最近选中的监控标签（系统 / 监控偏好）保存在客户端偏好中，面板重新聚焦或客户端重启时恢复；从顶栏、主菜单或命令搜索打开「监控」时总是先显示系统页。停靠的监控面板不再抹掉聚焦终端的光标：只有面板或对话框真正覆盖光标位置时才隐藏。滚轮不要求先聚焦面板：指针落在停靠的监控面板内容区任意位置，都滚动面板正在显示的那一页——内容放不下的卡片滚自己，其余位置滚页面——键盘仍归聚焦的面板；指针在其它面板上时滚轮不会滚动这一页。

终端太窄、放不下整排顶栏按钮时，按钮整个隐藏而不是被截成半个：先隐藏「监控」，再隐藏「锁定布局」，然后是「调整布局」（三者都仍可从主菜单与命令搜索打开）；只有顶栏才有的「复位」保留到它们之后。

## 主机监控

可选择 CPU 总量、逐逻辑核、内存与 swap、GPU、磁盘、网络、温度和进程。采样周期为 500、1000、2000 或 5000 毫秒。慢速采集项独立运行。首次差分采样、驱动不可用或权限不足时显示状态或 `—`，而不是零。

NVIDIA 使用 NVML；Linux 的其他显卡读取驱动公开的 DRM/sysfs 指标；Windows 使用 DXGI 和系统 GPU 性能计数器。温度、功耗与利用率能否获取取决于驱动。容器与 WSL 显示该环境可见的资源。无论采样间隔多短，GPU 驱动最多每 2 秒查询一次；Windows 的显卡列表每 60 秒刷新一次。NVML 能报告每一块 Windows 显卡的利用率时，Herdr 显示 NVML 的利用率（来源 `NVML + Windows DXGI`），跳过按进程统计的 GPU 引擎计数器——这是一次采样里最昂贵的部分；只要还有其他显卡，所有 GPU 仍使用性能计数器的利用率。没有客户端请求监控数据时，server 的采样线程会一直休眠到下一个请求。

告警关闭时，监控偏好页不会请求硬件采样。启用告警后，即使对应卡片隐藏，也会补入告警所需的指标组；系统页不可见时，不再请求进程列表等无关指标组。切换端点或收到新的 server 启动标识时，会清空资源和网络历史，并重置告警触发状态；同一来源的普通刷新保留这些状态。

系统页顶部是一条主机摘要——主机名、操作系统、已运行时间、样本时间与采样间隔——资源卡片在其下单列排布，面板宽度达到 96 列起改为双列。CPU 卡是总体 gauge（数字在任意宽度都保留）、型号（点选某个逻辑核后换成该核的说明）和历史迷你图；逐核卡每个逻辑核一条迷你条、铺满整张卡片的宽度，点击逻辑核可以切换其历史曲线。内存卡把已用与缓存画成同一条 gauge 的两段，另有 Swap gauge；GPU 逐设备列出温度、利用率与显存。磁盘是只含真实数据盘的表格：没有容量的伪文件系统不进表，同一设备挂在多处只列一次。网络为每个活动接口画收 / 发堆叠迷你图，空闲接口折成一行说明。温度按芯片汇总：数字与条形取芯片里最热的传感器，其后是芯片的平均温度，面板变窄时平均温度先让位；芯片都放得下、卡片还空着至少两行时，在其下画最热传感器的历史迷你图。同一张卡里的各条形行共用标签列与数字列，条形起止对齐。进程是表头可点击排序的表格，上一行是名称筛选与可见范围；PID 列按快照里最长的 PID 定宽，7 位 PID 也完整显示。卡片内滚轮浏览更多设备、核或进程；内容已经放得下的卡片（如 CPU、内存）上，滚轮改为滚动页面。页面其余位置的滚轮，以及未选中卡片时或所选卡片内容已放得下时的 `↑`/`↓`，每次滚动一行卡片，`PageUp`/`PageDown` 一次一屏；最后一张卡完整露出即停，反向滚动第一格画面就动。在此之前，下一行卡片在页面底边露出上半截：在边缘处裁断，不会被压成一张矮卡。监控偏好页每格滚动三行，同样停在最后一行。历史保存在客户端内存，支持 1–60 分钟范围，总预算为 16 MiB。暂停按钮暂停历史记录，实时采样与告警继续运行。

卡片顺序在「编辑布局」模式里调整，入口是摘要行右端的按钮：每张卡片顶边出现 ↑/↓ 按钮，选中一张卡片后其余转灰，`↑`/`↓` 键移动选中的卡片。「完成」或 `Esc` 退出该模式；再按一次 `Esc` 才关闭面板。卡片高度、隐藏设备与图表字形在「监控偏好」页设置。

进程支持排序、名称筛选、详情和结束操作。详情固定进程实例；结束需要再次确认，强制结束单独选择。过期确认、PID 重用和受保护进程会被拒绝。Windows 使用强制结束，需要相应权限。

告警默认关闭。可设置阈值、持续时间和冷却时间；只在 TUI 客户端连接期间生效，不会结束进程。监控偏好页的告警行与告警通知用指标名（CPU / 内存 / GPU / 磁盘）称呼规则，不显示配置里的 id。

「监控偏好」页把控件分进卡片：采样间隔（500 / 1000 / 2000 / 5000 ms）、卡片高度（7 / 10 / 16 / 24 行）、历史范围（1 / 5 / 15 / 30 / 60 分钟）以及每条告警规则的阈值（50–100%，每步 5）、持续与冷却用步进器；告警、显示项与已采样的设备用开关；图表字形用分段控件。步进器在固定档位表里取相邻档，两端回绕，配置文件里落在档位之间的值第一次点击先落到相邻档而不跳档。「图表字形」决定系统页迷你图与条形的字符集——盲文（默认）、方块，或给缺少这些字形的终端准备的 ASCII——保存为客户端偏好 `monitor_chart_glyphs`。

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true # 默认 false

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

`visible` 可以取 `cpu`、`cores`、`memory`、`gpu`、`disks`、`network`、`sensors` 与 `processes`（默认八项全开），告警的 `metric` 取 `cpu`、`memory`、`gpu` 或 `disk`。写了 `[[monitor.alerts]]` 就会替换内置规则（CPU、内存、磁盘 90 %，GPU 95 %，均为持续 30 s、冷却 60 s）。在「监控偏好」页修改采样间隔、卡片高度、历史范围、显示项、采样设备或告警设置，或在「编辑布局」里移动卡片，都会把整份监控配置保存为客户端偏好 `monitor`，此后它优先于配置文件里的 `[monitor]`。

客户端偏好逐字段读取：某个值无法解析（例如未知的 `monitor_chart_glyphs`）时只丢弃该字段并给出一次诊断，其余保留。

## API

公开 JSON 方法包括 `system.metrics.get/subscribe/unsubscribe` 和 `system.process.list/get/terminate`。慢速订阅者只保留最新样本；`system.metrics.updated` 推送的说明见 [事件订阅](/zh-cn/docs/socket-api/#事件订阅)。

多视图的 `client.views.set` 及具名帧/输入扩展仅用于协商后的 TUI 连接，不修改 generation 1 的消息编码。工作台移动窗格复用既有 `pane.move` 与 `pane.swap`。完整参数以 `herdr api schema --json` 为准。
