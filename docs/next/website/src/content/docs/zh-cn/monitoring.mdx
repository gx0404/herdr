title: 监控、账号用量与停靠布局
description: 在终端工作台查看主机资源和官方账号用量，拖动面板与标签安排工作空间。
---

从顶栏、全局菜单或命令搜索打开「监控」。单一面板承载 系统 / 账号 / 设置 三个页面，用面板内标签或 `1`/`2`/`3` 切换；`r` 刷新、`Space` 暂停历史、`Esc` 关闭。硬件数据属于当前连接的主机；悬浮远程 Agent 时，用量查询在该 Agent 所在的主机执行。

## 菜单、页面与稳定选字

`prefix+Space` 打开分类主菜单，`prefix+/` 打开独立命令搜索（默认 prefix 是 `Ctrl+B`）。菜单按工作区、标签窗格、SSH、监控、工具、设置和帮助分组；最近使用最多显示五项。搜索支持中文、英文动作名称、分类及机器地址。鼠标滚轮只滚动列表，方向键把选中项带回可视区域。

全局页面的上边框可以拖动，左右和下边框可以缩放；位置与尺寸保存在客户端偏好中，窗口变小时自动限制在屏幕内。停靠布局锁定时也禁止拖动页面。菜单关闭后恢复原页面的输入和选择；设置页选择后按 Enter 或保存按钮生效，主题可预览，Esc 取消预览。

主终端页跟随聚焦的工作区：在侧栏点击工作区，标签条与终端内容会整体切换到该工作区的标签页（编号每个工作区独立从 1 开始）。拖出为独立面板的标签不受工作区切换影响。

拖选终端文字时，Herdr 固定目标窗格的文字快照，后台进程和其他窗格继续运行。松开后自动复制并恢复实时显示；关闭 `copy_on_select` 时，选区保留到 Ctrl+C 复制或取消。冻结期间的滚动浏览固定历史，不移动实时终端。捕获前画面已经更新且鼠标已松开时，会提示确认固定选区后再按 Ctrl+C，避免复制未看到的新内容。

快照最多保留 65,536 格、2048 行和 8 MiB；历史超出边界时停止滚动。服务端总预算为 64 MiB、32 份，每个客户端同时一份。尺寸变化、切换目标、关闭页面或断线会回收快照；未确认的捕获有 60 秒租约。旧 server 不支持快照 API 时沿用原复制行为。

WezTerm 建议使用 `Ctrl+Shift+Space` 作为宿主前缀，保留 `Ctrl+B` 给 Herdr。普通拖选交给 Herdr，Shift+拖选使用 WezTerm 选区；终端主题不影响这两个入口。

## 安排工作台

拖动面板标题的 `⠿` 到其他面板的左、右、上、下边缘可以停靠，落点会显示边框。拖动分隔线调整大小。终端组可以同时展示多个标签；拖动标签到组内可以重排，拖到内容边缘可以拆为新组。窗格标题上的把手支持组内交换、跨标签移动，终端进程继续运行。无边框窗格的把手仅在「布局」模式显示，平时不会遮住终端正文。

`□` 最大化当前面板，再次点击恢复。布局模式中，`Tab` / `Shift+Tab` 切换面板，方向键调整分隔线，`Shift+方向键` 移动面板，`Enter` 最大化，`Esc` 完成。面板处于最大化时整套布局键仍然有效：`Tab` 让最大化目标跟随焦点轮转，方向键与 `Shift+方向键` 会先退出最大化，让调整或移动看得见。锁定布局可以防止误拖；「复位」恢复默认分栏。右键标签仍可使用原有菜单。

布局按客户端和主机保存。终端变小时，只投影当前面板；放大后恢复布局树。旧 server 未声明多视图能力时继续使用原来的单视图界面。

「监控」与「账号」面板的标题栏在 `□` 旁带 ` × ` 关闭按钮。面板聚焦时 `Esc` 关闭承载该页面的面板；终端聚焦时 `Esc` 进入终端，请用标题栏按钮或命令搜索中的「关闭监控面板」（仅当监控面板已停靠时出现）。布局锁定时拒绝关闭，并在监控页脚提示「布局已锁定，解锁后才能关闭面板」。最近选中的监控标签（系统 / 账号 / 设置）保存在客户端偏好中，面板重新聚焦或重新打开时恢复。停靠的监控或账号面板不再抹掉聚焦终端的光标：只有面板、悬浮用量总览或对话框真正覆盖光标位置时才隐藏。

## 主机监控

可选择 CPU 总量、逐逻辑核、内存与 swap、GPU、磁盘、网络、温度和进程。采样周期为 500、1000、2000 或 5000 毫秒。首次差分采样、缺少驱动、权限不足或设备不提供某个字段时显示状态或 `—`，不会显示虚假的零值。

NVIDIA 使用 NVML；Linux 的其他显卡读取驱动公开的 DRM/sysfs 指标；Windows 使用 DXGI 和系统 GPU 性能计数器。不同驱动提供的温度、功耗、共享显存和利用率不同。WSL、容器和远程连接显示当前环境可见的资源。

卡片内滚轮浏览所有 CPU 核、设备或进程；点击逻辑核可以切换其历史曲线。卡片标题的箭头调整顺序，设置中可以调整卡片高度和隐藏设备。历史保存在客户端内存，支持 1–60 分钟范围，总预算为 16 MiB。暂停按钮暂停历史记录，实时采样与告警继续运行。

进程支持排序、名称筛选、详情和结束操作。详情固定进程实例；结束需要再次确认，强制结束单独选择。过期确认、PID 重用和受保护进程会被拒绝。Windows 使用强制结束，需要相应权限。

告警默认关闭。可设置阈值、持续时间和冷却时间；只有客户端连接期间生效，不会自动结束进程。

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

## 账号绑定与展示

账号页只列出本机已安装官方 CLI 的厂商——检测与设置页的集成检测同源（多别名 PATH 扫描 + codex 的 standalone/nvm/volta/bun、Hermes 等安装布局），两处结论一致；显式配置了账号的厂商始终保留。`account.usage.providers` 为每个厂商返回 `installed` 标记；旧版 server 缺少该字段时仍显示完整注册表。自动刷新由服务端在有客户端展示数据期间执行：API 与门户账号按 `api_refresh_seconds`（不低于 60 s），CLI 探测按 `cli_refresh_seconds`（不低于 300 s；`account.usage.providers` 以 `minimum_interval_seconds` 播报实际生效值），失败后带上限的退避。只接受官方回调的厂商不播报轮询间隔，由回调驱动刷新。账号页打开时若尚未选厂商，按聚焦窗格正在运行的 agent 选，否则选第一个已列出的厂商。切换厂商或账号时旧快照保留并变暗，直到新数据到达；当前作用域配置的账号不足两个时「切换账号」为禁用态；在设置里关闭的厂商会同时离开厂商标签、切换候选和总览。codex 通过安装布局定位时，探测子进程会把该布局的 bin 目录前置到 `PATH`，使 npm shim 脚本能解析到自身的 node 解释器。

扫过 Agents 面板头部的「用量」按钮（停留满 `hover_delay_ms`，默认 400 ms）会在按钮下方弹出紧凑的跨厂商总览：每个账号一行头部加最多三行带进度条的额度，下方放不下时上翻到按钮上方。指针移开 250 ms 后自动关闭；点击按钮即钉住，之后只有 `Esc`、再次点击按钮或在浮层外点击才会关闭。点击浮层本体打开账号页。总览有自己的作用域，不会改写账号页的选择；钉住的总览只在按钮因面板过窄而消失时才自行关闭。面板很窄时按钮先缩成 1 列的 `%`，再截断排序标签；按钮需要开启鼠标捕获。

`prefix+a`（或命令搜索）可打开浮动用量仪表盘：以可拖动、可缩放的窗口展示跨账号总览，并遵循 `format`。它是非模态的：其余界面不压暗，除 `Esc` 外的按键照常落到聚焦终端，浮层内点击选中账号行或按其按钮，滚轮滚动，浮层外点击关闭；打开期间自动刷新。

客户端偏好逐字段读取：某个值无法解析（例如未知的 `usage_format`）时只丢弃该字段并给出一次诊断，其余保留。偏好键 `usage_hover_dashboard`（默认 `true`）关闭后扫过按钮不再弹总览，点击仍可钉住；与其它 `usage_*` 键一样，只有显式设置过才会回写。

鼠标停留在 Agent 行或 CLI 标题上，可以打开账号用量浮层。`format` 决定仪表盘还是表格；`position` 决定这个按窗格的浮层放在哪里：`hover` 与 `both` 都保留 Agent 行和 CLI 标题上的浮层，`page` 则关闭该浮层，只留账号页作为按窗格的入口（选中它时设置页会常驻提示）。账号页、用量按钮的总览和浮动仪表盘在任一取值下都可用。在 监控→设置 里做的修改保存为客户端偏好，在本机覆盖 `enabled`、`format`、`position`、`hover_delay_ms` 与关闭的厂商，直到在那里点「恢复配置文件值」。浮层中的「确认账号绑定」将当前窗格与选定账号关联。品牌相同不代表账号相同：未绑定窗格收到官方回调时，若该厂商只配置了一个账号，服务端会自动绑定并持久化，快照标注「已按唯一账号自动绑定」；配置了多个账号时回调被拒绝并列出候选，需要显式绑定。自动绑定要求 `account_usage.enabled` 开启且回调含额度字段。

显式刷新（`account.usage.refresh`、账号页的刷新动作、切换厂商或账号）按账号做 10 s 防抖，且不豁免厂商退避（HTTP 429）；被防抖时响应带 `next_allowed_at_ms`。终态结果（需要登录、不支持、无权限）按慢周期自动重试——10 分钟起、每次翻倍、1 小时封顶、最多 6 次；CLI 可执行文件或凭据文件一有变化就解除保持，登录后无需重启即可自愈；显式刷新始终重试终态。没有额度字段的官方回调不会覆盖缓存样本。超过 15 分钟没有回调时快照显示为缓存数据，可能回落探测，但只有探测成功或下一次回调才会替换它。只接受官方回调的厂商在刷新状态里标 `callback_only`：显式刷新对它们产生不了新的额度样本，但仍可能刷新登录或绑定占位。

账号页或浮动仪表盘可见期间，客户端会在宣告了 `account.usage.subscribe` 的 server 上订阅，收到 `account.usage.updated` / `account.usage.refreshing` 推送即时更新，只保留 30 s 的兜底轮询；页面隐藏即退订，断线重连后重新订阅，旧版 server 回退到轮询（2 s，探测在途时 500 ms）。正在探测的账号在自己一行显示「刷新中…」；「刷新」按钮在选中账号（未选中时为所有已列出账号）仍被防抖期间显示「N 秒后可刷新」，超过一分钟的厂商退避改在账号行说明而不锁按钮。账号页还有一行绑定入口：只列出运行所选厂商 agent 的 pane 选择器、「绑定到聚焦 pane」，以及服务端拒绝未绑定窗格的回调后给出的 `pending_binding` 一键候选。所有绑定入口都会拒绝运行其它厂商 agent 的 pane；启用官方回调后顺手绑定的是应答那台主机上的 pane，不会发往其间切换到的其它主机。

Claude Code 以回调为主路径：额度来自官方 statusline 回调，探测只用非交互的 `claude auth status --json` 检查登录态（只读地复用真实登录存储）。已登录但未接入回调的账号显示「等待官方 statusline 回调」并指向启用它的设置；在第一次回调到达前，这个预检按与终态相同的慢周期退避。交互式 `/usage` 探测需要显式开启（`interactive_probe = true`），且只在显式刷新时运行，工作目录固定在 herdr 状态目录下的稳定探测目录：Claude Code 会要求你在自己的 CLI 里对该目录确认一次信任——刷新状态里标 `trust_required`，message 给出目录路径——Herdr 不会代为应答。交互探测复用真实登录态，并发启动可能触发凭据轮换；除非确实需要在没有回调的情况下取 `/usage`，否则保持关闭。

仪表盘和表格都支持滚轮浏览；在账号页也可使用上下键翻看超出视口的额度窗口。悬浮层可与监控面板同时显示，操作浮层不会触发下面的卡片或进程行。

查询结果保留套餐窗口、重置时间、余额单位、采样时间和数据来源。套餐额度、API 密钥预算、组织账单和本机会话 token 各自标注范围。暂时网络失败保留旧样本并显示缓存状态，遵守最短刷新周期和服务端重试间隔。

账号配置属于运行 Agent 的 server。只填写凭据环境变量名称；令牌不会保存到 Herdr 配置、偏好或远程客户端。CLI 登录由官方工具管理。

```toml
[account_usage]
enabled = true
format = "dashboard" # dashboard / table
position = "hover" # hover / page / both；page 关闭 Agent 行浮层
hover_delay_ms = 400
api_refresh_seconds = 60
cli_refresh_seconds = 300
probe_timeout_seconds = 20
interactive_probe = false # 仅显式刷新；Claude 需在 CLI 中信任一次探测目录
disabled_providers = []

[[account_usage.accounts]]
id = "work-codex"
label = "工作账号"
agent = "codex"
provider = "codex"
auth_mode = "cli"
profile_dir = "/path/to/codex-profile"

[[account_usage.accounts]]
id = "team-api"
label = "组织 API"
agent = "claude"
provider = "anthropic"
auth_mode = "api"
credential_env = "ANTHROPIC_ADMIN_KEY"
```

`organization`、`account_user` 按对应官方接口设置组织、团队、用户 ID 或明确要求的邮箱。GitHub Enterprise 使用 `billing_scope = "enterprise"` 并把 enterprise slug 填入 `organization`；OpenRouter 的 `billing_scope = "account"` 使用管理密钥查询账号总额，默认仅查询当前 API key。OMP 多账号查询必须指定实际 provider 和账号身份。`base_url` 只接受已登记的官方地址；Kimi 本地 API 只允许 loopback。

Kimi 2.x 的 `quota.usages` 窗口与旧版字段都支持解析；OpenCode 需要 `stats` 支持 JSON 输出的 CLI 版本，旧版本会显示明确的升级提示。

## 官方回调

Claude 与 Antigravity 的账号页可启用或移除官方状态栏回调。已有状态栏命令通过管道保留；输入报文原样交给原渲染器，Herdr 只抽取用量字段。Claude 的 `rate_limits` 需要支持该字段的 CLI 版本，并且通常在首次正常 API 响应后出现；Herdr 不会为取额度发送模型任务。

其他官方集成可以将受支持的 JSON 通过 `herdr api usage-report --agent <agent>` 写入 stdin。默认使用 `HERDR_PANE_ID` 对应的绑定，也可明确指定 `--account <id>`。未绑定的窗格仅在该厂商只有一个账号时自动绑定，否则先绑定账号；原始 JSON 和会话内容不会写入持久化文件。`--passthrough` 用于已有状态栏管道。

## API

公开 JSON 方法包括 `system.metrics.get/subscribe/unsubscribe`、`system.process.list/get/terminate`、`account.usage.providers/get/refresh/subscribe/unsubscribe/report/integration` 和 `account.binding.set`。订阅事件有独立采样时间，慢消费者只保留最新样本。

`account.usage.get` / `account.usage.refresh` 的响应与 `account.usage.updated` 事件在快照旁带一份 `refresh` 列表（`UsageRefreshState`，按 `account_id` 与 `accounts` 对齐；旧版 server 省略）：探测进度（`in_flight`、`queued`）、显式刷新防抖（`requested_at_ms`、`next_allowed_at_ms`）、厂商退避（`retry_after_ms`）、`binding_inferred`、`trust_required`、`callback_only`、`pending_binding` 与 `callback_enabled`。`account.usage.refreshing` 在探测派发时只推送这份列表。字段含义与事件信封见 [事件订阅](/zh-cn/docs/socket-api/#事件订阅)。

多视图的 `client.views.set` 及具名帧/输入扩展仅用于协商后的 TUI 连接，不修改 generation 1 的消息编码。工作台移动窗格复用既有 `pane.move` 与 `pane.swap`。完整参数以 `herdr api schema --json` 为准。
