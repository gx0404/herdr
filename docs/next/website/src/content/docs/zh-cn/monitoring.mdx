从顶栏、全局菜单或命令搜索打开「监控」。单一面板承载 系统 / 账号 / 监控偏好 三个页面，用面板内标签或 `1`/`2`/`3` 切换；`r` 刷新、`Space` 暂停历史、`Esc` 关闭，页脚把刷新 / 暂停 / 关闭列成可点的提示。硬件数据属于当前连接的主机；悬浮远程 Agent 时，用量查询在该 Agent 所在的主机执行。

## 菜单、页面与稳定选字

`prefix+Space` 打开分类主菜单，`prefix+/` 打开独立命令搜索（默认 prefix 是 `Ctrl+B`）。菜单按工作区、标签窗格、SSH、监控、工具、设置和帮助分组；最近使用最多显示五项。搜索支持中文、英文动作名称、分类及机器地址。鼠标滚轮只滚动列表，方向键把选中项带回可视区域。

全局页面的上边框可以拖动，左右和下边框可以缩放；位置与尺寸保存在客户端偏好中，窗口变小时自动限制在屏幕内。停靠布局锁定时也禁止拖动页面。菜单关闭后恢复原页面的输入和选择；设置页选择后按 Enter 或保存按钮生效，主题可预览，Esc 取消预览。

主终端页跟随聚焦的工作区：在侧栏点击工作区，标签条与终端内容会整体切换到该工作区的标签页（编号每个工作区独立从 1 开始）。拖出为独立面板的标签不受工作区切换影响。

拖选终端文字时，Herdr 固定目标窗格的文字快照，后台进程和其他窗格继续运行。松开后自动复制并恢复实时显示；关闭 `copy_on_select` 时，选区保留到 Ctrl+C 复制或取消。冻结期间的滚动浏览固定历史，不移动实时终端。捕获前画面已经更新且鼠标已松开时，会提示确认固定选区后再按 Ctrl+C，避免复制未看到的新内容。

快照最多保留 65,536 格、2048 行和 8 MiB；历史超出边界时停止滚动。服务端总预算为 64 MiB、32 份，每个客户端同时一份。尺寸变化、切换目标、关闭页面或断线会回收快照；未确认的捕获有 60 秒租约。旧 server 不支持快照 API 时沿用原复制行为。

WezTerm 建议使用 `Ctrl+Shift+Space` 作为宿主前缀，保留 `Ctrl+B` 给 Herdr。普通拖选交给 Herdr，Shift+拖选使用 WezTerm 选区；终端主题不影响这两个入口。

## 安排工作台

拖动面板标题的 `⠿` 到其他面板的左、右、上、下边缘可以停靠，落点会显示边框。拖动分隔线调整大小。终端组可以同时展示多个标签；拖动标签到组内可以重排，拖到内容边缘可以拆为新组。窗格标题上的把手支持组内交换、跨标签移动，终端进程继续运行。无边框窗格的把手仅在「调整布局」模式显示，平时不会遮住终端正文。

`□` 最大化当前面板，再次点击恢复。点顶栏的「调整布局」进入调整布局模式，开启期间按钮反色，页脚显示模式名与键位提示：`Tab` / `Shift+Tab` 切换面板，方向键调整分隔线，`Shift+方向键` 移动面板，`Enter` 最大化，`Esc` 完成（页脚的「Esc 完成」也可以直接点）。面板处于最大化时整套布局键仍然有效：`Tab` 让最大化目标跟随焦点轮转，方向键与 `Shift+方向键` 会先退出最大化，让调整或移动看得见。「锁定布局」是开关，锁定期间带勾选标记，可以防止误拖；「复位」只在调整布局模式显示，恢复默认分栏。右键标签仍可使用原有菜单。

布局按客户端和主机保存。终端变小时，只投影当前面板；放大后恢复布局树。旧 server 未声明多视图能力时继续使用原来的单视图界面。

「监控」与「账号」面板的标题栏在 `□` 旁带 ` × ` 关闭按钮。停靠面板里的页面不再自带外框——面板标题栏与分隔线已经框住它——页签就在面板正文第一行，卡片与面板边缘隔一列。面板聚焦时 `Esc` 关闭承载该页面的面板；终端聚焦时 `Esc` 进入终端，请用标题栏按钮或命令搜索中的「关闭监控面板」（仅当监控面板已停靠时出现）。布局锁定时拒绝关闭，并在监控页脚提示「布局已锁定，解锁后才能关闭面板」。最近选中的监控标签（系统 / 账号 / 监控偏好）保存在客户端偏好中，面板重新聚焦或重新打开时恢复。停靠的监控或账号面板不再抹掉聚焦终端的光标：只有面板、用量浮层或对话框真正覆盖光标位置时才隐藏。

终端太窄、放不下整排顶栏按钮时，按钮整个隐藏而不是被截成半个：先隐藏「监控」，再隐藏「锁定布局」「调整布局」（三者都仍可从主菜单与命令搜索打开）；只有顶栏才有的「复位」保留到它们之后。

## 主机监控

可选择 CPU 总量、逐逻辑核、内存与 swap、GPU、磁盘、网络、温度和进程。采样周期为 500、1000、2000 或 5000 毫秒。首次差分采样、缺少驱动、权限不足或设备不提供某个字段时显示状态或 `—`，不会显示虚假的零值。

NVIDIA 使用 NVML；Linux 的其他显卡读取驱动公开的 DRM/sysfs 指标；Windows 使用 DXGI 和系统 GPU 性能计数器。不同驱动提供的温度、功耗、共享显存和利用率不同。WSL、容器和远程连接显示当前环境可见的资源。

系统页顶部是一条主机摘要——主机名、操作系统、已运行时间、样本时间与采样间隔——资源卡片在其下单列排布，面板宽度达到 96 列起改为双列。CPU 卡是总体 gauge（数字在任意宽度都保留）、型号与选中核说明和历史迷你图；逐核卡每个逻辑核一条迷你条、铺满整张卡片的宽度，点击逻辑核可以切换其历史曲线。内存卡把已用与缓存画成同一条 gauge 的两段，另有 Swap gauge；GPU 逐设备列出温度、利用率与显存。磁盘是只含真实数据盘的表格：没有容量的伪文件系统不进表，同一设备挂在多处只列一次。网络为每个活动接口画收 / 发堆叠迷你图，空闲接口折成一行说明。温度按芯片汇总：数字与条形取芯片里最热的传感器，其后是芯片的平均温度，面板变窄时平均温度先让位；芯片都放得下、卡片还空着至少两行时，在其下画最热传感器的历史迷你图。同一张卡里的各条形行共用标签列与数字列，条形起止对齐。进程是表头可点击排序的表格，上一行是名称筛选与可见范围；PID 列按快照里最长的 PID 定宽，7 位 PID 也完整显示。卡片内滚轮浏览更多设备、核或进程；内容已经放得下的卡片（如 CPU、内存）上，滚轮改为滚动页面。页面其余位置的滚轮，以及未选中卡片时的 `↑`/`↓`，每次滚动一行卡片，`PageUp`/`PageDown` 一次一屏；最后一张卡完整露出即停，反向滚动第一格画面就动。监控偏好页每格滚动三行，同样停在最后一行。历史保存在客户端内存，支持 1–60 分钟范围，总预算为 16 MiB。暂停按钮暂停历史记录，实时采样与告警继续运行。

卡片顺序在「编辑布局」模式里调整，入口是摘要行右端的按钮：每张卡片顶边出现 ↑/↓ 按钮，选中一张卡片后其余转灰，`↑`/`↓` 键移动选中的卡片。「完成」或 `Esc` 退出该模式；再按一次 `Esc` 才关闭面板。卡片高度、隐藏设备与图表字形在「监控偏好」页设置。

进程支持排序、名称筛选、详情和结束操作。详情固定进程实例；结束需要再次确认，强制结束单独选择。过期确认、PID 重用和受保护进程会被拒绝。Windows 使用强制结束，需要相应权限。

告警默认关闭。可设置阈值、持续时间和冷却时间；只有客户端连接期间生效，不会自动结束进程。

「监控偏好」页把控件分进卡片：采样间隔（500 / 1000 / 2000 / 5000 ms）、卡片高度（7 / 10 / 16 / 24 行）、历史范围（1 / 5 / 15 / 30 / 60 分钟）、悬浮延时以及每条告警规则的阈值（50–100%，每步 5）、持续与冷却用步进器；告警、厂商账号用量、显示项、已列出的厂商与已采样的设备用开关；用量样式、用量位置与图表字形用分段控件。步进器在固定档位表里取相邻档，两端回绕，配置文件里落在档位之间的值第一次点击先落到相邻档而不跳档。「图表字形」决定系统页迷你图与条形的字符集——盲文（默认）、方块，或给缺少这些字形的终端准备的 ASCII——保存为客户端偏好 `monitor_chart_glyphs`。

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

## 账号绑定与展示

账号页只列出本机已安装官方 CLI 的厂商——检测与设置页的集成检测同源（多别名 PATH 扫描 + codex 的 standalone/nvm/volta/bun 等安装布局），两处结论一致；ZCode 没有 CLI 可找，连接的主机上存在它的本地数据库 `~/.zcode/cli/db/db.sqlite` 时才列出；显式配置了账号的厂商始终保留。`account.usage.providers` 为每个厂商返回 `installed` 标记；旧版 server 缺少该字段时仍显示完整注册表。自动刷新由服务端在有客户端展示数据期间执行：API 账号按 `api_refresh_seconds`（不低于 60 s），CLI 探测按 `cli_refresh_seconds`（不低于 300 s；`account.usage.providers` 以 `minimum_interval_seconds` 播报实际生效值；ZCode 的本地数据库读取也按这个周期），失败后带上限的退避。由官方回调（Claude Code）或 Herdr 自带集成扩展（Pi）推送数据的厂商不播报轮询间隔，由这些推送驱动刷新。账号页打开时若尚未选厂商，按聚焦窗格正在运行的 agent 选，否则选第一个已列出的厂商。切换厂商或账号时旧快照保留并变暗，直到新数据到达；当前作用域配置的账号不足两个时「切换账号」为禁用态；在设置里关闭的厂商会同时离开厂商标签、切换候选和总览。codex 通过安装布局定位时，探测子进程会把该布局的 bin 目录前置到 `PATH`，使 npm shim 脚本能解析到自身的 node 解释器。

Agent 行或 CLI 标题上的账号用量浮层在停留满 `hover_delay_ms`（默认 400 ms）后出现，指针离开该行与浮层 250 ms 后自动关闭。它有自己的作用域，不会改写账号页的选择；浮层里的「打开页面」按钮打开账号页。跨厂商总览在账号页里：首个标签「全部厂商」一次列出所有已列出的厂商。总览没有账号可显示时会说明原因，而不是让你「选择厂商」：此主机没有厂商 CLI 也没有配置账号、已列出的厂商全部在「监控偏好」里关闭，或仍在查询。

同一张卡也可以主动打开：在 agent 行上右键，选「用量」。卡片立即出现并保持钉住——标题为「<agent> · 用量」，顶边右端带「已钉住」标记——指针移开或扫过别的 agent 行都不会关闭或替换它；按 Esc 或点击卡片外任意处关闭。该入口在任何 `position` 下都可用（包括 `page`）；经典布局下监控页面打开时，钉住的卡也画在页面之上。在监控偏好里关闭了账号用量时，卡片会照实说明而不是一直加载。从 agent 行打开的卡（悬停或钉住）摆在 Agents 面板旁边——右侧，面板停靠在最右边时改到左侧——从行的下一行开始向下展开，下方放不下就在行的上一行结束，因此不会盖住相邻的 agent 行；面板两侧都腾不出 40 列时，改为出现在行的正下方或正上方。从 CLI 标题打开的卡出现在标题行正下方、与标题左对齐（离右缘太近时向左平移），下方放不下就翻到标题上方。上下都不够高时取空间较大的一侧并收缩高度，矮于 5 行的卡不显示；卡片永远不会盖住自己的行或标题。

客户端偏好逐字段读取：某个值无法解析（例如未知的 `usage_format` 或 `monitor_chart_glyphs`）时只丢弃该字段并给出一次诊断，其余保留。`usage_*` 键只有显式设置过才会回写。

鼠标停留在 Agent 行或 CLI 标题上，可以打开账号用量浮层。`format` 决定仪表盘还是表格；`position` 决定这个按窗格的浮层放在哪里：`hover` 与 `both` 都保留 Agent 行和 CLI 标题上的浮层，`page` 则关闭指针悬停浮层，按窗格的入口只剩账号页与右键「用量」打开的卡片（选中它时监控偏好页会常驻提示）。账号页在任一取值下都可用。在 监控→监控偏好 里做的修改保存为客户端偏好，在本机覆盖 `enabled`、`format`、`position`、`hover_delay_ms` 与关闭的厂商，直到在那里点「恢复配置文件值」。浮层中的「确认账号绑定」将当前窗格与选定账号关联。品牌相同不代表账号相同：未绑定窗格收到官方回调时，若该厂商只配置了一个账号，服务端会自动绑定并持久化，快照标注「已按唯一账号自动绑定」；配置了多个账号时回调被拒绝并列出候选，需要显式绑定。自动绑定要求 `account_usage.enabled` 开启且回调含额度字段。

面板够宽（≥96 列）时，右侧详情栏还会画出所选账号「最紧的那一档」额度随时间的变化：客户端保留最近 120 个采样（轮询响应与订阅推送都算），以「用量历史」标题下的 sparkline 呈现。
显式刷新（`account.usage.refresh`、账号页的刷新动作、切换厂商或账号）按账号做 10 s 防抖，且不豁免厂商退避（HTTP 429）；被防抖时响应带 `next_allowed_at_ms`。终态结果（需要登录、不支持、无权限）按慢周期自动重试——10 分钟起、每次翻倍、1 小时封顶、最多 6 次；CLI 可执行文件或凭据文件一有变化就解除保持，登录后无需重启即可自愈；显式刷新始终重试终态。没有额度字段的官方回调不会覆盖缓存样本。超过 15 分钟没有回调时快照显示为缓存数据，可能回落探测，但只有探测成功或下一次回调才会替换它。靠推送取数的厂商（Claude Code 的官方回调、Pi 的扩展推送）在刷新状态里标 `callback_only`：显式刷新对它们产生不了新的样本，但仍可能刷新登录或绑定占位。

账号页可见期间，客户端会在宣告了 `account.usage.subscribe` 的 server 上订阅，收到 `account.usage.updated` / `account.usage.refreshing` 推送即时更新，只保留 30 s 的兜底轮询；页面隐藏即退订，断线重连后重新订阅，旧版 server 回退到轮询（2 s，探测在途时 500 ms）。正在探测的账号在自己一行显示「刷新中…」；「刷新」按钮在选中账号（未选中时为所有已列出账号）仍被防抖期间显示「N 秒后可刷新」，超过一分钟的厂商退避改在账号行说明而不锁按钮。账号页还有一行绑定入口：只列出运行所选厂商 agent 的 pane 选择器、「绑定到聚焦 pane」，以及服务端拒绝未绑定窗格的回调后给出的 `pending_binding` 一键候选。所有绑定入口都会拒绝运行其它厂商 agent 的 pane；启用官方回调后顺手绑定的是应答那台主机上的 pane，不会发往其间切换到的其它主机。

Claude Code 以回调为主路径：额度来自官方 statusline 回调，探测只用非交互的 `claude auth status --json` 检查登录态（只读地复用真实登录存储）。已登录但未接入回调的账号显示「等待官方 statusline 回调」并指向启用它的设置；在第一次回调到达前，这个预检按与终态相同的慢周期退避。交互式 `/usage` 探测需要显式开启（`interactive_probe = true`），且只在显式刷新时运行，工作目录固定在 herdr 状态目录下的稳定探测目录：Claude Code 会要求你在自己的 CLI 里对该目录确认一次信任——刷新状态里标 `trust_required`，message 给出目录路径——Herdr 不会代为应答。交互探测复用真实登录态，并发启动可能触发凭据轮换；除非确实需要在没有回调的情况下取 `/usage`，否则保持关闭。

除 `rate_limits` 里的账号额度窗口（`five_hour`、`seven_day`，以及 Claude apps gateway 下的 `spend_limit`）外，回调还带上报会话的估算费用、会话时长与 API 等待时长（`cost.*`）和上下文窗口（`context_window.*`）。它们按会话统计列出，从不算作账号额度；多个会话共用一个账号时，反映的是最近一次上报的那个会话。三处细节遵循官方 statusline 契约：某个窗口过了 `resets_at` 后 Claude Code 会把它从 JSON 里去掉（会话首个 API 响应之前则整段不带 `rate_limits`），所以缺席的窗口沿用上次的值而不是归零，且在重置时间已过后标明「已过重置时间」（沿用最多到重置时间之后一周；不带 `resets_at` 的窗口最多到它最后一次出现之后一周）；`context_window.current_usage` 与 `used_percentage` 在首次 API 调用之前、以及 `/compact` 之后为 `null`，显示为「暂无数据」而不是 0；`spend_limit` 可以超过 100%，按上报值保留。完全不带 `rate_limits`（旧版 CLI 或 API key 登录）且没有可沿用窗口的回调不会接管该账号。

仪表盘格式下每个账号一张卡片，按厂商排布：卡片上边框写账号标签与状态，卡内首行是采样时间、套餐与身份（徽标是统计声明时，状态也写在这一行）。Claude Code 用 gauge 画 5 小时、每周与消费额度三个窗口，再列出本会话的上下文占用与费用：消费额度超过 100% 时按上报值显示，条形末端画溢出标记 `▸`；已过重置时间的窗口沿用上次的值、文字转灰、条形变暗，并标明「已过重置」。Codex 为每个限额桶画主 / 次窗口（按窗口长度命名，例如「5h 窗口」）与该桶的额外余额，多个桶各占一个小节。Kimi Code 画 5 小时、7 天与月度窗口，按币种显示的余额，以及额外用量钱包。OpenCode 与 ZCode 的卡片带「本地统计，非账号额度」徽标，会话数、费用、token 与工具调用等只画数值、不画 gauge；Pi 的卡片带「会话统计」徽标：上下文 gauge、本会话费用与模型、token 明细，第一次推送到达前显示空态。只有所连主机报告了 ZCode 账号时才出现 ZCode 卡片。卡片不认识的指标照样逐条列出，未知厂商用通用卡片。gauge 按阈值着色，并画一格刻度标出窗口已过去多少（5 小时、每周与 7 天窗口按固定长度计算，其它窗口在厂商报告了长度时才画），用量跑在时间前面时提前转黄 / 红；面板变窄时先缩短、再去掉条形，数字始终保留。选「全部厂商」且列出了不止一个厂商时，页面改为每厂商一张紧凑卡——最紧张的一个额度窗口（本地 / 会话统计则是关键数值）加一行状态——≥96 列时双栏；点击紧凑卡或在它上面按 Enter 进入该厂商。Agent 行悬浮层里的卡片不会高过悬浮层：放不下的行在下边框记为「+N」，「打开页面」可以看完整卡片。

仪表盘和表格都支持滚轮浏览；在账号页也可使用上下键翻看超出视口的额度窗口。悬浮层可与监控面板同时显示，操作浮层不会触发下面的卡片或进程行。

查询结果保留套餐窗口、重置时间、余额单位、采样时间和数据来源。套餐额度、API 密钥预算、组织账单和本机会话 token 各自标注范围。暂时网络失败保留旧样本并显示缓存状态，遵守最短刷新周期和服务端重试间隔。

账号配置属于运行 Agent 的 server。只填写凭据环境变量名称；令牌不会保存到 Herdr 配置、偏好或远程客户端。CLI 登录由官方工具管理。Kimi Code 用 `KIMI_CODE_HOME` 选择 profile，登录态在该目录的 `credentials/kimi-code.json`；在那里登录后，「需要登录」的账号无需重启即可自愈。

`organization`、`account_user` 按对应官方接口设置组织、团队、用户 ID 或明确要求的邮箱。API 密钥账号覆盖 OpenAI、Anthropic、Moonshot 与 OpenRouter；OpenRouter 的 `billing_scope = "account"` 使用管理密钥查询账号总额，默认仅查询当前 API key。`base_url` 只接受已登记的官方地址；Kimi 本地 API 只允许 loopback。

Kimi 的 Server API 被官方标为 experimental：`quota.usages` 的窗口与旧版字段都支持解析，缺失或形状不符的字段只跳过该项，不会让整份样本失败。

## 官方回调

Claude Code 的账号页可启用或移除官方状态栏回调。已有状态栏命令通过管道保留；输入报文原样交给原渲染器，Herdr 只抽取用量字段。Claude 的 `rate_limits` 需要支持该字段的 CLI 版本，并且通常在首次正常 API 响应后出现；Herdr 不会为取额度发送模型任务。

其他官方集成可以将受支持的 JSON 通过 `herdr api usage-report --agent <agent>` 写入 stdin。默认使用 `HERDR_PANE_ID` 对应的绑定，也可明确指定 `--account <id>`。未绑定的窗格仅在该厂商只有一个账号时自动绑定，否则先绑定账号；原始 JSON 和会话内容不会写入持久化文件。`--passthrough` 用于已有状态栏管道。

Pi 没有 statusline 契约，它的 RPC 模式又是另起的 headless 进程，看不到窗格里正在运行的会话。因此由 Herdr 的 Pi 扩展（集成版本 `10`；运行 `herdr integration install pi` 更新）在运行中的 TUI 会话里直接取数，经 Herdr socket 推送：会话开始时、每轮结束后（最多每 5 s 一次）、压缩之后，以及 agent 停稳时。推送内容是上下文用量（`ctx.getContextUsage()`）、本会话的 token 与费用合计，以及当前服务商与模型——服务商实际应答的模型与请求的不同时取实际应答的那个。Pi 是多服务商 CLI，所以这些是会话统计，不是账号额度：带上服务商 / 模型是为了把这份会话关联到为它付费的订阅账号，而不是重复计量。刚压缩完、下一次响应到来之前，Pi 自己也不知道上下文大小；Herdr 显示为「暂无数据」，不是 0。Pi 没有回调开关；第一次推送到达之前，账号会说明它在等什么。

## 厂商能力与官方依据

账号用量覆盖六个 Agent：Codex、Claude Code、Kimi Code、OpenCode、Pi 与 ZCode。官方依据最近一次复核于 2026-09-22（Codex 为 2026-09-16，ZCode 数据库结构为 2026-09-23）。官方未公开个人额度 API、权限不足或 CLI 输出变化时，显示可用性说明和官方入口；为其它 Agent 配置的账号会提示未登记官方来源。表中的会话统计与本地统计不代表账号剩余额度。

| Agent | 官方查询与范围 |
| --- | --- |
| Codex | [App Server](https://learn.chatgpt.com/docs/app-server) 的账号、速率窗口和附加用量；API 计费另用管理员报表。 |
| Claude Code | [statusline JSON](https://code.claude.com/docs/en/statusline)：`rate_limits` 的账号额度窗口，加上本会话的 `cost` 与 `context_window`；可选开启官方 `/usage`。API 组织用量与费用独立。 |
| Kimi Code | [本地 Server API](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html)（官方标为 experimental）：`quota.usages` 的 5 小时、7 天、月度窗口及月度窗口里的 Code 部分；`quota.extraUsage` 超额按量钱包以金额显示（余额、总额、本月费用，以及开启时的每月上限）。Moonshot API 余额另查。 |
| OpenCode | [`opencode db <query> --format json`](https://opencode.ai/docs/cli/)：对 `session` 表的只读聚合——会话数、子 agent 会话数、费用，以及输入 / 输出 / 推理 / 缓存 token。本地统计，非账号额度。 |
| Pi | Herdr 的 Pi 扩展，基于官方[扩展 API](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)：上下文用量、本会话 token 与费用、当前服务商 / 模型。会话统计，非账号额度。 |
| ZCode | [ZCode 桌面应用](https://github.com/zai-org/ZCode)的本地数据库 `~/.zcode/cli/db/db.sqlite`，用系统 `sqlite3 -readonly` 只读查询 `model_usage` 表最近 24 小时的数据：按主任务与子 agent 拆分的 token 及合计、工具调用次数、子 agent 会话数。不需要也不读取任何凭据。只有本地统计，非账号额度；远端额度不查询。 |

OpenCode 没有任何账号额度接口，所以它的两种形态都在指标范围与来源说明里标明是本地会话统计。`db` 查询只读计数与合计，不读会话标题或路径。没有 `db` 子命令或其 `--format` 选项的 CLI 版本，以及查询失败的情况（例如旧版数据库结构），回退到解析 `opencode stats` 的表格。OpenRouter 的密钥预算与账号总额是两回事。

账号页上 OpenCode 与 ZCode 带「本地统计，非账号额度」徽标，Pi 带「会话统计」徽标，都不会被当成账号额度。ZCode 的本地统计来自 ZCode 桌面版数据库，远端额度不查询。

ZCode 是桌面应用，从不在窗格里运行，Herdr 也从不启动它（它的命令会打开窗口）。server 用自身 `PATH` 上的 `sqlite3` 命令读它的数据库；没有这个命令时，ZCode 账号会说明原因而不显示数字。查询只按请求开始时间对请求行计数与求和，从不读取提示词、消息或错误文本。`query_source` 为 `subagent` 或 `task_type` 为 `subagent_child` 的请求记到子 agent，其余请求（主轮次、标题生成、压缩）都记到主任务。数据库被占用、无法读取或结构变化时，保留上次样本并显示为缓存数据，按退避重试。ZCode 账号拒收 `herdr api usage-report` 推送，也不支持 `profile_dir`；把 `"zcode"` 加进 `disabled_providers` 即可停止轮询。

## API

公开 JSON 方法包括 `system.metrics.get/subscribe/unsubscribe`、`system.process.list/get/terminate`、`account.usage.providers/get/refresh/subscribe/unsubscribe/report/integration` 和 `account.binding.set`。订阅事件有独立采样时间，慢消费者只保留最新样本。

`account.usage.get` / `account.usage.refresh` 的响应与 `account.usage.updated` 事件在快照旁带一份 `refresh` 列表（`UsageRefreshState`，按 `account_id` 与 `accounts` 对齐；旧版 server 省略）：探测进度（`in_flight`、`queued`）、显式刷新防抖（`requested_at_ms`、`next_allowed_at_ms`）、厂商退避（`retry_after_ms`）、`binding_inferred`、`trust_required`、`callback_only`、`pending_binding` 与 `callback_enabled`。`account.usage.refreshing` 在探测派发时只推送这份列表。字段含义与事件信封见 [事件订阅](/zh-cn/docs/socket-api/#事件订阅)。

多视图的 `client.views.set` 及具名帧/输入扩展仅用于协商后的 TUI 连接，不修改 generation 1 的消息编码。工作台移动窗格复用既有 `pane.move` 与 `pane.swap`。完整参数以 `herdr api schema --json` 为准。
