Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them.

## Workspace

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

A workspace owns tabs and panes. Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

Panes always answer default color queries. A program that asks for the foreground, background, or cursor color with `OSC 10 ; ?`, `OSC 11 ; ?`, or `OSC 12 ; ?` gets a reply even before Herdr has learned the host terminal's theme. The fallback is per color: whichever color the host terminal has not reported falls back to Herdr's own terminal default, so a host that reports only a background leaves the pane reporting Herdr's default foreground. The cursor color follows the foreground unless the program sets one. Herdr's own defaults follow the host appearance: black on white when the host reports a light appearance, white on black otherwise. Programs that pick a palette from `OSC 11` therefore do not land on a dark theme in a light terminal. Replies use the same terminator as the query, `BEL` or `ST`.

Because panes now have real default colors, reverse video (`CSI ? 5 h`) actually swaps them and paints the pane explicitly instead of being ignored. Panes still inherit the host background whenever their colors match the defaults Herdr gave them.

## Mouse UI

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

In the docked layout, drag a panel's `⠿` title handle to rearrange panels. While **Lock layout** is on, panel titles drop the `⠿` handle, the footer says the layout is locked instead of suggesting drags, and the resize and move hints of **Arrange layout** are dimmed. A maximized panel is the only panel on screen, so there is nowhere to dock it: its title drops the `⠿` handle, pressing the title only focuses the panel, and the footer says how to restore the layout — click `◫` (without mouse capture, press `Enter` in **Arrange layout**). Restoring works while the layout is locked too; the footer then also notes the lock. In **Arrange layout** mode, a borderless pane's `⠿` handle sits in the row just above the pane, which is the tab bar or the gap between panes, instead of covering the terminal's first line; it stays on the pane's first line only when that row has no room. With mouse capture off (`mouse_capture = false`) nothing can be dragged, so panel titles and panes drop their `⠿` handles and the footer, instead of suggesting drags, points to **Arrange layout** in the main menu and its keys: `Tab` focuses a panel, arrows resize, `Shift+arrows` move. While the layout is locked it says to turn off **Lock layout** in the main menu instead of the top bar.

When the terminal is smaller than the docked layout's minimum size, Herdr switches to a compact view that shows only the focused panel. Every panel keeps a minimum width and height, so the default layout needs 37 columns and 13 rows, and 66 columns once the Monitor panel is docked beside the terminal. The compact view's title bar lists every panel in layout order with the current one highlighted: click a name to switch to that panel, or use **Arrange layout** and `Tab`. When the names do not fit, the title bar shows only the focused panel. Compact view has only one panel to dock, so its title bar never draws the `⠿` handle, and pressing anywhere on it only switches focus instead of starting a drag. With `ui.mouse_capture = false` the footer keeps the **Arrange layout** + `Tab` hint instead of suggesting a click, since switching by name needs mouse capture. The docked layout does not use `ui.mobile_width_threshold` or the mobile switcher; they apply only to the classic layout used with older servers.

## Agent

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The agent finished and you have not looked at it yet. |
| `idle` | The agent is finished or waiting and has been seen. |
| `unknown` | Herdr cannot confidently classify the state. |

Each client tracks which completions it has displayed. Viewing a completion in one client does not clear another client's Done badge. CLI/API statuses use the server's seen state, so they need not match a particular client's badge; both `idle` and `done` mean ready for input.

The agents panel shows agents as a collapsible tree: machine (only when you have added other machines, as in the workspace list), then workspace, then tab (only when that workspace has more than one tab), then agent. Workspace and tab headers show the combined status of their agents, machine headers show the machine's connection status, and every header shows how many entries it holds; click anywhere on a header to collapse or expand it. A blocked agent's status text is bold in the status color. With the default dot icons, where blocked and working share the same `●`, a workspace or tab header that contains a blocked agent also shows a bold `!` before the count, and a blocked agent row whose status text does not fit shows a bold `!` instead, so blocked agents do not rely on color alone. Collapsing a machine here also collapses it in the workspace list. Each agent row shows its status icon, name, status text when there is room, and, when the agent reports sub-agents or tasks, an activity badge: `2/5 running` (running / total) while any of them is still running, just the total such as `5 activities` (or `1 activity`) once none is running, and no badge when there is no activity. On a narrow sidebar the badge first shrinks to just the numbers, such as `2/5`, and then disappears, so the status icon and name always keep their room. The arrow on that row expands the latest activity item, followed by `+N more` when there are more; clicking either opens the agent activity window. Right-clicking an agent row offers **Focus**, **View agent activity** (dimmed while the agent reports no activity), **Rename pane** (renames the pane on the machine that runs the agent, without switching to that machine; dimmed while that machine is offline or its server does not advertise `pane.rename`), **Usage** and **Bind account** (only for Codex, Claude Code, Kimi Code, OpenCode and Pi, the agents whose account usage Herdr tracks), and **Close pane**. When another machine rejects a rename or close, for example because the pane has already closed, a notice gives its reason; when closing the pane would also close a worktree group there, the notice asks you to switch to that machine and close it there, where you can confirm. Right-clicking a workspace header opens the same menu as right-clicking that workspace in the workspace list. The sort toggle switches between this tree and launch order, which lists agents flat in launch order while agent rows can still expand their activity. With multiple connected machines, launch order groups agents by machine first and orders them by launch sequence within each machine; it never interleaves launch sequences across machines. Status-filtered views are flat too and leave out External entries. With no agents at all and no status filter, the list shows a centered `no agents` note instead of staying blank. When the panel is too short to show group headers, it lists every agent flat with its workspace name instead (with room for only one line, that line shows the status icon, the agent name and then the workspace name), and the collapsed sidebar of the classic layout lists every agent too; collapsed workspace, tab, and External groups do not hide entries in these flat lists, because there is no header there to expand them. A collapsed machine is the exception: with other machines added and the panel showing the tree (not launch order or a status filter), collapsing a machine also leaves its agents out of these flat lists until you expand it again in the workspace list. The collapsed sidebar lists only agents running in Herdr panes; External entries appear only in the expanded panel. Agents that an external source reports outside any Herdr pane appear under an External group per source; clicking one opens its agent activity window. In the classic layout used with older servers, the mobile switcher keeps its flat agent list and adds the same activity badge after the agent's details; when the row has no room for it, the badge likewise shrinks to just the numbers and then disappears, instead of being cut off mid-count.

### Agent activity window

The agent activity window shows what an agent reports about its sub-agents, tasks, todos, and background processes. Open it by clicking an activity item (or `+N more`) under an agent row in the agents panel, by clicking an entry in an External group, or by choosing **View agent activity** from the right-click menu of an agent row (while it reports activity) or of an External entry. Opening it from an activity item selects that item.

The left column is the activity tree. Each item shows its branch in the tree, a status mark, its label, its kind, and how long it has run: running items use the accent color, failed items are red, and finished items are grey. Click the arrow on an item to collapse or expand its children. The right column shows the selected item's output under a header with the item's label, kind, status, and duration, plus its type and summary when the source reports them. When the header runs out of room, the status text goes first (the status mark still shows it), then the label is shortened, then the kind and finally the duration are left out; a duration is never cut off mid-number. Markdown output gets colored headings and list markers; JSON Lines output shows one record per line, prefixed with its `type`, `role`, and `name`. Long lines wrap at the column width, and a note at the top says when only the latest part of the output is shown.

For an agent in a pane the window opens in follow mode: Herdr refreshes the tree about once a second and reads new output after each refresh, and the output stays on the newest line until you scroll up. Scroll back to the bottom, or press `End` while the output has focus, to stick to new output again. Turn follow off with the **Follow** button or `f`; while it is off, the title shows a note when the agent's activity changes, and the **Refresh** button or `r` reloads the tree and the selected output. Entries from an external source are marked "External source, read-only" and never follow. A long agent or entry name is shortened in the title so this mark and the update note stay visible. If a read is interrupted, for example because the connection to the machine drops, the window retries it once the machine is reachable again.

The window is a floating page: drag its top border to move it, or its side and bottom borders to resize it (not while **Lock layout** is on), and Herdr remembers its position and size. A server that does not provide agent activity, such as an older Herdr server, shows a note instead of the tree. When the window is narrower than 60 columns inside its border it shows one column at a time; `Tab` switches between the tree and the output.

| Key | Action |
| --- | --- |
| `↑` `↓` | Select the previous or next item; scroll the output when it has focus |
| `←` `→` | Collapse or expand the selected item; `←` on a child selects its parent, and in the output moves focus back to the tree |
| `Enter` | Reload the selected item's output from the start and move focus to it |
| `Tab` | Switch focus between the tree and the output |
| `PgUp` `PgDn` `Home` `End` | Scroll or jump in the focused column |
| `f` | Turn follow on or off |
| `r` | Refresh |
| `Esc` | Close the window and return to the window it was opened from, if any |

The mouse wheel scrolls whichever column the pointer is over, and clicking outside the window closes it.

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named sessions are separate runtime namespaces:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The server owns panes and process state. The client is the terminal UI attached to that server.

With one attached client, all tabs follow its size as before. With multiple clients, each can view its own workspace and tab. Different viewed tabs follow their respective clients; when clients view the same tab, the last one to focus, select, or interact with it controls that tab's pane sizes.

Detach the client with `ctrl+b q`. The server and agents continue running.

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. See [Keyboard](/docs/keyboard/) if the prefix idea is new to you.
