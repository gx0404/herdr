Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them.

## Workspace

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

A workspace owns tabs and panes. Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

## Session sidebar

The **Sessions** panel lists your sessions the way desktop coding apps do. Its header has `✚` (new workspace) and `⌕` (search sessions in the session navigator). The **Agent overview** row below it counts pane agents on your online machines that need input (`◆`), failed (`✕`), are working (spinner), or are done and waiting for review (`●`); click it to open the session navigator. Offline cached agents and External entries are not counted.

By default sessions are grouped by workspace: a machine row (only when you have added other machines), then each workspace with its collapse arrow, its name, and the status that needs you most with how many agents are in it, a dim line with the branch and how far it is ahead or behind, and one row per pane. An agent row shows its status glyph, the agent name, a one-line summary, and its age; a plain terminal row shows `·` and the pane name or directory. The summary is the pending question or permission request for an agent that needs input, the error for a failed one, the current tool (or the session title) for a working one, and otherwise the session title or the last message. Working ages measure the current turn; other ages measure time in the current state. Ages are rounded to minutes (`now`, `3m`, `1h`): crossing a wall-clock minute refreshes the cached rows and requests one repaint when ages are present, never a per-second repaint. Linked worktrees nest under their main workspace, and collapsing the main workspace also collapses its worktrees. An active agent with sub-agents or background tasks shows a `▸2` tag; click it to expand its activity tree. External sources follow in their own group and reuse the same activity expansion. Clicking an External entry opens read-only activity when its server advertises `agent.activity.read`; without that method the Sub-agents page explains that it is unavailable. An External entry has no pane to focus. Workspace rows keep their drag reordering, number keys, navigation mode, and right-click menu.

Click **By workspace ▾**, or run **Toggle session grouping** from the command palette, to group by status instead: Needs input, Failed, Review, Working, Idle, and Other (plain terminals or unknown status) sections, where pane rows also name their workspace. Activity expansion remains available in this view, and section counts count sessions, not activity children. Empty sections are hidden. The choice is remembered per machine. The footer opens settings and help and shows the active machine's status; click the machine to manage machines. When the terminal is narrower than 100 columns and the dock has a compatible left sidebar, the panel shrinks to a 4-column rail with one numbered status glyph per workspace; click one to switch to it. Custom, maximized, and compact layouts keep their applicable geometry.

Press `prefix+a` to jump to the next pane session that needs you: agents that need input first, then failed ones, then those waiting for review, cycling across workspaces and online machines. External entries and offline cached agents are excluded.

Classic layouts (including older servers) and the mobile switcher use one Sessions tree, with no Inspector and no second Agents list. The classic tree occupies the entire sidebar rather than sharing its height with an agent section. The width divider, collapse button, workspace rail, scrolling, and workspace navigation remain available; the old internal section divider is no longer interactive. Existing `sidebar_section_split` preferences can be read, but new interactions do not save a section split. Configured agent rows, per-agent tokens, custom state labels, selected agent views, and launch ordering apply to the agent sessions in this tree. Launch order keeps workspace navigation above a single ordered session list; different machines' launch sequences are never compared. In workspace grouping, a workspace with multiple tabs has a collapsible header for each tab: its arrow hides only that tab's sessions, and clicking its name focuses the tab. Agent navigation reveals the target session (or its workspace in the rail) during view computation, opening any collapsed ancestor. External rows retain the reported agent name and the unreadable marker when applicable; activity chips keep the full count or yield to the name instead of truncating digits. The tree has one proportional scrollbar for workspaces, sessions, and activity rows.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

Panes always answer default color queries. A program that asks for the foreground, background, or cursor color with `OSC 10 ; ?`, `OSC 11 ; ?`, or `OSC 12 ; ?` gets a reply even before Herdr has learned the host terminal's theme. The fallback is per color: whichever color the host terminal has not reported falls back to Herdr's own terminal default, so a host that reports only a background leaves the pane reporting Herdr's default foreground. The cursor color follows the foreground unless the program sets one. Herdr's own defaults follow the host appearance: black on white when the host reports a light appearance, white on black otherwise. Programs that pick a palette from `OSC 11` therefore do not land on a dark theme in a light terminal. Replies use the same terminator as the query, `BEL` or `ST`.

Because panes now have real default colors, reverse video (`CSI ? 5 h`) actually swaps them and paints the pane explicitly instead of being ignored. Panes still inherit the host background whenever their colors match the defaults Herdr gave them.

## Mouse UI

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

In the docked layout, drag a panel's `⠿` title handle to rearrange panels. While **Lock layout** is on, panel titles drop the `⠿` handle, the status bar says the layout is locked and how to unlock it from the title bar's `⋯` menu, and the resize and move hints of **Arrange layout** are dimmed. A maximized panel is the only panel on screen, so there is nowhere to dock it: its title drops the `⠿` handle, pressing the title only focuses the panel, and the status bar says how to restore the layout — click `◫` (without mouse capture, press `Enter` in **Arrange layout**). Restoring works while the layout is locked too; the status bar then also notes the lock. In **Arrange layout** mode, a borderless pane's `⠿` handle sits in the row just above the pane, which is the panel header with its tabs or the gap between panes, instead of covering the terminal's first line; it stays on the pane's first line only when that row has no room. With mouse capture off (`mouse_capture = false`) nothing can be dragged, so panel titles and panes drop their `⠿` handles and the status bar points to **Arrange layout** in the main menu and its keys: `Tab` focuses a panel, arrows resize, `Shift+arrows` move. While the layout is locked it says to turn off **Lock layout** in the main menu instead of the title bar's `⋯` menu.

When the terminal is smaller than the docked layout's minimum size, Herdr switches to a compact view that shows only the focused panel. Every panel keeps a minimum width and height, so the default layout needs 37 columns and 7 rows with Inspector hidden, and 66 columns once the Monitor panel is docked beside the terminal. The compact view's panel header lists every panel in layout order with the current one highlighted: click a name to switch to that panel, or use **Arrange layout** and `Tab`. When the names do not fit, the header shows only the focused panel. Compact view has only one panel to dock, so its header never draws the `⠿` handle, and pressing anywhere on it only switches focus instead of starting a drag. With `ui.mouse_capture = false` the status bar keeps the **Arrange layout** + `Tab` hint instead of suggesting a click, since switching by name needs mouse capture. The docked layout does not use `ui.mobile_width_threshold` or the mobile switcher; they apply only to the classic layout used with older servers.

## Agent

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The agent finished and you have not looked at it yet. |
| `idle` | The agent is finished or waiting and has been seen. |
| `unknown` | Herdr cannot confidently classify the state. |

Each client tracks which completions it has displayed. Viewing a completion in one client does not clear another client's Done badge. CLI/API statuses use the server's seen state, so they need not match a particular client's badge; both `idle` and `done` mean ready for input.

Agent sessions use the same Sessions tree in the docked, classic, and mobile layouts. Expanding activity shows the active subtree with its ancestors, such as Claude Code workflow → phase → sub-agent. Workflow and phase groups use `⧉` and `▤` (`W` and `P` in narrow rows), with running/total counts. A grey completion row summarizes done and failed activity and opens the Sub-agents page; `+N more` appears only when the active summary is truncated.

Right-clicking an agent session offers **Focus**, **View agent activity** (dimmed without reported activity), **Rename pane**, and **Close pane**. Rename acts on the machine that owns the pane without switching machines and is dimmed while offline or without `pane.rename`. Rejected remote actions show the reason; closing a remote worktree group asks you to switch to that machine to confirm there. Workspace headers retain their workspace context menu; External entries remain read-only.

### Agent overview

`prefix+g` opens the agent overview. Status groups show only nonzero counts and initially retain six sessions per group; Enter on a group or its **more** row expands it. `g` switches to location mode, preserving machine, workspace and terminal navigation. Space toggles the selected agent's received-insight preview. Read/unread badges and manual marks belong to this client, not the server. See [Agents](/docs/agents/) for reply capability and identity rules.

### Inspector

The docked layout uses **Sessions | Terminal | Inspector**, with content-width shares of 20 / 56 / 24 after divider columns. Version-1 layouts migrate once to version 2: the old Agents and retired Accounts panels are removed, Inspector is inserted at the root's right edge, and the terminal split tree and groups, focus, lock, and valid maximization are preserved. A one-time notice confirms the upgrade; corrupt layouts still reset and future versions are not migrated.

Inspector shows the focused agent's title, status, turn duration, endpoint/workspace/branch/tab, model, question and options or failure reason, last message and prompt, a sub-agent summary, and the latest eight locally observed state transitions. Ordinary terminals show a clear empty state; older servers without insight or activity reading remain usable. Codex supports activity reading once its session hook reports a usable thread ID; without that ID the read can return `not_implemented`. The local state-transition history retains at most 128 agents, isolated by endpoint, server boot, pane, and agent launch identity. It is not a server audit log.

The **Sub-agents N** section replaces the full activity tree. Its count line lists only nonzero **Needs input**, **Failed**, **Running**, **Done**, and **Pending** counts. Up to three representative rows prioritize items that need input, failed items, and running items; the final **View all ›** row shows the `d` shortcut. Shortcut actions use keycaps: `↵` for **Jump and answer**, `d` for **Sub-agents page**, and `r` for **Refresh**.

Inspector is hidden by default. `prefix+i` toggles it between shown and hidden, saved per endpoint in client-shell preferences. Existing per-endpoint choices stay in effect. A manually saved `inspector_visibility` value of `auto` still shows Inspector at 140 columns or wider; the toggle never saves `auto`. Resizing never rewrites the dock tree. Visible Inspector reads the full reported tree, rather than only the sidebar's active summary, with the existing `agent.activity.read` method, one request at a time, and follows at most once a second. Open overlays pause new follow reads. Hidden panels and target changes stop follow reads locally; an already accepted server read may finish and its follow lease expires. The tree cache retains at most eight targets, 512 nodes and 128 KiB of display text per target; oversized trees show a truncation notice. Node output and pagination remain on the Sub-agents page. Duration and age labels update by the minute, while all working glyphs share one animation clock.

### Sub-agents page

The Sub-agents page shows an agent's sub-agents, tasks, todos, and background processes. Open it from Inspector with **Sub-agents page**, **View all ›**, or `d` while Inspector has keyboard focus. The existing Sessions activity items, completion summary, `+N more`, External entries, and **View agent activity** context-menu action also open this page; opening an activity item selects it. In the workbench layout the page fills the content area; in classic and mobile layouts it fills the screen.

The header shows **Back**, **Sub-agents**, the owner and its location, with **Follow**, **Refresh**, **Jump to terminal**, and **Close** on the right. External sources show **Read-only** and have no terminal to jump to. Older servers without activity reading show an explanation instead of a tree. Codex activity becomes available once its session hook reports a usable thread ID; before that `agent.activity.read` can return `not_implemented`.

Press `1`, `2`, or `3` to switch views; Herdr remembers the choice for the current session:

| Key | View | Contents |
| --- | --- | --- |
| `1` | Tree | The parent-child hierarchy |
| `2` | Status | Items grouped by state |
| `3` | Timeline | Swimlanes above, transcript and summary below; the summary is hidden below 120 columns |

Codex, Claude Code, and OpenCode transcripts are parsed into nested blocks for quotes, assistant text, thinking, tool calls and output, plans, and metadata. Tool output can be collapsed. Long lines wrap, and a note identifies output that contains only the latest part of a transcript.

For a pane owner the page opens in follow mode, refreshing about once a second. Output stays at the newest line until you scroll up; return to the bottom or press `End` in the transcript to resume following new output. `f` toggles follow and `r` refreshes the tree and selected transcript. External entries remain read-only and do not follow periodically.

Below 100 columns the page uses one column; below 60 columns each item takes one line. Below 80 columns the header buttons show icons only. Below 12 rows the header's second line is hidden; below 40 columns or 8 rows only a minimal hint is shown.

| Key | Action |
| --- | --- |
| `↑` `↓` / `j` `k` | Select an item or scroll the transcript, according to focus |
| `←` `→` / `h` `l` | Collapse or expand an item |
| `Tab` | Switch focus between the list and transcript |
| `Enter` | Open the selected transcript from the list; in the transcript, expand or collapse all tool output |
| `/` | Filter items while retaining their ancestors |
| `c` | Collapse or expand completed items |
| `f` | Toggle follow |
| `r` | Refresh |
| `t` | Jump to the owner's terminal, only when the owner is a pane |
| `PgUp` `PgDn` `Home` `End` | Scroll or jump in the focused area |
| `Esc` | Clear the filter first; otherwise close the page |

The mouse can select rows, view tabs, and buttons; clicking a tool header toggles its output. The wheel scrolls the area under the pointer.

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named sessions are separate runtime namespaces:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The server owns panes and process state. The client is the terminal UI attached to that server.

With one attached client, all tabs follow its size as before. With multiple clients, each can view its own workspace and tab. Different viewed tabs follow their respective clients; when clients view the same tab, the last one to focus, select, or interact with it controls that tab's pane sizes.

Detach the client with `ctrl+b q`. The server and agents continue running.

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. See [Keyboard](/docs/keyboard/) if the prefix idea is new to you.
