Open **Monitor** from the top bar, the global menu, or command search. A single panel hosts three pages — System, Accounts and Settings — switched with the in-panel tabs or `1`/`2`/`3`; `r` refreshes, `Space` pauses history, and `Esc` closes. Hardware metrics belong to the connected host; hovering a remote agent queries its own host.

## Menus, pages, and stable selection

`prefix+Space` opens the categorized main menu; `prefix+/` opens command search (the default prefix is `Ctrl+B`). Categories cover workspaces, tabs and panes, SSH, monitoring, tools, settings, and help. Recent commands are limited to five. Search accepts localized titles, English action aliases, categories, and machine addresses. The wheel scrolls independently; keyboard navigation reveals the selected item.

Drag a page's top border to move it, or its side and bottom borders to resize it. Client preferences retain geometry and constrain it to smaller terminals. Layout locking also disables page dragging. Closing the menu restores the previous page. Settings apply on Enter or the save button; theme selection previews and Escape cancels the preview.

Selecting terminal text freezes a text snapshot of that pane while processes and other panes keep updating. Release copies and resumes live output. With `copy_on_select` disabled, Ctrl+C copies the retained selection. Scrolling reads captured history without scrolling the live terminal. If output changed before capture and the mouse was already released, confirm the captured selection with Ctrl+C instead of automatically copying unseen content.

Each snapshot is bounded to 65,536 cells, 2048 rows, and 8 MiB; scrolling stops at the captured boundary. Server limits are 64 MiB, 32 snapshots, and one per client. Resize, target changes, cancellation, and disconnect release the snapshot. Unacknowledged captures expire after 60 seconds. Older servers retain the legacy selection path.

Use `Ctrl+Shift+Space` as the WezTerm leader and keep `Ctrl+B` for Herdr. Ordinary dragging selects within Herdr; Shift+drag uses WezTerm's selection.

## Docking

Drag a panel's `⠿` title handle to another panel's edge. The drop preview shows the destination. Drag dividers to resize, tabs to reorder or create another terminal group, and pane handles to swap panes or move them between tabs without restarting their processes. Borderless panes show their handles only in Layout mode, keeping normal terminal text unobstructed. Right-click tab menus remain available.

The primary terminal page belongs to the focused workspace: clicking a workspace in the sidebar swaps both the tab strip and the terminal content to that workspace's tabs, numbered from 1 per workspace. Tabs dragged into their own panel stay visible regardless of workspace focus.

`□` maximizes/restores a panel. In Layout mode, `Tab` / `Shift+Tab` selects a panel, arrows resize, `Shift+arrows` move, `Enter` maximizes, and `Esc` finishes. Lock prevents accidental rearrangement; Reset restores the default layout. Layouts persist per client and endpoint. Small terminals project the focused panel without discarding the saved layout. Older servers retain the previous single-view UI.

## Host resources

Choose total/per-core CPU, RAM/swap, GPUs, disks, network interfaces, temperatures and processes. Sampling supports 500, 1000, 2000 and 5000 ms. Slow collectors run independently. Initial differential samples, unavailable drivers and permission failures display a status or `—`, rather than zero.

NVIDIA uses NVML. Other Linux GPUs use driver-exposed DRM/sysfs fields; Windows uses DXGI and native GPU performance counters. Temperature, power and utilization availability depends on the driver. Containers and WSL report resources visible in that environment.

Scroll inside a card to inspect additional devices, CPU cores or processes. Click a core to select its history. Card arrows change order; settings control height and hidden devices. History is client-local, covers 1–60 minutes and has a 16 MiB budget. Pause stops history recording while live sampling and alerts continue.

Process details pin the process instance. Termination requires confirmation; force is a separate choice. Expired confirmations, reused PIDs and protected processes are rejected. Windows termination requires the force option and appropriate permission.

Alerts default to off and operate only while a TUI is connected. Configure threshold, duration and cooldown; alerts never kill processes.

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

## Account binding

Hover an agent row or CLI title to inspect usage. `format` picks dashboard gauges or a table. `position` decides where that per-pane popover lives: `hover` and `both` keep it on agent rows and CLI titles; `page` turns the popover off and leaves the accounts page as the only per-pane view (the settings page shows a hint while it is selected). The accounts page, the usage button's overview and the floating dashboard are available in every mode. Choices made in Monitor → Settings are saved as client preferences that override `enabled`, `format`, `position`, `hover_delay_ms` and the disabled providers on that machine until "Restore config file values" is used there. Select and bind the account to the pane. A shared vendor name does not identify an account by itself: when an official callback arrives from an unbound pane and that vendor has exactly one configured account, the server binds the pane to it, persists the binding and marks the snapshot as auto-bound; with several accounts for the vendor the callback is rejected with the candidate list and the pane must be bound explicitly. Auto-binding requires `account_usage.enabled` and a callback that carries quota fields.

Hovering the agents panel's usage button (after `hover_delay_ms`, 400 ms by default) opens a compact cross-provider overview anchored below the button: one header line per account plus up to three quota lines with progress bars, flipped above the button when there is no room below. Moving the pointer away closes it after 250 ms; clicking the button pins it so it stays until `Esc`, another click on the button, or a click outside it. Clicking the overview itself opens the accounts page. The overview keeps its own scope and never rewrites the accounts page selection; a pinned overview only closes on its own when the button disappears because the panel became too narrow. In narrow panels the button shrinks to a one-column `%` label before the sort label is truncated, and it needs mouse capture.

Command search still opens the floating usage dashboard: the cross-account overview in a movable, resizable window that honors `format`. It is non-modal: the rest of the shell is not dimmed, keys other than `Esc` go to the focused terminal, clicks inside select rows or press its buttons, the wheel scrolls it, and a click outside closes it. It refreshes automatically while open.

Client preferences are read field by field: an unreadable value (for example an unknown `usage_format`) drops only that field with one diagnostic and keeps the rest. The `usage_hover_dashboard` preference (default `true`) turns the hover overview off while clicking the button still pins it; like the other `usage_*` keys it is written back only once it has been set explicitly.

The accounts page lists only providers whose official CLI is installed on the connected host — resolved with the same multi-alias PATH and install-layout detection as the integrations settings page (codex standalone/nvm/volta/bun, Hermes), so both surfaces agree. Providers with an explicitly configured account stay listed. `account.usage.providers` reports an `installed` flag per provider; older servers omit the field and keep listing the full registry. Automatic refresh runs on the server while a client shows the data: API and portal accounts every `api_refresh_seconds` (at least 60 s), CLI probes every `cli_refresh_seconds` (at least 300 s; `account.usage.providers` advertises the effective value as `minimum_interval_seconds`), with bounded backoff after failures. Callback-only vendors advertise no polling interval and are refreshed by their callbacks. When the accounts page opens without a provider selected it picks the agent running in the focused pane, otherwise the first listed provider. Switching provider or account keeps the previous snapshot dimmed until fresh data arrives; "Switch account" is disabled when the current scope has fewer than two configured accounts, and providers turned off in settings leave the provider chips, the switch candidates and the overview at once. When a codex CLI is found through an install layout, the probe runs it with that layout's bin directory first on `PATH` so npm-shim CLIs resolve their interpreter.

An explicit refresh (`account.usage.refresh`, the account page's refresh action, switching provider or account) is debounced to 10 s per account and still honors vendor backoff (HTTP 429); a debounced response carries `next_allowed_at_ms`. Terminal results (not signed in, unsupported, permission denied) are retried automatically on a slow schedule — 10 min, doubling up to 1 h, at most 6 times — and the hold is lifted as soon as the CLI binary or its credential files change, so signing in heals the account without a restart; an explicit refresh always retries a terminal state. Official callbacks without quota fields do not overwrite the cached sample. After 15 min without a callback the snapshot is shown as cached data; probes may fall back, but only a successful probe or the next callback replaces it. Callback-only vendors report `callback_only` in the refresh state: an explicit refresh cannot produce a new quota sample for them, though it may still refresh a login or binding placeholder.

While the accounts page or the floating dashboard is visible, the client subscribes with `account.usage.subscribe` on servers that advertise it and applies pushed `account.usage.updated` / `account.usage.refreshing` events as they arrive, keeping only a 30 s fallback poll; the subscription is dropped when the page is hidden, re-established after a reconnect, and older servers fall back to polling (2 s, or 500 ms while a probe is in flight). An account being probed shows "Refreshing…" on its own row; the refresh button reads "Refresh in N s" while the selected account (or, with no selection, every listed account) is still debounced, and a vendor backoff longer than a minute is noted on the account's row instead of locking the button. The accounts page also carries a binding row: a pane picker that only offers panes running the selected provider's agent, "Bind focused pane", and one-click candidates from `pending_binding` after the server rejected a callback from an unbound pane. Every binding entry refuses a pane running another provider's agent, and enabling the official callback binds the pane on the host that answered — never on a host that became active meanwhile.

Claude Code is callback-first. Quota comes from the official statusline callback; probes only check the login state with the non-interactive `claude auth status --json`, which reads the real login store read-only. A signed-in account without the callback shows "waiting for the official statusline callback" together with the setting to enable, and that precheck backs off on the same slow schedule as terminal states until the first callback arrives. The interactive `/usage` probe is opt-in (`interactive_probe = true`) and runs on explicit refresh only, inside a stable probe directory under the herdr state directory: Claude Code asks you to trust that directory once in your own CLI — the refresh state reports `trust_required` and the message names the directory — and herdr never answers that dialog for you. Because the interactive probe reuses the real login state, concurrent launches can rotate credentials; leave it off unless you need `/usage` without the callback.

Both formats support wheel scrolling; the account page also supports the arrow keys for quota windows below the viewport. The usage popover can appear over a focused monitor panel and captures its own input without activating background cards or process rows.

Subscription windows, key budgets, organization billing and local session statistics keep their own scopes and units. Results show reset times, source and sample age. Temporary errors retain the last successful sample with a cached status and bounded retry intervals.

Configure accounts on the server running the agent. `credential_env` names an environment variable; do not place the credential itself in TOML. Herdr does not copy CLI OAuth credentials to clients. CLI profiles use the vendor's documented directory selector. New Kimi Code uses `KIMI_CODE_HOME`; legacy Python Kimi uses a separate login store.

```toml
[account_usage]
enabled = true
format = "dashboard" # dashboard / table
position = "hover" # hover / page / both; page turns the agent-row popover off
hover_delay_ms = 400
api_refresh_seconds = 60
cli_refresh_seconds = 300
probe_timeout_seconds = 20
interactive_probe = false # explicit refresh only; Claude needs a one-time folder trust
disabled_providers = []

[[account_usage.accounts]]
id = "work-codex"
label = "Work"
agent = "codex"
provider = "codex"
auth_mode = "cli"
profile_dir = "/path/to/profile"

[[account_usage.accounts]]
id = "team-api"
label = "Organization API"
agent = "claude"
provider = "anthropic"
auth_mode = "api"
credential_env = "ANTHROPIC_ADMIN_KEY"
```

Use `organization` and `account_user` for the exact identity required by the selected API. Set `billing_scope = "enterprise"` and an enterprise slug in `organization` for GitHub Enterprise. OpenRouter uses a management key with `billing_scope = "account"`; its default scope is the current API key. OMP's multiple-account output requires a provider/account selection. `base_url` only accepts registered official hosts; Kimi's local API is restricted to loopback.

## Official callbacks

Claude and Antigravity account panels can enable/remove the official statusline callback. An existing renderer is retained at the end of a passthrough pipeline. Claude's quota fields require a supporting CLI version and normally appear after the first ordinary API response. Herdr never sends a model prompt to obtain usage.

Other integrations can send supported official JSON to stdin of `herdr api usage-report --agent <agent>`. The command uses the binding for `HERDR_PANE_ID`, or explicit `--account <id>`. An unbound pane is bound automatically only when the vendor has a single configured account; otherwise bind first. Raw reports and conversation contents are not persisted. `--passthrough` preserves input for an existing statusline renderer.

## Provider capabilities

The registry covers 23 agents, excluding Muse. Official sources were checked on 2026-09-16. Subscription access and administrator billing access differ. Unsupported versions, absent APIs or missing permissions produce an explicit availability message. Session statistics never imply an account quota.

See the [provider source matrix](/zh-cn/docs/monitoring/#厂商能力与官方依据) for every official reference. Codex uses App Server; Kimi uses its authenticated local Server API; Claude and Antigravity support statusline quotas. Letta has a dedicated usage command; Kiro supports non-interactive `/usage`. Cursor, Devin, Cline, Copilot and Factory use their separately authorized reporting APIs. OMP, Amp and OpenCode have distinct CLI formats. Gemini, Grok and Hermes use guarded official CLI commands. Qoder currently has no verified automatic input-readiness contract. Mastra Code, Qwen, Maki and Pi provide session statistics and can bind their actual billing provider.

Factory daily reports end no later than yesterday UTC. Cursor overage spend is separate from subscription-inclusive spend. Amp BYOK list-price estimates are not billed usage. Letta's quota bucket labels remain categorical. OpenRouter key budgets are distinct from account totals. Kimi 2.x `quota.usages` windows and legacy fields are both parsed. OpenCode usage requires a CLI version whose `stats` command supports JSON output; older builds report an explicit upgrade hint.

## API

Public JSON methods include `system.metrics.get/subscribe/unsubscribe`, `system.process.list/get/terminate`, `account.usage.providers/get/refresh/subscribe/unsubscribe/report/integration`, and `account.binding.set`. Slow subscribers retain the newest sample.

`account.usage.get` / `account.usage.refresh` responses and `account.usage.updated` events carry a `refresh` list (`UsageRefreshState`, aligned to `accounts` by `account_id`; older servers omit it) next to the snapshots: probe progress (`in_flight`, `queued`), the explicit-refresh debounce (`requested_at_ms`, `next_allowed_at_ms`), vendor backoff (`retry_after_ms`), `binding_inferred`, `trust_required`, `callback_only`, `pending_binding` and `callback_enabled`. `account.usage.refreshing` pushes only that list as a probe starts. Field meanings and the event envelope are documented under [event subscriptions](/docs/socket-api/#event-subscriptions).

`client.views.set` and named view-frame/input extensions require a negotiated TUI connection. Generation 1 encoding stays unchanged. Pane dragging reuses `pane.move` and `pane.swap`. Use `herdr api schema --json` for the precise contracts.
