Open **Monitor** from the title bar's `⋯` layout menu, the main menu, or command search. A single panel hosts two pages — System and Monitor preferences — switched with the in-panel tabs or `1`/`2`; `r` refreshes, `Space` pauses history, and `Esc` closes, and the panel footer lists them as clickable hints — refresh and pause on the System page, close everywhere; the Monitor preferences page holds only local preferences, so its footer offers no refresh. Hardware metrics belong to the connected host.

## Menus, pages, and stable selection

`prefix+Space` opens the categorized main menu; `prefix+/` opens command search (the default prefix is `Ctrl+B`). Categories cover workspaces and agents, tabs and panes, machines and SSH, monitoring, tools and automation, appearance and settings, and help and notifications. Recent commands are limited to five. Search matches action titles in either interface language, shortcuts, category names, and machine addresses. The wheel scrolls independently; keyboard navigation reveals the selected item.

Drag a page's top border to move it, or its side and bottom borders to resize it. Client preferences retain geometry and constrain it to smaller terminals. Layout locking also disables page dragging. Closing the menu restores the previous page. Settings apply on Enter or the **apply** button; theme selection previews and Escape cancels the preview.

Selecting terminal text freezes a text snapshot of that pane while processes and other panes keep updating. Release copies and resumes live output. With `copy_on_select` disabled, Ctrl+C copies the retained selection. Scrolling reads captured history without scrolling the live terminal. If output changed before capture and the mouse was already released, confirm the captured selection with Ctrl+C instead of automatically copying unseen content.

Each snapshot is bounded to 65,536 cells, 2048 rows, and 8 MiB; scrolling stops at the captured boundary. Server limits are 64 MiB, 32 snapshots, and one per client. Resize, target changes, cancellation, and disconnect release the snapshot. Unacknowledged captures expire after 60 seconds. Older servers retain the legacy selection path.

Inside Ghostty GX, leave `Ctrl+B` to Herdr and bind host shortcuts to chords Herdr does not use, such as a key sequence that starts with `Ctrl+Shift+Space`. Ordinary dragging selects within Herdr; Shift+drag uses Ghostty GX's own selection.

## Docking

Drag a panel's `⠿` title handle to another panel's edge. The drop preview shows the destination. Drag dividers to resize, tabs to reorder or create another terminal group, and pane handles to swap panes or move them between tabs without restarting their processes. Borderless panes show their handles only in **Arrange layout** mode, keeping normal terminal text unobstructed. Right-click tab menus remain available.

The primary terminal page belongs to the focused workspace: clicking a workspace in the sidebar swaps both the tab strip and the terminal content to that workspace's tabs, numbered from 1 per workspace. Tabs dragged into their own panel stay visible regardless of workspace focus.

`□` maximizes a panel; while one is maximized the button shows `◫` and restores the layout. The title bar's `⋯` opens the layout menu: **Monitor**, **Arrange layout**, **Lock layout**, and **Reset layout**, which also stay in the main menu and command search. **Arrange layout** enters arrange mode: its menu entry carries a check mark, the title bar shows an **Arrange** chip (click it to finish), and the status bar names the mode and lists its keys: `Tab` selects a panel (`Shift+Tab` goes back), arrows resize, `Shift+arrows` move, `Enter` maximizes, and `Esc` finishes (the status bar's **Esc done** hint is clickable too). While a panel is maximized the whole layout still responds: `Tab` moves the maximized panel along with the focus, and arrows or `Shift+arrows` leave maximize first so the resize or move is visible. **Lock layout** is an on/off toggle that carries a check mark while the layout is locked and prevents accidental rearrangement; **Reset layout** restores the default layout, and while the layout is locked it is dimmed and choosing it does nothing. Layouts persist per client and endpoint. Small terminals project the focused panel without discarding the saved layout. Older servers retain the previous single-view UI.

The Monitor panel carries a ` × ` button in its header next to `□`. Inside the docked panel the page draws no frame of its own — the panel header and divider already frame it — so its tabs sit on the first line below the panel header and its cards one column in from the panel edge. When the panel is focused, `Esc` closes the panel hosting the page; when a terminal is focused, `Esc` goes to the terminal, so use the header button or **Close monitor panel** in command search (listed only while the Monitor panel is docked). With the layout locked, closing is refused and the panel footer says so. The monitor tab you last selected — System or Monitor preferences — is kept in client preferences and restored when the panel regains focus or the client restarts; opening **Monitor** from the `⋯` layout menu, the main menu, or command search starts on the System page. A docked Monitor panel no longer hides the focused terminal's cursor: the cursor disappears only where a panel or a dialog actually covers it. The wheel does not need the panel to be focused: anywhere over a docked Monitor panel's content it scrolls the page the panel shows — a card whose content does not fit scrolls itself, anywhere else the page moves — while the keyboard stays with the focused panel, and a wheel over another panel never scrolls the page.

## Title bar, status bar, and tabs

The docked layout puts a title bar on the top row and a status bar on the bottom row. The title bar starts with **≡ herdr**, which opens the main menu, followed by a breadcrumb for the focused terminal: `workspace / tab`, led by the machine name when you have more than one machine, and ending with the agent's status glyph and name when the focused pane runs an agent. Its right end holds the attention counts, one chip per state with agents in it (needs input, failed, working, and done but not yet seen, such as `◆ 2`), and clicking any of them opens the agent navigator; then the command search hint, `⌕` followed by your configured keys (`ctrl+b /` by default), which opens command search; and `⋯`, the layout menu. When the terminal is too narrow for the whole title bar, its items give way whole instead of being cut off, in a fixed order: the command search hint goes first; the breadcrumb is then shortened from the left and finally hidden; the attention counts shrink to the most urgent one; then the **Arrange** chip and the last count go; and last of all **≡ herdr** shrinks to `≡`. The `≡` entry and `⋯` always stay, so the main menu and every layout action remain one click away.

The status bar starts with a mode label. In terminal mode it is a quiet **TERMINAL** label followed by key hints for the prefix key, sessions (the agent navigator), commands (command search), and keybinds (the keybind help); the last three are clickable. Prefix, navigate, resize, copy, and arrange modes show a highlighted label with that mode's keys, and an endpoint error shows a red label with the message. In compact view, while a panel is maximized, while the layout is locked, or with mouse capture off, the hints give way to a short note on how to switch panels, restore the layout, unlock it, or arrange it from the keyboard; when the note does not fit next to the **TERMINAL** label, the label steps aside. The server's status segments, such as host and time, sit at the right end, and the input broadcast badge leads the bar while broadcast is on.

Each panel has a one-line header on the panel's own background: the `⠿` drag handle, the title (bold while the panel is focused), and `□` / `◫` on the right, plus ` × ` on the Monitor panel. A terminal group's header also carries its tabs. Tabs are session-style: the active tab sits on a lighter background in bold, and a tab with agents leads with the status glyph of its most urgent agent. With mouse capture on, the active tab and the tab under the pointer show `×`, which closes the tab through the same confirmation as the tab menu's **close tab**.

Status glyphs follow one scheme everywhere: sidebar rows, the agent tree, tabs, the breadcrumb, the attention counts, and agent pane titles (see `ui.status_indicators` in [Configuration](/docs/configuration/)). Every working spinner follows one shared clock, so they turn in step. Rows, tabs, and the breadcrumb of a machine that is offline keep still, dimmed glyphs, and pane border titles, which the server draws, always show still glyphs.

## Host resources

Choose total/per-core CPU, RAM/swap, GPUs, disks, network interfaces, temperatures and processes. Sampling supports 500, 1000, 2000 and 5000 ms. Slow collectors run independently. Initial differential samples, unavailable drivers and permission failures display a status or `—`, rather than zero.

NVIDIA uses NVML. Other Linux GPUs use driver-exposed DRM/sysfs fields; Windows uses DXGI and native GPU performance counters. Temperature, power and utilization availability depends on the driver. Containers and WSL report resources visible in that environment. GPU drivers are queried at most every 2 s whatever the sampling interval, and on Windows the adapter list is refreshed every 60 s. When NVML reports utilization for every Windows adapter, Herdr shows NVML's utilization (source `NVML + Windows DXGI`) and skips the per-process GPU engine counters, the expensive part of a sample; with any other adapter present every GPU keeps the performance-counter utilization. When no client requests monitor data, the server's sampling threads sleep until the next request.

The Monitor preferences tab does not request hardware samples while alerts are off. Enabled alerts add their required metric groups even when those cards are hidden; with the System page hidden, unrelated groups such as the process list are not requested. Switching endpoints or receiving a new server boot resets resource and network histories and alert latches; ordinary refreshes from the same source preserve them.

The System page opens with a host summary line — host name, operating system, uptime, sample age and sampling interval — and lays the resource cards out below it in one column, or two columns once the panel is at least 96 columns wide. The CPU card shows the total as a gauge whose number stays visible at any width, the model (or the selected core once you click one), and a history sparkline; the per-core card draws one mini bar per logical core, spread across the whole card width, and clicking a core selects its history. Memory shows used and cache as segments of one gauge plus a swap gauge; each GPU lists temperature, utilization and VRAM. Disks are a table of real data volumes: pseudo filesystems without capacity are skipped and a device mounted in several places is listed once. Network draws a stacked receive/transmit sparkline per active interface and folds idle interfaces into one line. Temperatures are summarised per chip: the number and bar show the hottest sensor, followed by the chip's average, which a narrow panel drops first; when every chip fits with at least two rows to spare, the card plots the hottest sensor's history below them. Within one card the bar rows share a label column and a number column, so their bars start and end at the same columns. Processes are a table whose headers sort on click; the row above it holds the name filter and the visible range, and the PID column is as wide as the longest PID in the sample, so seven-digit PIDs are never cut off. Scroll inside a card to inspect additional devices, cores or processes; over a card whose content already fits, such as CPU or memory, the wheel scrolls the page instead. Elsewhere on the page the wheel, and `↑`/`↓` while no card is selected or the selected card's content already fits, scroll one row of cards at a time, and `PageUp`/`PageDown` a screen at a time; scrolling stops once the last card is fully in view, so turning back moves the page on the first notch. Until then the next row of cards shows its top at the bottom edge of the page, cut off by the edge rather than squeezed into a shorter card. The Monitor preferences page scrolls three lines per notch and stops at its last line the same way. History is client-local, covers 1–60 minutes and has a 16 MiB budget. Pause stops history recording while live sampling and alerts continue.

Card order is changed in **Edit layout** mode, entered from the button at the right end of the summary line: every card gets ↑/↓ buttons on its top edge, once a card is selected the others dim, and the `↑`/`↓` keys move the selected card. **Done** or `Esc` leaves the mode; `Esc` closes the panel only on the next press. Card height, hidden devices and the chart glyphs are set on the Monitor preferences page.

Process details pin the process instance. Termination requires confirmation; force is a separate choice. Expired confirmations, reused PIDs and protected processes are rejected. Windows termination requires the force option and appropriate permission.

Alerts default to off and operate only while a TUI is connected. Configure threshold, duration and cooldown; alerts never kill processes. The Monitor preferences rows and the alert notification name each rule by its metric — CPU, Memory, GPU or Disk — rather than by its config id.

The **Monitor preferences** page groups its controls into cards. Steppers set the sampling interval (500 / 1000 / 2000 / 5000 ms), card height (7 / 10 / 16 / 24 rows), history range (1 / 5 / 15 / 30 / 60 min) and each alert rule's threshold (50–100 % in steps of 5), duration and cooldown; toggles switch alerts, the visible cards and the sampled devices; a segmented control picks the chart glyphs. A stepper moves to the neighbouring step of its fixed ladder and wraps at both ends, so a config value that sits between two steps moves to the next step first instead of skipping one. **Chart glyphs** selects the alphabet of the System page's sparklines and bars — Braille (default), Blocks, or ASCII for terminals without those glyphs — and is stored as the client preference `monitor_chart_glyphs`.

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true # default: false

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

`visible` takes any of `cpu`, `cores`, `memory`, `gpu`, `disks`, `network`, `sensors`, and `processes` (all eight by default), and an alert's `metric` is `cpu`, `memory`, `gpu`, or `disk`. Listing `[[monitor.alerts]]` replaces the built-in rules (CPU, memory, and disk at 90 %, GPU at 95 %, each for 30 s with a 60 s cooldown). Changing the sampling interval, card height, history range, visible cards, sampled devices, or alert settings on the Monitor preferences page, or moving cards in **Edit layout**, saves the whole monitor configuration as the client preference `monitor`, which from then on takes precedence over `[monitor]` in the config file.

Client preferences are read field by field: an unreadable value (for example an unknown `monitor_chart_glyphs`) drops only that field with one diagnostic and keeps the rest.

## API

Public JSON methods include `system.metrics.get/subscribe/unsubscribe` and `system.process.list/get/terminate`. Slow subscribers retain the newest sample; the `system.metrics.updated` push is described under [event subscriptions](/docs/socket-api/#event-subscriptions).

`client.views.set` and named view-frame/input extensions require a negotiated TUI connection. Generation 1 encoding stays unchanged. Pane dragging reuses `pane.move` and `pane.swap`. Use `herdr api schema --json` for the precise contracts.
