タイトルバーの `⋯` レイアウトメニューの **Monitor**、メインメニュー、コマンド検索から開きます。1 つのパネルが System / Preferences の 2 ページを持ち、パネル上部のタブ列（現在のページは一段明るい背景に太字で表示）または `1`/`2` で切り替えます。`r` は更新、`Space` は履歴の一時停止、`Esc` で閉じます。パネルのフッターにはこれらがステータスバーと同じキーキャップのクリックできるヒントとして並びます。更新と一時停止は System ページ、閉じるは全ページにあります。Preferences ページはローカル設定だけなので、フッターに更新は表示しません。ハードウェアの指標は接続先ホストのものです。

## メニュー、ページと安定した選択

`prefix+Space` はカテゴリ別のメインメニュー、`prefix+/` はコマンド検索を開きます（既定の prefix は `Ctrl+B`）。カテゴリはワークスペースとエージェント、タブとペイン、マシンと SSH、監視、ツールと自動化、外観と設定、ヘルプと通知です。最近使ったコマンドは最大 5 件です。検索はどちらの表示言語のアクション名、ショートカット、カテゴリ名、マシンのアドレスにも一致します。ホイールは選択とは独立してスクロールし、キーボード操作は選択中の項目を表示範囲に入れます。

ページの上枠をドラッグすると移動し、左右と下の枠をドラッグするとサイズを変えられます。位置とサイズはクライアント設定に保存され、小さなターミナルでは画面内に収まるよう調整されます。レイアウトのロック中はページもドラッグできません。メニューを閉じると元のページに戻ります。設定は Enter または **apply** ボタンで反映され、テーマは選ぶとプレビューされ、Esc でプレビューを取り消せます。

ターミナルの文字を選択している間は、そのペインの文字スナップショットを固定し、プロセスとほかのペインは更新を続けます。マウスを離すとコピーしてライブ表示に戻ります。`copy_on_select` が無効なら、保持された選択を Ctrl+C でコピーします。スクロールは取得済みの履歴を読むだけで、ライブのターミナルはスクロールしません。取得前に出力が変わり、すでにマウスを離していた場合は、見ていない内容を自動でコピーせず、Ctrl+C で取得済みの選択を確定してもらいます。

スナップショット 1 件の上限は 65,536 セル、2048 行、8 MiB で、スクロールは取得した範囲の端で止まります。サーバー全体では 64 MiB、32 件、クライアントごとに 1 件です。サイズ変更、対象の変更、取り消し、切断でスナップショットは解放されます。確認されない取得は 60 秒で期限切れになります。古いサーバーでは従来の選択動作を使います。

Ghostty GX では `Ctrl+B` を Herdr に残し、ホスト側のショートカットには Herdr が使わないキー（たとえば `Ctrl+Shift+Space` で始まるキーシーケンス）を割り当ててください。通常のドラッグは Herdr 内の選択、Shift+ドラッグは Ghostty GX 自身の選択です。

## ドック配置

パネルタイトルの `⠿` ハンドルを別のパネルの端へドラッグするとドックできます。ドロップのプレビューが移動先を示します。境界線をドラッグしてサイズを変え、タブをドラッグして並べ替えたり別の端末グループを作ったりでき、ペインのハンドルをドラッグすると、プロセスを再起動せずにペインを入れ替えたり別のタブへ移したりできます。枠のないペインのハンドルは **Arrange layout** モードのときだけ表示され、通常のターミナル本文を遮りません。タブの右クリックメニューも引き続き使えます。

プライマリの端末ページはフォーカス中のワークスペースに属します。サイドバーでワークスペースをクリックすると、タブ列と端末の内容がそのワークスペースのタブに切り替わります（番号はワークスペースごとに 1 から）。独立したパネルへドラッグしたタブは、ワークスペースのフォーカスにかかわらず表示されたままです。

`□` はパネルを最大化し、最大化中はボタンが `◫` になってレイアウトを元に戻します。タイトルバーの `⋯` はレイアウトメニューを開きます。**Monitor**、**Arrange layout**、**Lock layout**、**Reset layout** の 4 項目で、いずれもメインメニューとコマンド検索にも残っています。**Arrange layout** でレイアウト調整モードに入ると、メニューのこの項目にチェックマークが付き、タイトルバーに **Arrange** チップが表示され（クリックすると終了します）、ステータスバーにはモード名とキーが表示されます。`Tab` でパネルを選び（`Shift+Tab` で逆順）、矢印でサイズ変更、`Shift+矢印` で移動、`Enter` で最大化、`Esc` で終了します（ステータスバーの **Esc done** もクリックできます）。パネルの最大化中もレイアウト全体が反応し、`Tab` は最大化をフォーカスと一緒に移し、矢印や `Shift+矢印` はいったん最大化を解除してからサイズ変更や移動を見せます。**Lock layout** はオン/オフの切り替えで、ロック中はチェックマークが付き、誤って並べ替えるのを防ぎます。**Reset layout** は既定のレイアウトに戻します。レイアウトのロック中は淡色表示になり、選んでも何も起きません。レイアウトはクライアントとエンドポイントごとに保存されます。小さいターミナルでは保存したレイアウトを捨てずに、フォーカス中のパネルだけを表示します。古いサーバーでは従来の単一ビューの UI を使います。

Monitor パネルのヘッダーには `□` の横に ` × ` ボタンがあります。ドックしたパネル内のページは独自の枠を描きません（パネルのヘッダーと区切り線がすでに枠になるため）。タブはパネルのヘッダーの下の 1 行目に、カードはパネルの端から 1 列内側に並びます。パネルにフォーカスがあるときは `Esc` でそのページを載せたパネルを閉じます。ターミナルにフォーカスがあるときは `Esc` はターミナルへ渡るので、ヘッダーのボタンかコマンド検索の **Close monitor panel**（Monitor パネルがドック中のときだけ表示）を使ってください。レイアウトがロックされていると閉じられず、パネルのフッターにその旨が表示されます。最後に選んだ Monitor のタブ（System / Preferences）はクライアント設定に保存され、パネルが再びフォーカスされたときやクライアントの再起動時に復元されます。`⋯` レイアウトメニュー、メインメニュー、コマンド検索から **Monitor** を開いたときは System ページから始まります。ドックした Monitor パネルは、フォーカス中のターミナルのカーソルを隠さなくなりました。カーソルが消えるのは、パネルやダイアログが実際にその位置を覆うときだけです。ホイールはパネルにフォーカスがなくても使えます。ドックした Monitor パネルの内容の上ならどこでも、パネルが表示しているページをスクロールします（内容が収まりきらないカードはカード自身が、それ以外の場所ではページが動きます）。キーボードはフォーカス中のパネルのままで、ほかのパネルの上でホイールを回してもこのページはスクロールしません。

## タイトルバー、ステータスバーとタブ

ドッキングレイアウトでは、最上行にタイトルバー、最下行にステータスバーを表示します。タイトルバーの左端はメインメニューを開く **≡ herdr** で、その後ろにフォーカス中のターミナルのパンくずリストが続きます。`ワークスペース / タブ` の形で、マシンが複数あるときは先頭にマシン名が付き、フォーカス中のペインでエージェントが動いているときは末尾にその状態グリフと名前が付きます。右側には、エージェントがいる状態ごとに 1 つずつの注意カウント（入力待ち、失敗、実行中、完了して未確認。たとえば `◆ 2`。どれをクリックしてもエージェントナビゲーターが開きます）、`⌕` に続けて実際に設定されたキー（既定では `ctrl+b /`）を示すコマンド検索のヒント（クリックするとコマンド検索が開きます）、レイアウトメニューの `⋯` が並びます。ターミナルの幅がタイトルバー全体に足りないときは、各項目を途中で切らずに丸ごと決まった順に譲ります。まずコマンド検索のヒントを隠し、次にパンくずリストを左側から短くして最後には隠し、注意カウントを最も緊急な 1 つにまとめ、続いて **Arrange** チップと残りのカウントを隠し、最後に **≡ herdr** を `≡` に縮めます。`≡` と `⋯` は常に残るので、メインメニューとすべてのレイアウト操作にいつでも 1 クリックで届きます。

ステータスバーはモードのラベルから始まります。ターミナルモードでは控えめな **TERMINAL** ラベルの後に、プレフィックスキー、セッション（エージェントナビゲーター）、コマンド（コマンド検索）、キーバインド（キーバインドヘルプ）のキーヒントが並び、後ろの 3 つはクリックできます。プレフィックス、ナビゲート、リサイズ、コピー、レイアウト調整の各モードでは強調したラベルとそのモードのキーを表示し、エンドポイントのエラーは赤いラベルとメッセージで示します。コンパクトビューのとき、パネルを最大化しているとき、レイアウトをロックしているとき、マウスキャプチャが無効なときは、キーヒントの代わりに、パネルの切り替え方、レイアウトの戻し方、ロックの解除方法、キーボードでの並べ替え方を短く案内します。案内が **TERMINAL** ラベルと並べて収まらないときは、ラベルのほうが譲ります。右端にはホストや時刻などサーバーのステータスセグメントが並び、入力ブロードキャスト中はブロードキャストのバッジが先頭に表示されます。

各パネルには、パネル自身の背景色の上に 1 行のパネルヘッダーがあります。`⠿` ドラッグハンドル、タイトル（パネルにフォーカスがあるときは太字）、右側に `□` / `◫`、Monitor パネルにはさらに ` × ` が並びます。端末グループのパネルヘッダーにはそのタブも並びます。タブはセッション風で、アクティブなタブは一段明るい背景に太字で表示され、エージェントがいるタブには最も緊急なエージェントの状態グリフが名前の前に付きます。マウスキャプチャが有効なときは、アクティブなタブとポインターの下のタブに `×` が表示され、クリックするとタブの右クリックメニューの **close tab** と同じ確認を経てタブを閉じます。

状態グリフはどこでも同じ体系です。サイドバーの行、エージェントツリー、タブ、パンくずリスト、注意カウント、エージェントのペインの枠タイトルに使われます（グリフのスタイルは[設定](/ja/docs/configuration/)の `ui.status_indicators` を参照）。実行中のスピナーはすべて 1 つの時計に従うので、足並みをそろえて回ります。オフラインのマシンの行、タブ、パンくずリストのグリフは静止した淡色で表示され、サーバーが描くペインの枠タイトルは常に静止したグリフです。

## リソース監視

CPU の合計・コアごと、RAM/swap、GPU、ディスク、ネットワークインターフェース、温度、プロセスを選べます。サンプリング間隔は 500、1000、2000、5000 ms です。遅い取得処理は独立して動きます。初回の差分サンプル、利用できないドライバー、権限の失敗は、0 ではなく状態または `—` で表示します。ただし、DRM/sysfs 経路、または NVML が利用できない場合の `nvidia-smi` フォールバック経路では、ランタイムでサスペンド中の Linux GPU は 0 % と休止の説明を表示します。

NVIDIA は読み込める場合に NVML を使います。Linux で NVML を読み込めない場合（GX Shell パッケージの静的リンク musl ビルドなど）、Herdr は `nvidia-smi` にフォールバックし、`PATH`、`/usr/bin`、`/usr/lib/wsl/lib` の順に探します。PCI bus id、名前、使用率、使用中/合計 VRAM、温度、電力を取得します。照会ごとのタイムアウトは 3 秒、出力上限は 64 KiB で、失敗後は 30 秒、`nvidia-smi` が見つからない場合は 10 分待って再試行します。どちらも利用できない場合、カードには “NVML could not be loaded and nvidia-smi is unavailable” と表示します。NVIDIA のデバイス ID は `00000000:01:00.0` のような NVML の bus id 形式を使います。

Linux のほかの GPU はドライバーが公開する DRM/sysfs のフィールドを使います。DRM/sysfs 経路と、NVML が利用できない場合の `nvidia-smi` フォールバック経路では、sysfs の `power/runtime_status` が `suspended` の GPU は 0 % と “Asleep to save power; not woken for metrics” を表示します。Herdr はその GPU のメトリクスを一切読まないため、監視によって復帰させることはありません。NVML が利用できる場合は、Herdr は引き続き NVML ですべての NVIDIA GPU を照会するため、ランタイムでサスペンド中のカードを復帰させることがあります。Intel i915/Xe 内蔵 GPU のようにドライバーがビジー率を公開しない場合、現在のユーザーが読み取れるプロセスの DRM fdinfo エンジンカウンター（`drm-engine-*` のナノ秒、または Xe の `drm-cycles-*`/`drm-total-cycles-*`）から使用率を推定します。エンジンごとにクライアントを合計し、最も忙しいエンジンを使い、ソースは `DRM fdinfo` と表示します。起動後、またはサンプル間隔が 10 秒を超えた後の最初のサンプルは基準値の確立に使い、ウォームアップ状態を表示します。走査の上限は 65,536 ファイル記述子、4,096 クライアント、fdinfo ファイルごとに 16 KiB です。

Windows は DXGI とネイティブの GPU パフォーマンスカウンターを使います。温度・電力・使用率を取得できるかはドライバー次第です。コンテナーと WSL はその環境で見えるリソースを表示します。GPU ドライバーへの照会はサンプリング間隔にかかわらず最大 2 秒に 1 回で、Windows のアダプター一覧は 60 秒ごとに更新します。NVML がすべての Windows アダプターの使用率を報告できる場合、Herdr は NVML の使用率（ソース `NVML + Windows DXGI`）を表示し、1 回のサンプルで最も重いプロセスごとの GPU エンジンカウンターを省きます。ほかのアダプターが 1 つでもあれば、すべての GPU でパフォーマンスカウンターの使用率を使い続けます。モニターのデータを要求するクライアントがないとき、server のサンプリングスレッドは次のリクエストまで休止します。

アラートがオフなら、Preferences タブからハードウェアのサンプルは要求しません。アラートが有効なら、対応するカードが非表示でも必要なメトリクスグループを追加します。System ページが非表示の間は、プロセス一覧など無関係なグループを要求しません。エンドポイントの切り替えや server の新しい起動識別子を受信すると、リソース・ネットワークの履歴とアラートの発火状態をリセットします。同じソースの通常更新では保持します。

System ページの先頭はホスト概要の 1 行（ホスト名、OS、稼働時間、サンプルの経過時間、サンプリング間隔）で、その下にリソースカードを 1 列、パネル幅が 96 列以上なら 2 列で並べます。最初のサンプルが届くまでは、ページの中央にプレースホルダーを表示します。各カードは角の丸い枠で、上辺にタイトル、上辺の右端に主な読み値（CPU・メモリ・GPU・ディスクの使用率、最も高い温度、プロセス数）を置くので、数値はどの幅でも残ります。リソースの種類ごとに色相を使います。CPU（コアごとのカードを含む）は青、メモリと GPU の VRAM バーは紫、GPU は緑、ディスクは青緑、ネットワークの受信はシアン・送信はマゼンタ、温度は空色です。カードのタイトル（選択時は太字）、通常のバー、履歴の輪郭、ディスクの使用率、上辺の主な読み値に使い、履歴の塗りとメモリのキャッシュ部分は同じ色相の控えめな色にします。パレットは `panel_bg` の明るさに応じて暗色用と明色用を選び、16 色テーマやターミナル既定の背景では、順に標準 ANSI の blue、magenta、green、cyan、light cyan、light magenta、light blue を使います。警告と古いデータの状態を優先し、バーと読み値は対応するアラートルールのしきい値より 15 ポイント低い警告ラインを超えると黄色、しきい値そのものに達すると赤になります（既定では CPU・メモリ・ディスクが 90 %、GPU が 95 %。ルールのないメトリクスは 75 % と 90 %）。古いデータは灰色になります。カードの枠、ホスト概要、プロセスカードは中立色を保ちます。CPU カードは全体を示す横幅いっぱいのバー、モデル名と論理 CPU 数（コアをクリックするとそのコアの説明に置き換わります）、履歴チャートを表示し、チャートの輪郭と控えめな塗りは CPU の色相を共有します。コアごとのカードは論理コアごとのミニバーをカード幅いっぱいに並べ、コアをクリックするとその履歴を選びます。メモリは使用中とキャッシュを同じ色相の濃淡で 1 本のバーの区分として描き、その下の行に量を示し、swap のバーも付きます。GPU はデバイスごとに温度・使用率・VRAM を並べます。ディスクは実データのボリュームだけの表で、容量のない疑似ファイルシステムは除外し、複数箇所にマウントされた同じデバイスは 1 回だけ載せます。ネットワークはアクティブなインターフェースごとに受信 / 送信を重ねたスパークラインを描き、速度の文字とチャートの両方で受信をシアン、送信をマゼンタで示し、アイドルなインターフェースは 1 行にまとめます。温度はチップごとに要約します。数値とバーはチップ内で最も熱いセンサーを示し、その後にチップの平均温度が続きます（パネルが狭いと平均から省きます）。すべてのチップが収まり 2 行以上余るときは、その下に最も熱いセンサーの履歴を描きます。同じカード内のバー行はラベル列と数値列を共有するため、バーの始点と終点がそろいます。プロセスはヘッダーのクリックで並べ替えられる表で、その上の行に名前フィルターと表示範囲があります。PID 列はサンプル中で最も長い PID に合わせた幅になり、7 桁の PID も切れません。パネルが広いとユーザー列が加わり、狭くなるとユーザー、メモリ、PID の順に列を省くので、名前（12 列以上）と CPU は残ります。数値は右揃えで単位は淡色になり、詳細を開いているプロセス、またはキーボードのフォーカスがある行は選択色の背景に表示されます。カード内でスクロールすると追加のデバイス・コア・プロセスを表示します。CPU やメモリのように内容がすでに収まっているカードの上では、ホイールはページをスクロールします。ページのそれ以外の場所では、ホイールと、カード未選択時または選択中のカードの内容が収まっているときの `↑`/`↓` がカード 1 行ずつ、`PageUp`/`PageDown` が 1 画面ずつスクロールします。最後のカードが完全に見えた所で止まるので、逆方向の最初の 1 目盛りですぐ動きます。それまでは次の行のカードがページ下端から上部だけ見え、低いカードに押し縮めず下端で切り取って表示します。Preferences ページは 1 目盛り 3 行でスクロールし、同じく最終行で止まります。履歴はクライアント内に保持され、1–60 分、上限 16 MiB です。一時停止は履歴の記録だけを止め、ライブのサンプリングとアラートは続きます。

カードの順序は、概要行の右端のボタンから入る **Edit layout** モードで変更します。各カードの上辺に ↑/↓ ボタンが現れ、カードを 1 つ選ぶと他は淡色になり、`↑`/`↓` キーで選択中のカードを動かします。**Done** または `Esc` でモードを抜け、パネルが閉じるのは次の `Esc` です。カードの高さ、非表示のデバイス、チャートの字形は Preferences ページで設定します。

プロセスの詳細はプロセスのインスタンスに固定されます。ダイアログは共通の角丸枠と文字階層を使い、翻訳されたラベルの幅に合わせてボタンの間隔を取るため、狭いターミナルでも Cancel、Terminate、Force を操作できます。終了には確認が必要で、強制終了は別の選択肢です。期限切れの確認、再利用された PID、保護されたプロセスは拒否されます。Windows での終了には強制オプションと適切な権限が必要です。

ホバー効果が有効なときは、ポインター下のコントロールを控えめに強調します。キーボードの選択や現在のタブは変えません。破壊的なプロセス操作は赤色を保ち、下線を加えます。同じコントロール内の移動では再描画を要求しません。

アラートは既定でオフで、TUI が接続している間だけ動作します。しきい値、継続時間、クールダウンを設定でき、アラートがプロセスを終了することはありません。Preferences の行とアラートの通知は、ルールを設定の id ではなくメトリクス名（CPU、Memory、GPU、Disk）で示します。アラートは System ページがそのメトリクスを赤くするのと同じしきい値で発生し、通知は警告のスタイルで表示されます。

**Preferences** ページはコントロールをカードにまとめ、各行はラベルと短い説明、コントロールを並べます。サンプリング間隔（500 / 1000 / 2000 / 5000 ms）、カードの高さ（7 / 10 / 16 / 24 行）、履歴範囲（1 / 5 / 15 / 30 / 60 分）、各アラートルールのしきい値（50–100 %、5 刻み）・継続時間・クールダウンはステッパー、アラート、表示するカード、取得するデバイスはトグル、チャートの字形はセグメントコントロールです。ステッパーは固定の段階表の隣の段へ移動し、両端で折り返すので、段階の間にある設定値は段を飛ばさず最初に隣の段へ移ります。**Chart glyphs** は System ページのスパークラインとバーの字形——Braille（既定）、Blocks、それらの字形がないターミナル向けの ASCII——を選び、クライアント設定 `monitor_chart_glyphs` として保存されます。

```toml
[monitor]
interval_ms = 1000
history_minutes = 15
visible = ["cpu", "cores", "memory", "gpu", "network", "processes"]
card_height = 10
hidden_devices = []
alerts_enabled = true # 既定: false

[[monitor.alerts]]
metric = "cpu" # cpu / memory / gpu / disk
threshold = 90
duration_seconds = 30
cooldown_seconds = 60
```

`visible` には `cpu`、`cores`、`memory`、`gpu`、`disks`、`network`、`sensors`、`processes` を指定でき（既定は 8 つすべて）、アラートの `metric` は `cpu`、`memory`、`gpu`、`disk` のいずれかです。`[[monitor.alerts]]` を書くと組み込みのルール（CPU・メモリ・ディスクは 90 %、GPU は 95 %、いずれも 30 秒継続・クールダウン 60 秒）が置き換わります。Preferences ページでサンプリング間隔、カードの高さ、履歴範囲、表示するカード、取得するデバイス、アラートの設定を変えるか、**Edit layout** でカードを動かすと、監視の設定全体がクライアント設定 `monitor` として保存され、以後は設定ファイルの `[monitor]` より優先されます。

クライアント設定はフィールドごとに読み込まれます。読み取れない値（例: 未知の `monitor_chart_glyphs`）は、そのフィールドだけが 1 回の診断とともに破棄され、残りは保持されます。

## API

公開している JSON メソッドには `system.metrics.get/subscribe/unsubscribe`、`system.process.list/get/terminate` があります。遅い購読者には最新のサンプルだけが残ります。`system.metrics.updated` のプッシュについては[イベント購読](/ja/docs/socket-api/#イベント購読)を参照してください。

`client.views.set` とビューのフレーム/入力の名前付き拡張には、ネゴシエーション済みの TUI 接続が必要です。generation 1 のエンコードは変わりません。ペインのドラッグは既存の `pane.move` と `pane.swap` を使います。詳しい契約は `herdr api schema --json` を参照してください。
