上部の Monitor、グローバルメニュー、コマンド検索から開きます。1 つのパネルが System / Accounts / Monitor preferences の 3 ページを持ち、パネル内タブまたは `1`/`2`/`3` で切り替えます。`r` は更新、`Space` は履歴の一時停止、`Esc` で閉じます。パネルのフッターには更新 / 一時停止 / 閉じるがクリックできるヒントとして並びます。ハードウェア情報は接続先ホストのものです。リモート Agent にホバーすると、その Agent のホストで使用量を照会します。

## メニュー、ページと安定した選択

`prefix+Space` は分類メニュー、`prefix+/` はコマンド検索を開きます（既定の prefix は `Ctrl+B`）。ワークスペース、タブとペイン、SSH、監視、ツール、設定、ヘルプを分類し、最近使った操作は最大5件です。表示名、英語の操作名、分類、接続先で検索できます。ホイールは選択とは独立してスクロールし、キーボード操作は選択項目を表示します。

ページの上枠をドラッグして移動し、左右と下枠でサイズを変更できます。位置はクライアントに保存され、小さな画面内に収まります。レイアウトのロックはページ移動にも適用されます。メニューを閉じると元のページに戻ります。設定は Enter または保存で反映し、テーマのプレビューは Esc で取り消せます。

文字選択中は対象ペインの文字スナップショットを固定し、プロセスと他のペインは更新を続けます。マウスを離すとコピーしてライブ表示に戻ります。`copy_on_select` が無効なら Ctrl+C でコピーします。スクロールは固定履歴だけを移動します。取得前に画面が変わり、すでにマウスを離した場合は、固定された選択を確認して Ctrl+C を押します。

1件の上限は65,536セル、2048行、8 MiBです。サーバー全体は64 MiB、32件、クライアントごとに1件です。サイズ変更、対象変更、取消、切断で解放します。未確認の取得は60秒で期限切れになります。古いサーバーでは従来の選択動作を使用します。

WezTerm の leader は `Ctrl+Shift+Space`、Herdr は `Ctrl+B` を推奨します。通常のドラッグは Herdr、Shift+ドラッグは WezTerm の選択を使います。

## ドック配置

タイトルの `⠿` を別パネルの端へドラッグするとドックできます。境界をドラッグしてサイズを変更し、タブをグループ内で並べ替えるか別グループへ分割できます。ペインのハンドルで交換・別タブへの移動ができ、実行中プロセスは維持されます。枠のないペインでは **Arrange layout** モード時だけハンドルを表示し、通常のターミナル本文を遮りません。

プライマリの端末ページはフォーカス中のワークスペースに属します。サイドバーでワークスペースをクリックすると、タブ列と端末内容がそのワークスペースのタブへ切り替わります（番号はワークスペースごとに 1 から）。独自パネルへドラッグしたタブは切り替えの影響を受けません。

`□` は最大化と復元です。上部バーの **Arrange layout** でレイアウト調整モードに入り、オンのあいだはボタンが反転表示されます。フッターにはモード名とキーのヒントが表示され、`Tab` / `Shift+Tab` でパネル選択、矢印でサイズ変更、`Shift+矢印` で移動、`Enter` で最大化、`Esc` で終了します(フッターの **Esc done** もクリックできます)。最大化中もレイアウト操作は有効で、`Tab` は最大化対象をフォーカスと一緒に移し、矢印や `Shift+矢印` はいったん最大化を解除してから変更を適用します。**Lock layout** はオン/オフの切り替えで、ロック中はチェックマークが付き、誤操作を防ぎます。調整モード中だけ表示される **Reset** は既定の配置に戻します。配置はクライアントとホストごとに保存されます。狭い画面では選択パネルだけを表示し、保存した配置は維持します。旧 server は従来の単一ビューを使います。

Monitor と Accounts パネルのヘッダーには `□` の横に ` × ` ボタンがあります。ドッキングしたパネル内のページは独自の枠を描きません（パネルのヘッダーと区切り線がすでに枠になるため）。タブはパネル本文の 1 行目に、カードはパネルの端から 1 列内側に並びます。パネルにフォーカスがあるときは `Esc` でそのページを載せたパネルを閉じます。ターミナルにフォーカスがあるときは `Esc` はターミナルへ渡るので、ヘッダーのボタンかコマンド検索の **Close monitor panel**（Monitor パネルがドック中のときだけ表示）を使います。レイアウトがロックされていると閉じられず、パネル下部にその旨を表示します。最後に選んだ Monitor のタブ（System / Accounts / Monitor preferences）はクライアント設定に保存され、パネルが再びフォーカスされたとき・再び開いたときに復元されます。ドックした Monitor / Accounts パネルはフォーカス中ターミナルのカーソルを隠さなくなりました。カーソルが消えるのは、パネル・使用量のポップオーバー・ダイアログが実際にその位置を覆うときだけです。

上部バーが画面幅に収まらないときは、ボタンを途中で切らずに丸ごと隠します。**Monitor**、**Lock layout**、**Arrange layout** の順に隠し(3 つともメインメニューとコマンド検索から使えます)、上部バーにしかない **Reset** はそれらより後まで残します。

## リソース監視

CPU 全体・論理コア、RAM/swap、GPU、ディスク、ネットワーク、温度、プロセスを選択できます。間隔は 500 / 1000 / 2000 / 5000 ms。遅い取得処理は独立して実行します。初回の差分、権限不足、非対応項目には状態または `—` を表示します。

NVIDIA は NVML、Linux の他の GPU は公開された DRM/sysfs、Windows は DXGI と GPU パフォーマンスカウンターを使用します。温度・電力などはドライバーによって異なります。WSL とコンテナーはその環境で見えるリソースを表示します。

System ページの先頭はホスト概要の 1 行（ホスト名、OS、稼働時間、サンプル経過時間、サンプリング間隔）で、その下にリソースカードを 1 列、パネル幅が 96 列以上なら 2 列で並べます。CPU カードは全体のゲージ（数値はどの幅でも残ります）、モデル名と選択中コアの説明、履歴スパークラインを表示し、コアごとのカードは論理コアごとにミニバーをカード幅いっぱいに並べて描き、コアのクリックでその履歴を選択します。メモリは使用中とキャッシュを 1 本のゲージの区分として描き、swap のゲージも付きます。GPU はデバイスごとに温度・使用率・VRAM を並べます。ディスクは実データボリュームだけの表で、容量のない疑似ファイルシステムは除外し、複数箇所にマウントされた同じデバイスは 1 回だけ載せます。ネットワークはアクティブなインターフェースごとに受信 / 送信を重ねたスパークラインを描き、アイドルなインターフェースは 1 行にまとめます。温度はチップごとに要約します。数値とバーはチップ内で最も熱いセンサーを示し、その後にチップの平均温度が続きます（パネルが狭いと平均から省きます）。すべてのチップが収まり 2 行以上余るときは、その下に最も熱いセンサーの履歴スパークラインを描きます。同じカード内のバー行はラベル列と数値列を共有するため、バーの始点と終点がそろいます。プロセスはヘッダーのクリックで並べ替えられる表で、その上の行に名前フィルターと表示範囲があります。PID 列はサンプル中で最も長い PID に合わせた幅になり、7 桁の PID も省略されません。カード内のスクロールで追加のデバイス・コア・プロセスを表示します。内容が収まっているカード（CPU やメモリなど）の上では、ホイールはページをスクロールします。ページのそれ以外の場所では、ホイールとカード未選択時の `↑`/`↓` がカード 1 行ずつ、`PageUp`/`PageDown` が 1 画面ずつスクロールします。最後のカードが完全に見えた所で止まるので、逆方向の最初の 1 目盛りですぐ動きます。監視設定ページは 1 目盛り 3 行で、同じく最終行で止まります。履歴は 1–60 分、クライアントのメモリ上限は 16 MiB。Pause は履歴記録を停止し、現在値と通知は継続します。

カードの順序は概要行の右端のボタンから入る **Edit layout** モードで変更します。各カードの上辺に ↑/↓ ボタンが現れ、カードを 1 つ選ぶと他は薄くなり、`↑`/`↓` キーで選択中のカードを動かします。**Done** または `Esc` でモードを抜け、パネルが閉じるのは次の `Esc` です。カードの高さ、非表示デバイス、チャート字形は Monitor preferences ページで設定します。

プロセスの終了は詳細画面で再確認します。PID の再利用や期限切れの確認は拒否します。強制終了は別操作で、Windows では必要です。通知は既定で無効です。有効時は接続中のみ、閾値・継続時間・クールダウンを評価し、自動でプロセスを終了しません。

**Monitor preferences** ページはコントロールをカードにまとめます。サンプリング間隔（500 / 1000 / 2000 / 5000 ms）、カードの高さ（7 / 10 / 16 / 24 行）、履歴範囲（1 / 5 / 15 / 30 / 60 分）、ホバー遅延、各通知ルールの閾値（50–100 %、5 刻み）・継続時間・クールダウンはステッパー、通知、プロバイダーのアカウント使用量、表示するカード、表示中のプロバイダー、取得済みデバイスはトグル、使用量の形式・配置とチャート字形はセグメントコントロールです。ステッパーは固定の段階表の隣の段へ移動し、両端で折り返すので、段階の間にある設定値は最初のクリックで段を飛ばさず隣の段に落ちます。**Chart glyphs** は System ページのスパークラインとバーの字形——Braille（既定）、Blocks、字形のないターミナル向けの ASCII——を選び、クライアント設定 `monitor_chart_glyphs` として保存されます。

## 設定とアカウント

アカウントページは、接続先ホストに公式 CLI がインストールされているプロバイダーのみ表示します。判定は統合設定ページと同じ多别名 PATH スキャンとインストールレイアウト確認（codex の standalone/nvm/volta/bun など）を使い、両画面の結果が一致します。ZCode には探す CLI がないため、接続先ホストにそのローカルデータベース `~/.zcode/cli/db/db.sqlite` がある場合に表示されます。アカウントを明示設定したプロバイダーは常に表示されます。`account.usage.providers` はプロバイダーごとに `installed` フラグを返し、旧 server ではこのフィールドが省略され、レジストリ全体が表示されます。自動更新はクライアントがデータを表示している間、server 側で実行されます。API アカウントは `api_refresh_seconds`（最低 60 秒）、CLI プローブは `cli_refresh_seconds`（最低 300 秒。実効値は `account.usage.providers` の `minimum_interval_seconds` として告知。ZCode のローカルデータベースの読み取りも同じ周期）で照会し、失敗後は上限付きのバックオフがかかります。公式コールバック（Claude Code）または Herdr 付属の統合拡張（Pi）からデータが届くベンダーはポーリング間隔を告知せず、そのプッシュで更新されます。アカウントページをプロバイダー未選択で開くと、フォーカス中のペインで実行中のエージェントを選び、なければ最初に表示されているプロバイダーを選びます。プロバイダーやアカウントを切り替えると、新しいデータが届くまで以前のスナップショットを薄く表示したまま保持します。現在のスコープに設定済みアカウントが 2 つ未満なら「アカウント切り替え」は無効になり、設定で無効化したプロバイダーはプロバイダーのチップ、切り替え候補、概要から同時に消えます。インストールレイアウト経由で codex CLI を見つけた場合、プローブはその bin ディレクトリを `PATH` 先頭に付与して実行し、npm shim のインタープリター解決を保証します。

Agent 行や CLI タイトル上の使用量ポップオーバーは `hover_delay_ms`（既定 400 ms）の経過後に表示され、ポインターが行とポップオーバーから離れて 250 ms 後に閉じます。独自のスコープを持ち、アカウントページの選択を書き換えません。ポップオーバー内の「Open page」ボタンでアカウントページが開きます。プロバイダー横断の概要はアカウントページにあり、先頭のチップ「All providers」で表示中のプロバイダーをまとめて確認できます。

同じカードは意図して開くこともできます。Agent 行を右クリックして「Usage」を選ぶと、カードがすぐに表示され、ピン留めされたままになります。タイトルは「<agent> · Usage」で、上枠の右端に「pinned」マークが付きます。ポインターを離しても、ほかの Agent 行の上を通っても閉じたり置き換わったりせず、Esc キーかカードの外側のクリックで閉じます。この項目は `page` を含むどの `position` でも使え、クラシックレイアウトでモニターページを開いているときもピン留めしたカードはページの上に描画されます。モニター設定でアカウント使用量をオフにしている場合、カードは読み込みを続けずにその旨を表示します。Agent 行から開いたカード（ホバーでもピン留めでも）は Agents パネルの横に表示されます。通常は右側で、パネルが右端にドッキングされているときは左側です。行のすぐ下の行から始まり、下に収まらないときは行のすぐ上の行で終わるので、隣の Agent 行を覆いません。パネルの両側とも 40 列の空きがないときは、行の真下または真上に開きます。CLI タイトルから開いたカードはタイトル行の真下に左揃えで開き（右端に近すぎるときは左へずらします）、下に収まらないときはタイトルの上へ反転します。上下どちらも高さが足りないときは広い側に縮めて表示し、5 行未満になるカードは表示しません。カードが自分の行やタイトルを覆うことはありません。

クライアント設定はフィールドごとに読み込まれ、解析できない値（例: 未知の `usage_format` や `monitor_chart_glyphs`）はそのフィールドだけを診断 1 回とともに破棄し、残りは保持します。`usage_*` キーは明示的に設定した場合にのみ書き戻されます。

`monitor` の `interval_ms`、`history_minutes`、`visible`、`card_height`、`hidden_devices`、`alerts_enabled` を設定できます。`[[monitor.alerts]]` は `metric`（cpu / memory / gpu / disk）、`threshold`、`duration_seconds`、`cooldown_seconds` を持ちます。

`account_usage` の `format` は `dashboard` / `table` です。`position` はペインごとのポップオーバーの置き場所を決めます。`hover` と `both` は Agent 行と CLI タイトル上のポップオーバーを保ち、`page` はポインターによるポップオーバーを無効にし、ペインごとの入口をアカウントページと右クリック「Usage」で開くカードだけにします（選択中は Monitor preferences ページにヒントが表示されます）。アカウントページはどの値でも利用できます。Monitor → Monitor preferences で行った変更はクライアント設定として保存され、そのマシンでは「設定ファイルの値に戻す」を使うまで `enabled`、`format`、`position`、`hover_delay_ms`、無効化したプロバイダーを上書きします。Agent 行でアカウントを選び、ペインへ関連付けてください。同じブランドというだけではアカウントを特定しません。未関連付けのペインから公式コールバックが届いた場合、そのブランドに設定済みアカウントが 1 つだけならサーバーが自動的に関連付けて保存し、スナップショットに自動関連付けと表示します。複数ある場合は候補を添えて拒否され、明示的な関連付けが必要です。自動関連付けには `account_usage.enabled` と、クォータ項目を含むコールバックが必要です。

パネルが広い場合(96 列以上)、右側の詳細カラムは選択中のアカウントで最も厳しいクォータ枠の推移も表示します。クライアントは直近 120 サンプル(ポーリング応答と購読プッシュの両方)を保持し、「使用量履歴」の見出しの下にスパークラインで描画します。
明示的な更新（`account.usage.refresh`、アカウントページの更新操作、プロバイダーやアカウントの切り替え）はアカウントごとに 10 秒のデバウンスがかかり、ベンダーのバックオフ（HTTP 429）も適用されます。デバウンス中の応答には `next_allowed_at_ms` が含まれます。終端結果（未ログイン、未対応、権限なし）は 10 分から始まり倍増して最大 1 時間、最大 6 回まで低頻度で自動再試行され、CLI 本体や資格情報ファイルが変わると保留は即座に解除されるため、ログイン後は再起動なしで回復します。明示的な更新は終端状態でも常に再試行します。クォータ項目のない公式コールバックはキャッシュ済みサンプルを上書きしません。15 分間コールバックがない場合はスナップショットがキャッシュ表示になり、プローブにフォールバックすることがありますが、置き換えるのは成功したプローブか次のコールバックだけです。プッシュで取得するベンダー（Claude Code の公式コールバック、Pi の拡張プッシュ）は更新状態に `callback_only` を報告します。明示的な更新では新しいサンプルは得られませんが、ログインや関連付けのプレースホルダーは更新されることがあります。

アカウントページが表示されている間、クライアントは `account.usage.subscribe` を告知する server に購読し、プッシュされる `account.usage.updated` / `account.usage.refreshing` イベントを即座に反映します（30 秒のフォールバックポーリングのみ維持）。ページを閉じると購読を解除し、再接続後は購読し直し、旧 server ではポーリング（2 秒、プローブ実行中は 500 ms）にフォールバックします。プローブ中のアカウントは自分の行に「更新中…」を表示します。更新ボタンは、選択中のアカウント（未選択なら表示中の全アカウント）がデバウンス中の間「N 秒後に更新可能」と表示し、1 分を超えるベンダーのバックオフはボタンをロックせずアカウントの行で説明します。アカウントページには関連付け行もあります。選択中のプロバイダーのエージェントを実行しているペインだけを列挙するペインピッカー、「フォーカス中のペインを関連付け」、未関連付けペインのコールバックが拒否された後に server が返す `pending_binding` のワンクリック候補です。どの入口も別プロバイダーのエージェントを実行しているペインを拒否し、公式コールバックを有効化した後の自動関連付けは応答したホスト上のペインに対して行われ、その間にアクティブになった別のホストへは送られません。

Claude Code はコールバック優先です。クォータは公式 statusline コールバックから取得し、プローブは非対話の `claude auth status --json` でログイン状態のみ確認します（実際のログイン情報を読み取り専用で参照）。ログイン済みでコールバック未設定のアカウントには「公式 statusline コールバック待ち」と有効化する設定が表示され、最初のコールバックが届くまでこの事前確認は終端状態と同じ低頻度スケジュールで退避します。対話式 `/usage` プローブはオプトイン（`interactive_probe = true`）で、明示的な更新時のみ、herdr の状態ディレクトリ配下の固定プローブディレクトリで実行されます。Claude Code はそのディレクトリの信頼を自分の CLI で一度確認するよう求めます（更新状態に `trust_required`、message にディレクトリのパスが入ります）。Herdr がそのダイアログに代わって応答することはありません。対話式プローブは実際のログイン状態を再利用するため、同時起動で資格情報がローテーションされる可能性があります。コールバックなしで `/usage` が必要な場合以外は無効のままにしてください。

コールバックは `rate_limits` のアカウント枠（`five_hour`、`seven_day`、Claude apps gateway 配下の `spend_limit`）に加えて、報告元セッションの推定費用・経過時間・API 待ち時間（`cost.*`）とコンテキストウィンドウ（`context_window.*`）も運びます。これらはセッション統計として表示され、アカウントのクォータには数えません。複数のセッションが 1 つのアカウントを共有している場合は、最後に報告したセッションの値になります。公式 statusline の仕様に沿った点が 3 つあります。枠が `resets_at` を過ぎると Claude Code はその枠を JSON から外し（セッション最初の API 応答までは `rate_limits` 自体がありません）、欠けた枠は 0 にせず前回の値を保持し、リセット時刻を過ぎていればその旨を表示します（保持はリセット時刻から 1 週間まで、`resets_at` のない枠は最後に現れてから 1 週間までです）。`context_window.current_usage` と `used_percentage` は最初の API 呼び出し前と `/compact` 直後に `null` になり、0 ではなく「データなし」と表示します。`spend_limit` は 100 % を超えることがあり、報告値のまま保持します。`rate_limits` をまったく含まず（古い CLI や API キーでのログイン）、引き継げる枠もないコールバックはアカウントを引き継ぎません。

ダッシュボード形式ではアカウントごとに 1 枚のカードを、プロバイダーごとの配置で描きます。カードの上枠にアカウント名と状態、カード内の 1 行目にサンプル経過時間・プラン・アカウント識別子（バッジが統計の注記の場合は状態も）を表示します。Claude Code は 5 時間・週間・利用額上限の 3 つの枠をゲージで描き、続けてセッションのコンテキスト使用率と費用を表示します。利用額上限が 100 % を超えた場合は報告値のまま表示し、バーの末尾に超過マーク `▸` を描きます。リセット時刻を過ぎた枠は前回の値を保持したまま文字をグレーにし、バーを薄く表示して「past reset」と明記します。Codex はレート制限のバケットごとに主 / 副の枠（枠の長さで命名、例: 「5h window」）とそのバケットの追加クレジットを描き、バケットが複数あればそれぞれ小見出しで分けます。Kimi Code は 5 時間・7 日・月間の枠、通貨単位の残高、追加使用量のウォレットを描きます。OpenCode と ZCode のカードには「Local stats, not account quota」のバッジが付き、セッション数・費用・トークン・ツール呼び出しなどは数値だけを表示してゲージは描きません。Pi のカードには「Session stats」のバッジが付き、コンテキストのゲージ、セッションの費用とモデル、トークンの内訳を表示し、最初のプッシュが届くまでは空の状態を表示します。ZCode のカードは、接続先ホストが ZCode アカウントを報告した場合にのみ表示されます。カードが認識しないメトリクスも汎用の行として表示し、未知のプロバイダーには汎用カードを使います。ゲージはしきい値で色分けし、枠の経過位置に目盛りを描き（5 時間・週間・7 日の枠は固定の長さで計算し、その他の枠はプロバイダーが長さを報告した場合のみ）、使用量が経過時間より先行すると早めに黄 / 赤に変わります。パネルが狭くなるとまずバーを縮めて省き、数値は常に残します。「All providers」を選び、複数のプロバイダーが表示されている場合は、プロバイダーごとの小さなカード（最も厳しいクォータ枠、ローカル / セッション統計では主要な数値、と状態の 1 行）に切り替わり、96 列以上では 2 列に並べます。小さなカードをクリックするか、選択して Enter を押すとそのプロバイダーを開きます。Agent 行のポップオーバー内のカードはポップオーバーより高くならず、収まらない行は下枠に「+N」として数え、「Open page」でカード全体を確認できます。

ダッシュボードと表はマウスホイールでスクロールでき、アカウントページでは上下キーも使えます。使用量ポップアップは監視パネルと同時に表示でき、背後のカードやプロセス行へ入力が抜けることはありません。

```toml
[account_usage]
enabled = true
format = "dashboard"
position = "hover" # hover / page / both。page は Agent 行のポップオーバーを無効にします
hover_delay_ms = 400
api_refresh_seconds = 60
cli_refresh_seconds = 300
probe_timeout_seconds = 20
interactive_probe = false # 明示的な更新のみ。Claude は CLI でプローブディレクトリを一度信頼する必要があります
disabled_providers = []

[[account_usage.accounts]]
id = "work"
label = "Work"
agent = "codex"
provider = "codex"
auth_mode = "cli"
profile_dir = "/path/to/profile"
```

API 用アカウントは `auth_mode = "api"` と環境変数名の `credential_env` を指定します。必要に応じて `organization` と `account_user` を設定します。API キーのアカウントは OpenAI、Anthropic、Moonshot、OpenRouter に対応します。OpenRouter 全体の残高は管理キーと `billing_scope = "account"` を使います。Kimi Code は `KIMI_CODE_HOME` でプロファイルを選び、ログイン状態はそのディレクトリの `credentials/kimi-code.json` にあります。そこでログインすれば、未ログインのアカウントは再起動なしで回復します。資格情報を TOML に書かないでください。設定は Agent が実行される server に置きます。`base_url` は登録済み公式ホストのみ、Kimi のローカル API は loopback のみです。

## 公式回調

Claude Code は Accounts 画面から公式 statusline 回調を有効化・解除できます。既存の描画コマンドはパイプラインで維持します。対応 JSON は `herdr api usage-report --agent <agent>` の stdin からも送れます。`HERDR_PANE_ID` の関連付け、または `--account <id>` を使います。未関連付けのペインはブランドのアカウントが 1 つだけの場合のみ自動的に関連付けられ、それ以外は先に関連付けてください。`--passthrough` は既存 statusline 用です。

Claude の quota フィールドは対応 CLI と通常の最初の API 応答が必要です。使用量取得のためにモデルへプロンプトを送信しません。生 JSON や会話内容を保存しません。

Pi には statusline の仕様がなく、RPC モードは別のヘッドレスプロセスを起動するため、ペインで実行中のセッションを参照できません。そこで Herdr の Pi 拡張（統合バージョン `10`。`herdr integration install pi` で更新）が実行中の TUI セッション内で使用量を読み取り、Herdr ソケット経由でプッシュします。タイミングはセッション開始時、各ターンの終了後（最大 5 秒に 1 回）、コンパクション後、エージェントが落ち着いた時です。内容はコンテキスト使用量（`ctx.getContextUsage()`）、セッションのトークンと費用の合計、現在のプロバイダーとモデル（要求したモデルと実際に応答したモデルが異なる場合は応答した方）です。Pi はマルチプロバイダー CLI なので、これはセッション統計であり、アカウントのクォータではありません。プロバイダー / モデルは、このセッションを実際に支払っている契約アカウントへ関連付けるためのもので、二重に計上するためではありません。コンパクション直後から次の応答までは Pi 自身もコンテキストサイズを把握しておらず、Herdr は 0 ではなく「データなし」と表示します。Pi にコールバックのスイッチはなく、最初のプッシュが届くまではアカウントに待機理由が表示されます。

## 対応範囲と公式資料

アカウント使用量は Codex、Claude Code、Kimi Code、OpenCode、Pi、ZCode の 6 つの Agent を対象にしています。公式資料の最終確認は 2026-09-22（Codex は 2026-09-16、ZCode のデータベース構造は 2026-09-23）です。契約枠、API キー予算、組織請求、セッション統計、ローカル統計は分けて表示します。非対応版・未公開 API・権限不足は明示し、それ以外の Agent に設定したアカウントは公式ソース未登録と表示します。セッション統計とローカル統計はアカウントの残りクォータを意味しません。

| Agent | 公式ソースと範囲 |
| --- | --- |
| Codex | [App Server](https://learn.chatgpt.com/docs/app-server) のアカウント、レート枠、追加クレジット。API 課金は管理者レポートを別途使用します。 |
| Claude Code | [statusline JSON](https://code.claude.com/docs/en/statusline)：`rate_limits` のアカウント枠と、セッションの `cost`・`context_window`。公式 `/usage` はオプトイン。API 組織の使用量と費用は別扱いです。 |
| Kimi Code | [ローカル Server API](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html)（公式に experimental）：`quota.usages` の 5 時間・7 日・月間の枠と、月間枠のうち Code の分。`quota.extraUsage` の従量課金ウォレットは金額で表示します（残高、総額、今月の費用、有効な場合は月間上限）。Moonshot API 残高は別途照会します。 |
| OpenCode | [`opencode db <query> --format json`](https://opencode.ai/docs/cli/)：`session` テーブルの読み取り専用集計（セッション数、サブエージェントのセッション数、費用、入力 / 出力 / 推論 / キャッシュのトークン）。ローカル統計であり、アカウントのクォータではありません。 |
| Pi | Herdr の Pi 拡張（公式の[拡張 API](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md) を使用）：コンテキスト使用量、セッションのトークンと費用、現在のプロバイダー / モデル。セッション統計であり、アカウントのクォータではありません。 |
| ZCode | [ZCode デスクトップアプリ](https://github.com/zai-org/ZCode)のローカルデータベース `~/.zcode/cli/db/db.sqlite` を、システムの `sqlite3 -readonly` で読み取り専用に照会します。`model_usage` テーブルの直近 24 時間分：メインタスクとサブエージェントに分けたトークンとその合計、ツール呼び出し回数、サブエージェントのセッション数。資格情報は不要で、読み取りもしません。ローカル統計のみで、アカウントのクォータではありません。リモートのクォータは照会しません。 |

OpenCode にはアカウントクォータの API がないため、どちらの取得形態もメトリクスのスコープとソース表示でローカルのセッション統計と明示します。`db` のクエリは件数と合計だけを読み、セッションのタイトルやパスは読みません。`db` サブコマンドやその `--format` オプションがない CLI、またはクエリが失敗した場合（古いデータベース構造など）は、`opencode stats` の表の解析にフォールバックします。OpenRouter のキー予算はアカウント合計とは別です。Kimi の Server API は公式に experimental とされているため、`quota.usages` の枠と従来フィールドの両方を解析しつつ、欠けている項目や形の違う項目はその項目だけを飛ばし、サンプル全体を失敗にはしません。

アカウントページでは OpenCode と ZCode に「Local stats, not account quota」、Pi に「Session stats」のバッジが付き、いずれもアカウントのクォータとしては扱いません。ZCode のローカル統計は ZCode デスクトップ版のデータベースから読み、リモートのクォータは照会しません。

ZCode はペインで動かないデスクトップアプリで、Herdr がそれを起動することはありません（そのコマンドはウィンドウを開きます）。server は自身の `PATH` 上の `sqlite3` コマンドでデータベースを読み取り、コマンドがない場合は ZCode のアカウントに数値の代わりにその理由を表示します。クエリはリクエスト行を開始時刻で数えて合計するだけで、プロンプト、メッセージ、エラー本文は読みません。`query_source` が `subagent`、または `task_type` が `subagent_child` のリクエストはサブエージェントに、それ以外（メインターン、タイトル生成、コンパクション）はメインタスクに数えます。データベースがロック中・読み取り不能・構造変更の場合は、前回のサンプルをキャッシュとして保持し、バックオフ付きで再試行します。ZCode のアカウントは `herdr api usage-report` のプッシュを拒否し、`profile_dir` にも対応しません。ポーリングを止めるには `disabled_providers` に `"zcode"` を追加します。

## API

`system.metrics.*`、`system.process.*`、`account.usage.*`、`account.binding.set` を公開しています。

`account.usage.get` / `account.usage.refresh` の応答と `account.usage.updated` イベントは、スナップショットと並べて `refresh` リスト（`UsageRefreshState`。`account_id` で `accounts` と対応し、旧 server では省略）を返します。プローブの進行（`in_flight`、`queued`）、明示的な更新のデバウンス（`requested_at_ms`、`next_allowed_at_ms`）、ベンダーのバックオフ（`retry_after_ms`）、`binding_inferred`、`trust_required`、`callback_only`、`pending_binding`、`callback_enabled` を含みます。`account.usage.refreshing` はプローブ開始時にこのリストだけをプッシュします。フィールドの意味とイベントのエンベロープは[イベント購読](/ja/docs/socket-api/#イベント購読)を参照してください。`client.views.set` とビューの具名拡張は協商済み TUI 接続専用です。generation 1 のエンコードは維持します。ペイン移動は既存の `pane.move` / `pane.swap` を使います。詳細は `herdr api schema --json` を参照してください。
